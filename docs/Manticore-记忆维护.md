# 结构化记忆维护

入口：**知识与资料 → 结构化记忆**。面板显示完整正文、来源、确认依据、使用状态、有效期、范围、来源核验与修订。筛选计数来自全部记录；停用、过期、冲突和回收项都有查询入口。读取失败时会明确提示，上次读取结果不会冒充当前文件。

点击「新建记忆」或条目的「维护此记忆」，选择操作，检查生成的内容，然后「复制并打开本地对话」。指令带工作区、条目 ID、完整内容及 `expectedRevision`。在本地24私助会话粘贴并补全你的要求后发送。飞书日常交办与 Worker 仅可检索有效业务记忆，不能读取回收正文或执行维护。

- **确认内容**：明确说出要记住或确认的陈述，留下本人的指令依据。资料审核通过、保存文档或模型推断不代表长期记忆已确认。旧记录即使标为 confirmed，没有适用于当前陈述的确认依据，也只作线索；修改正文、范围或有效期间会使旧确认依据失效。重复旧确认依据保留原凭证，不会重新确认新陈述。本人可以用相同措辞再次确认当前内容，但须记录新指令的引用；复用旧引用或省略引用重复旧文字，不能当作新确认。
- 历史确认依据会随该记忆保留，清空当前依据或撤销修订不会把旧指令变成新确认；永久删除同时清除这条记忆的确认历史。
- **来源核验**：与内容确认分开，记录来源当前可读、已变化或不可访问的证据和时间。来源不可访问不自动推翻内容；引用前仍须结合使用场景核实。
- **冲突处理**：同主题、同类别、同范围且有效期间相交的不同已确认陈述会显示为可能冲突，只作线索。按来源和实际范围处理，可修正内容、分范围保留、调整生效期间，或明确标记冲突及处理依据；不会自动采用最后一条。
- **停用**：保留正文及历史，退出普通业务检索。需要时可重新启用。
- **回收**：从业务检索退出，正文仍在回收入口，可恢复到回收前的使用状态。
- **永久删除**：先回收并核对当前版本，再明确要求永久删除。清除当前正文及本工作区可恢复修订，只留下 ID、删除时间、revision 和操作标识。该 ID 不能再次复用，也不能通过撤销或旧备份恢复正文。原始资料、会话及已有备份需要分别处理；失败回执会区分正文已删除和历史清理尚未完成。
- **批量维护**：先展示实际变更集及前后内容，选择后应用同一预览。预览绑定完整文件、修改内容和当前本地会话；文件变化后必须重新预览。
- **撤销**：在「查看修订」中查明修订 ID，再从维护操作选择撤销。只有当前完整字段仍与原修订结果一致时才能撤销；撤销会形成新 revision。永久删除不提供撤销。

JSON 是唯一可编辑权威，路径为工作区 `.24pa/memory.json`。支持手工编辑，下次读取会显示当前文件；与记录修订不一致时明确提示。无效 JSON 会报错并保留原件，不会自动清空。维护前先备份、读取当前 revision；同一工作区保持一个活动写进程。新版兼容 schemaVersion 1，显式维护后写 schemaVersion 2，查询本身不迁移。

恢复备份须先在隔离位置核验。当前记录默认保留，存在差异的备份记录列为冲突；双方永久删除标记均保留，旧备份不得复活这些 ID。正常来源资料和会话中可能仍有同一事实，这不等于该记忆已恢复。

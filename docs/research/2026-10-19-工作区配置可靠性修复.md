# 工作区配置可靠性修复研究

2026-10-19；基线 main c36e464，产品规格 2.12，dsh 0.2.1-alpha.2 开发基线。用户授权实施架构审查的工作区加载、表单编辑与本地工具挂载三项修复。

## 已核对契约

- SPEC §11/§13、F33：AGENTS.md 唯一配置源；校验失败保留当前生效配置；表单以磁盘最新配置合并用户修改，不覆盖工作规则。
- F36：密钥库只写不回显、0600 原子替换；环境变量优先；配置引用名与密钥值独立保存，密钥不进 AGENTS.md/提示词/备份。
- ADR-0001：按工作区、实际会话入口和父子关系授权；本地工具扩展不进入飞书或 Worker。
- 复用 `docs/research/F18-QwenNote听记MCP接入研究.md` 的 2026-10-15 实证：宿主 agent/created 早于 MCP 工具挂载，必须有界等待；工具注册表是可用探测，不能假设存在 mcp-client 状态接口。

## 源码证据与取舍

- runtime.bind 原先先 openDatabaseFor，后加载目标 secrets/config，导致 store-only PostgreSQL 在首次启动时无可用 DSN；资源开失败前旧提醒已停止。准备阶段必须只使用目标工作区数据，成功后才替换活动资源。
- 配置更新和重载只按 mode 决定是否重连，引用名变化未纳入；密钥更新会重连。统一按解析后飞书身份与凭据比较决定生效。
- PostgreSQL 活动连接保存实际打开时的 DSN；热更新若解析后的连接不同则明确要求重新绑定，写入型操作在落盘前拒绝。指向同一 DSN 的引用名变更可直接生效。显式重新绑定继续走完整准备/激活路径。
- client 参数表单整表提交、脏状态对比不断变化的快照；保存 trim 后未更新草稿基线。改为稳定编辑基线、仅提交用户改动、保存成功采用服务端规范化结果；密钥继续独立提交与反馈。
- TTS 子字段单独产生补丁，并与磁盘当前 TTS 对象合并，避免修改引擎时覆盖会话刚改过的密钥引用。
- `extraLocalTools` 纯解析测试不能证明 agent 创建、等待、dispose 和权限应用顺序。将完整生命周期收进可取消的 module，并从真实插件注册入口运行行为测试。
- 复用现有 SQLite/PostgreSQL、Sdk/FakeFeishuTransport adapter，不创建新的业务存储或 MCP 客户端。前端继续使用宿主 ModuleLoader，测试用真实 React DOM 与本地 DOM adapter 驱动同一个入口。

## 验证计划

通过公开绑定/更新入口验证 store-only PG、切换凭据、准备失败保持原活动账本；通过 React 渲染交互验证差异补丁、规范化、错误保留与密钥独立保存；通过插件 agent/created 验证迟到挂载、超时、dispose、非本地角色无扩权。全部隔离临时目录/本地测试，不接触生产。

## 验证结果

- `npm run build` 通过。
- `workspace-activation` 9 项使用临时真实 SQLite/PostgreSQL、公开 runtime 入口，覆盖上述准备/激活、PG 连接热变更拒绝、同值引用名变更、显式重新绑定、嵌套配置与预设冲突后通知。
- `config-editor` 6 项从实际 ModuleLoader/Panel 入口渲染 React DOM，以用户输入和点击覆盖字段与 TTS 子字段差异补丁、错误重试、规范化基线和密钥独立状态。
- `local-tool-access` 6 项从插件 `apply`/`agent/created` 接口验证延迟挂载、60 秒超时、dispose 取消及非本地角色不扩权。
- 真实 Loader F33 E2E 4 项通过；以上定向测试合计 25/25。
- 隔离 localhost 浏览器实际操作确认参数 trim 后保存、按钮禁用/启用与密钥独立提交成功状态；截图 `/tmp/24pa-config-qa.png`。仅合成输入、内存 RPC，临时页面及服务器已关闭。

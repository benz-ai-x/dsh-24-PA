## 开发前核验

2026-10-23 再读本机 lark-cli 1.0.87、wecom-cli 1.3.4 的 schema，并核对官方同版资料。只运行 help/schema，不运行真实账号 auth、列表、写入或 dry-run。

- 飞书清单 tasks 返回 `has_more/page_token`，不传 completed 表示全部完成状态。摘要不提供完整创建者与会签完成情况，单项 `tasks get` 补齐；完整列表与角色完整度分别记录。`tasks create` 能在同次请求提交 members、tasklists 和 client_token，主人默认以 assignee 加入。`tasks patch` 通过 update_fields 精确改字段，`tasks delete` 是整项删除，不能继续沿用“飞书没有删除接口”的旧文案。
- 企微[同版 list 文档](https://github.com/WecomTeam/wecom-cli/blob/f9b28151dc8d42f703db624fc9b26723c3c93fc5/skills/wecomcli-todo/references/todo-list.md)称返回真人创建与参与的对象；schema 描述仍为机器人创建视角。查询显式使用 proceed/finished 两种状态，按 cursor 到末页；返回的分派关系含 userid 和 user_status，不把字段英文 followers 当成飞书关注人。全范围真机覆盖在有代表性的账号样本上验收，代码不能证明租户覆盖，查询保留此缺口。
- [同版 create](https://github.com/WecomTeam/wecom-cli/blob/f9b28151dc8d42f703db624fc9b26723c3c93fc5/skills/wecomcli-todo/references/todo-create.md)声明 follower_ids 为分派人；默认本人时显式传入已核验主人 userid，并读回验证其分派与责任状态。未核实创建者身份时不推断本人创建；未核实分派结果不报“本人负责”。平台接受但读回不符保留原对象并提供修复，不重建。
- [同版 finish](https://github.com/WecomTeam/wecom-cli/blob/f9b28151dc8d42f703db624fc9b26723c3c93fc5/skills/wecomcli-todo/references/todo-finish.md)分别支持本人份额及 finished_all；[delete](https://github.com/WecomTeam/wecom-cli/blob/f9b28151dc8d42f703db624fc9b26723c3c93fc5/skills/wecomcli-todo/references/todo-delete.md)的整项删除/个人退出按真实创建者和明确 effect 区分。创建者与机器人身份的歧义不通过默认解释绕过。
- 无截止不造截止；企微截止可能触发平台默认提醒，该平台行为明确回执，24私助不另建提醒或日程。投入时间与估时继续是本地规划字段。

## 实施边界

`SourceTodoReader` 归一化远端对象与逐项角色；`SourceTodo` 负责登记范围、筛选、真实计数、分页和定位；`SourceTodoWrites` 固定唯一平台/身份/清单/参数，经过原外部操作账，成功回执后的重试只补读回和关联。复用 schema 20 的 source_object、source_membership、source_observation，不引入第二份可编辑来源配置或新迁移。

显式角色替换来源默认条件；创建者、负责人、关注人和已证实交办关系分别处理。仅相同平台、真实身份和原生 ID 合并；同名、跨平台同 ID 不合并。失败观察保留旧缓存并标注，不用缓存条数报完整总数。普通页面只读存档，明确“核验”才访问平台。

共享接口：SourceRegistry.bind('todo', selector, 'create') 生成冻结 SourceTarget；SourceTodoWrites 在每次未发出动作前重验，`_sourceTarget` 仅由受控计划接线传入。外部效果未知保持原操作 ID，不以新运行或新默认避开对账。记录待办不启动执行其业务的额外交办。

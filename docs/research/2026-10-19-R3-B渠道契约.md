# R3-B 渠道契约核验

2026-10-19，基线 PR-A #199 合并 61ae27f；对应 #179/#181/#185–189。复用第三轮逐项复核与原始 CLI/SDK 证据。

实装 lark-cli 1.0.87：`task tasks get --task-guid ... --as user` 按 GUID 读取单项；`task +get` 不存在，不能用名称搜索代替权威读取。`task +create --due` 支持 date:YYYY-MM-DD 与 ISO 时刻。SDK 1.74.0 消息 uuid 最大 50 字符，完整业务键需稳定摘要而非截断。语音/text/card 都按各自 Outbox 内容类型和完整业务键及目标映射，重试不改变平台身份。

实装 wecom-cli 1.3.4（f9b2815）：`todo get --items [{todo_id}]` 返回单项 success、title、status(proceed/finished/deleted)、deadline(type=date/datetime,value)、user_status；不再用无过滤 list 推断详情。`todo finish` 缺 finished_all 只完成调用人的份，可能返回 ask_finish_all；不得自动提升到整项操作。完成写入必须核对目标回执并读回，个人份额完成仍显示任务 open/partial，不假装整项完成；未知结果不自动重发。

`identity whoami` 是只读当前授权真人解析；显式 wecom_check 强制刷新，合并并发请求，失败清空旧身份而非继续当当前通过。持久 Outbox 的旧 target 保持不变。

日期型截止按原始日期往返，只有 datetime 使用工作区时区换算。任务终态从待办行动候选排除，跟进前核对权威来源；核对失败明示 unknown。

CLI 调用超时/超限：先 TERM、500ms 后 KILL，1000ms 上限回收本地句柄；保留外部 unknown 语义。pg_dump 为交互联合备份设置 10 分钟期限、256MiB 输出上限（原实现全部载入内存）；超限/超时报告备份未完成且不产生成功清单。此界限不限制用户另行使用 PostgreSQL 工具的离线备份。

备忘真实模式按配置和 CLI 实际结果判断，不依赖机器人长连接是否在线；演示模式仍明确仅本地。无真实文档 ID 的旧演示成功记录不视为真实保存完成，可在本人再次执行相同请求时修复。验证仅临时工作区、进程及CLI替身，无真实账户写入。

两渠道观察与写入共用每任务 gate，观察前读当前本地规划字段；坏字段或权限失败不能发布新的完整观察。自身 [24PA] 创建标记不参与内容差异；日期与时刻精度进入指纹，旧时刻型指纹会保守失效一次，避免沿用日期语义不明的历史跟进。项目、晨报负荷及日常规划只消费 open 任务。

实装 CLI 的版本检查同样走有界进程网关，避免诊断路径仍被忽略 TERM 的子进程拖住。未知发送行不重发、有持久 message_id 的行只补回执，新平台键只作用于实际新发送；已排队目标不可改投。

本记录是代码与现行规格的只读调研，不是新目标定稿。用户已提出优化甚至重构晨报，并明确希望围绕**今日安排、到期事项、昨日进展，帮助一早安排今日工作**组织内容。具体内容层次、生成方式与迁移行为仍需形成设计。本次未访问生产实例、业务数据或凭据，未运行构建、测试或真实账号验收。

## 结论

当前 `digest-morning` 是确定性模板：Skill 正文描述输出契约，真正的数据收集、排序和文字组装在代码中。仅改 Skill 正文不能完成这次内容重构，修改后的模板正文还会被一致性检查拒绝。参见 [skills.ts:248–259](../../packages/24pa/src/skills.ts#L248)、[digest-service.ts:389–404、436–448](../../packages/24pa/src/digest-service.ts#L389)。

现有晨报偏向业务对象总览，没有“昨日进展”段；“今日重点”取本地待办列表前 3 项，既不读取已确认近期重点，也不读取昨日复盘。新的 `WorkPlanning.context` 与 `daily-planning` 已具有更适合工作安排的事实与建议记录，可作为重构复用起点。两者目前保持独立，不能把旧晨报计划直接绑定为 `daily-planning`。参见 [digest-service.ts:578–640](../../packages/24pa/src/digest-service.ts#L578)、[work-planning.ts:31–52](../../packages/24pa/src/work-planning.ts#L31)、[工作方法产品契约:8–14](../planning/24PA-工作方法-实施计划.md#L8)。

## 昨日进展的证据边界

1. 旧晨报没有昨日查询窗口。`tasksCompletedToday` 按当前报告日的 `last_synced_at` 筛选，代码明示这不是精确完成时刻；晨报分支又排除了这段完成状态列表。不能把它改个标题便称为“昨日完成”。参见 [digest-service.ts:264–265、319、606–607](../../packages/24pa/src/digest-service.ts#L264)。
2. `previousReview` 表示同一时区中、本日期之前最近一次复盘，不保证日期等于昨天。使用时须核对 `content.date`；跨周末或漏记时可以注明“最近一次复盘（日期）”，不能冒充昨日。参见 [repo/work-planning.ts:22–24](../../packages/24pa/src/repo/work-planning.ts#L22)。
3. 已保存的日终复盘绑定明确采纳版本，包含完成、推进中、受阻、主动调整、未知及证据。`completed` 需要当前有效待办/交办完成依据或本人说明；推进、受阻和主动调整需要本人说明。该校验可用于判断哪些进展有据可报。参见 [work-planning.ts:138–159](../../packages/24pa/src/work-planning.ts#L138)。
4. `WorkPlanning.context` 返回的交办是当前状态、进度与验收状态，没有在输出中附带发生时间；单靠这份结果不能判断进展发生于昨日。若没有昨天复盘或带时间的可靠业务证据，应标明未记录/待核实，不推断完成、原因或延误。参见 [work-planning.ts:49–52](../../packages/24pa/src/work-planning.ts#L49)。

## 可以复用的能力

- **安排工作的事实入口**：`WorkPlanning.context` 聚合当前日期、近期重点、当日建议与采纳、当日及最近复盘、多来源待办、日历、交办、等待、会议间隔和工作时段可用量；返回来源缺失说明。运行时待办查询使用 `status: all, deadline: all`、刷新且不分页，可再按今日截止/逾期/未定日期区分。参见 [work-planning.ts:31–52](../../packages/24pa/src/work-planning.ts#L31)、[runtime.ts:566–570](../../packages/24pa/src/runtime.ts#L566)。
- **生成今日建议**：`daily-planning` 读取上述入口，结合近期重点、承诺、截止、等待及最近复盘调整，最多选 3 项，保存成果、理由、下一步、估时、来源与取舍。保存建议与主人采纳分开，不自动创建日程或修改任务。参见 [work-methods.ts:19–36](../../packages/24pa/src/work-methods.ts#L19)、[work-planning.ts:90–135](../../packages/24pa/src/work-planning.ts#L90)。
- **日期与运行归属**：既有晨报冻结原发生窗口、计划快照及 Skill 快照，跨日恢复不按当前日期改写旧报告；已保存结果只恢复投递。内容重构应保留此能力。参见 [digest-service.ts:336–410](../../packages/24pa/src/digest-service.ts#L336)。
- **文本与语音投递**：旧链路把完整文本和可选语音正文共同入队。口播由全文做字符串删减，不是独立摘要：剥离同步时间/来源括注/链接，遇到字面“`三、数据缺失`”后丢弃后续全部行，超过 1200 字截断并提示。改标题、段落顺序或把重要缺口放到此标题之后时必须同步调整口播，避免遗漏。参见 [digest-service.ts:476–505](../../packages/24pa/src/digest-service.ts#L476)、[spoken-result.ts:1–30](../../packages/24pa/src/spoken-result.ts#L1)。

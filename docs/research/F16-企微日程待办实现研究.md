# F16 研究：企业微信日程、待办接入（wecom-cli 第二操作渠道＋单向推送）

日期：2026-10-07。研究先于实现完成；本文记录来源、实测与取舍。背景：用户提出新一轮迭代，在 24PA 中加入企业微信（下称企微）日程、待办能力；本会话已在本机完成 wecom-cli 全量实测，本文为实测结论的沉淀。

## 一、需求定位与规格约束

1. 用户需求：24PA 的日程、待办域能改走企微（用户真实工作组织在企微）。
2. 规格 1.5 Out of Scope 明确排除「第二聊天平台」。实测确认企微收信不可行：wecom-cli 无任何收信方法（message 服务仅 send/sessions/files）；企业侧 chat 会话接口对该企业返回 853006（tool not available）。故本迭代定位为**第二操作渠道＋单向推送出口**，收信入口仍唯一在飞书——以条款改写方式处理规格冲突，见规格 1.6。
3. 现状约束：日程/待办域硬编码飞书（config.tasklistId/calendarId；outbox channel 字面量 'feishu'）；lark.ts 网关语义与 wecom-cli 不兼容（见三）。

## 二、wecom-cli 能力面（2026-10-07 实测）

环境：npm 官方包 `@wecom/cli` 1.3.4（内核 f9b2815，2026-09-23 构建）；机器级配置 `~/.config/wecom`（凭据加密，无 profile 概念，单机器人绑定）。本机绑定：机器人「PC cli」（Bot ID `aibGig1kK7naG27XdmypLmcUm1v566XQG-h`）；授权真人＝梁鹏程（userid `wou0d1BwAAtxZPckTPJK9_rgX7vkPHOg`）；企业＝广汽集团（CLI 不暴露企业字段，由日程参与人 `@广汽集团` 后缀证实）。

本迭代要用的能力（全部实测通过）：

- **日程** `calendar schedules`：`list`（时间窗查询，默认当前起 30 天）、`create`（subject/begin/end/location/description/attendees/reminders/timezone/is_all_day/meeting_room_id）、`cancel`、`update`/`get`/`search`/`free`。
- **待办** `todo`：`create`/`update`/`delete`/`finish`/`get`/`list`，批量≤20 条，机器人视角（创建后授权真人自动成为 follower）。
- **推送** `message aibot send`：以智能机器人身份向单聊（--chat-id 传真人 userid）发 markdown/图片/文件/语音/视频；markdown 实测送达。
- **诊断** `auth show`（纯文本：Status/Bot ID）、隐藏命令 `identity whoami`（JSON：机器人身份＋授权真人身份＋权限边界说明）。

明确不可用/不用：`chat` 服务全家族与 `message send`（纯文本）对该企业 853006；邮件接口仅 ±7 天窗口（680220），本迭代不接；`contact` 通讯录未授权。

## 三、wecom-cli 契约要点（实测，网关实现依据）

**信封三态（关键差异：与 lark-cli 完全不同，不能复用 lark.ts）**：

| 形态 | 退出码 | 位置 | 判定 |
|---|---|---|---|
| 成功 | 0 | stdout | JSON，业务字段混入前缀字段 `security_notice`/`extra_identity_context`（需剥离，勿当业务数据）；例外：`auth show` 输出纯文本 |
| 业务错误 A（errcode 体） | 1 | stdout | `{"errcode":850003,"errmsg":…,"help_message":…}`；已知码：850002 未授权、850003 授权过期、853006 企业不可用；`help_message` 携带企微内授权链接，诊断层需透传 |
| 业务错误 B（error 体） | 1 | stdout | `{"error":{"code":680220,"message":…}}`；平台限制/参数类（如 680220 邮件窗口、40073 非法 id） |
| CLI 参数错误 | 1 | stderr | clap usage 文本 |
| 未知命令 | 2 | stderr | — |

全部业务响应（含错误）都在 stdout、stderr 为空；超时语义照搬 lark.ts 三态 `unknown`（结果未知，先核对再重试）。

**其他契约**：

- 无 `--profile`、无 `--json`（默认 JSON 输出）；每次调用自动附带身份上下文前缀字段。
- **无幂等键**：todo/calendar create 均不支持 idempotency 参数，实测重复调用产生重复对象（待办实测踩中）——幂等唯一防线是 24PA 侧 stagedOperation 操作键（kind 前缀 `wecom_*`），遇 `unknown` 结局必须提示核对远端、不盲重试。
- **授权生命周期**：`auth init` 扫码绑定机器人（一次）；服务级权限逐项授权且**会过期**（日程实测过期→重新授权恢复）。授权链接 type 码（help_message 所见）：日程=2、通讯录=4、待办=5、邮件=7。过期周期未知，需 check 诊断兜底。
- 时间格式统一 `"YYYY-MM-DD HH:mm:ss"`；提醒 `reminders:{is_remind, reminder_time:[秒差值，负数提前]}`（默认提前 900s）；attendees `[{"userid"}]`；待办截止 `deadline:{type:'date'|'datetime', value}`。
- 推送目标解析：`identity whoami` 返回授权真人 userid，作为 aibot send 的 --chat-id。

## 四、设计取舍

1. **定位**：企微＝日程/待办操作渠道＋提醒单向推送出口；不做企微收信（永不在本迭代范围）。规格 Out of Scope 改写为「第二聊天平台的收信接入」。
2. **按域选择**：config 新增 `calendarChannel`/`todoChannel`/`notifyChannel`（'feishu'|'wecom'，默认 feishu），存量配置零影响；不做双写（回执对账复杂度不值）。
3. **独立网关** `src/wecom.ts`：信封语义、前缀字段剥离、help_message 透传均与 lark 不同；spawn 固定 argv（无 profile/json 附加）。
4. **写操作全走 stagedOperation**：弥补 CLI 无幂等键；`wecom_*` 操作键命名空间与飞书隔离。
5. **推送出口**：outbox channel 扩展 'wecom'，WecomSender＝aibot send markdown；目标 userid 经 whoami 解析后缓存运行时，不进配置（单一事实源）。
6. **投影表加 channel 列**（迁移 v11，default 'feishu'），不建平行表；calendar_sync_state 同理。
7. **接入向导**：`wecom-setup.md` 随插件打包＋`pa24_connection` guide/check 扩展（仿 F15 三件套：指南/只读诊断/nextSteps）。
8. **提醒引擎不动**：ADR-0001 单轨 PG 账本保持，仅扩 notify 出口 channel。

# Manticore M08 预算与输入恢复契约

## 已核验宿主接口

- `packages/core/agent-loop/src/agent.ts:267–288`：pre-step 先 claim inbox，再执行 waterfall；reject 不归还已 claim 输入。必须在该边界持久保存完整 id/source/content，不能只存 instruction 或 execution 标记。
- 同文件 `405–445,570–685`：每次尝试（包括宿主内部 retry）都执行 agent/request，随后 prepareCall、user/message 和 request/header，再派发 stream。一次许可仅在 agent/request 原子消费，pre-step 只判断并保存；工具不得消费同一模型许可。
- `assistant/message` 带实际 source.provider/model 与可选 usage；缺失表示未知。失败/取消可能只有 assistant/attempt，其 stream 中可有 usage chunk。request/header 保存实际 adapter 配置。按 Session 持久 seq 去重，不按进程内 attemptId 计量；收到请求意向但没有用量的窗口保持未知。
- 原生 user/message 与 consumedTurn/turnHasModelInput 才证明输入采用。inbox received/consumed 是接纳/认领证据。未采用才可恢复原消息 ID；采用后只沿原历史继续，先核对未决工具和平台动作。
- 公共 subagents.sendMessage 负责原 Worker 冷激活。预算内部控制唤醒必须绑定原 Work/Run、父子会话与授权凭证；不得借普通补充建立新的 execution。终态拒绝迟到许可，等待不占模型/工具执行时限。

- `packages/llm/token-meter/src/index.ts:71` 与 `packages/llm/llm-deepseek/src/translate.ts:159`：宿主将非缓存输入、缓存读取、缓存写入、输出分桶，四者互不包含。Token 合计与费用都相加；不能再次从 inputTokens 扣缓存。缺 usage、未知桶价格、实际路由无报价都不按零估算。

## 实施选择

新增预算账本，覆盖本工作区受管 Skill 运行及普通 Worker，展示明确覆盖时段；顶层自由对话、外部 CLI 模型、TTS 和供应商账单不伪装纳入。原生事件补录实际路由与 usage，并保留派发后未结算窗口。配置支持请求次数、token 和有价格依据的估算费用限额；价格由主人配置且保留每次计算依据，不把估价称为账单。未知 usage/价格时有对应限额则阻断后续受管请求，允许显式一次放行。

预算阻断与 input/authorization/dependency 分项保存。一次放行限定原 Run/Work 和被阻断会话的下一次模型派发，并持久记录消费；重试也重新核验。放行不清其他阻断，不延长运行时限。已发请求和工具可结算、结果与 outbox 可保存投递；日历原生提醒不依赖此门禁。

真实 Loader 和 SQLite/PostgreSQL 验证结果在实施后补录；本记录是已核源码的契约依据，不替代测试或真实账号验收。

## 子会话及补充接缝

同一个 Run 的主会话和原生子会话可以分别等待预算；迁移 30 以 `(run_id, session_id)` 保存等待，控制阻断按会话区分。一张许可仍只绑定一个会话、下一次请求，不能被兄弟会话抢用。另一个会话的预算等待不撤销已派发请求或工具的收尾权限；独立 input/authorization/dependency、终态和累计时限仍阻止继续。

普通交办的许可消费另存当时 execution_id。完成核对只有在原会话存在该次已消费许可时，才越过先前预算拦截的 blocked/error 回合，不把旧许可套用到后续人工补充。Skill 预算控制唤醒的真实消息身份入原运行输入账本，原输入的 id/source/content 原样恢复，控制信号不另建交办。

## 独立评审后的修复验证

Standards 首轮发现子会话预算续办缺少共享容量占位、宿主明确拒绝后占位和重试不收敛。现在由未消费且已发送的持久许可预留原运行名额，保留其他会话的等待；消费后交给实际步骤回执，拒绝或停止则归还。明确未接纳只保存一次失败，主人可在预算记录中重试同一许可；接纳未知进入原运行待核对，不自动重发。迟到失败不覆盖停止，重启后重试沿用原许可身份，完成后同请求仍可读原回执。

评审提供的两个 SQLite 复现均已转为期望结果。修复相关预算／界面／共享容量／普通交办单元共67项通过；完成回执40项和执行控制32项亦已通过。真实 Loader 预算7项在 SQLite 与 PostgreSQL 分别通过，覆盖本地与业务 Skill、重启、补充输入、普通交办、计划和原生子任务。最新原许可跨工作区绑定重载测试19项通过；构建、语法、预设同步和 diff 检查通过。独立复审结果另行补录。

Standards 复审另发现 PostgreSQL 唤醒失败与普通交办停止的锁顺序相反。预算事务现按原执行所有者的锁顺序访问：Skill 先运行后交办，普通 Worker 先交办再控制账本与运行。实际 PG 屏障竞争测试验证两个事务都提交、停止请求及最终停止回执保留、失败证据落账；预算单元20项通过（1项 SQLite 跳过为 PG 专属竞争用例），共享容量14项与普通运行28项通过，最新 PostgreSQL Loader 7项通过。

## Spec 评审后的归属与冷恢复修复

业务交办是独立 Worker Run；Skill 父会话继续记录其生命周期及权限，但模型预算只由 WorkerRuns 的所属运行门禁计量，避免默认不限额时仍因两个运行争夺归属而拒绝执行。真实 Loader 现有 Skill→业务交办旅程增加实际预算归属和事件唯一性断言。

固定宿主 `packages/subagent/subagent/src/activation.ts`、`lifecycle.ts` 与 `manager.ts:543` 证明：Session 历史持久保存；子任务每次驻留使用新的随机 activation runId，冷激活不会补发旧进程的 end 回执。因此只在已有预算等待／未消费许可、身份匹配、没有未结束模型步骤或未知工具／作业的条件下，为旧驻留单独保存 `recovery_data` 及 Session 事件边界；原 `end_data` 保持缺失，不伪造完成。待办输入、原 Run、原子会话继续等待，下一次放行使用新驻留的真实回执；已确认的旧预算等待不再阻止最终完成后的正常重跑。

新增冷恢复旅程覆盖主子会话同时到限→重启→分别放行→原运行完成→再次重启查结果及重跑预览。异常缺预算、未闭合步骤、未决工具和无结束作业仍拒绝恢复，并且不保存错误的恢复结论。相关10文件单元210项通过、1项SQLite跳过（PG专属锁竞争）。SQLite预算8项通过；PostgreSQL首次组合27项有2项原生唤醒超时，独立原生场景2项、完整预算8项及相同组合27项随后通过，超时诊断已扩充保留原运行与宿主输出，首次失败不计为通过。SQLite完整Skill旅程19项通过；构建、客户端语法、预设同步及差异检查通过。真实账号与部署仍单列。

## 预算续办与结算的竞态闭环

上述 PostgreSQL 超时已由独立 Spec 复审用真实账本和可控屏障稳定复现：结算读取旧预算拒绝回合后，一次放行将原 Run 恢复为 running，旧快照随后把它标成 failed，导致许可永久停在 ready/sending。现在在读取 Session 前固定本运行的模型派发请求集合，最终结算持有同一 Run 锁核对没有待消费许可、请求集合未变化、仍可结算；拒绝旧快照后保留活动权限和计时。人工停止仍按原优先级收口。

复审另用实际子会话 bash 操作证明：原 Run 因兄弟会话预算等待而处于 waiting 时，工具账本曾错误拒绝已派发步骤。现于账本事务内核对独立阻断及停止，只允许预算等待中的已派发工具收尾；新模型请求仍逐次核验预算，人工/授权等待继续拒绝。Loader 的热恢复、冷恢复均改为执行实际子任务工具，再汇总原运行结果。

最新定向6文件184项通过、1项SQLite跳过（PG专属屏障）；SQLite完整Skill与预算27项通过。两种数据库的旧快照→未消费许可／已消费许可屏障均验证原运行不误结束、最终原请求可完成，并保留人工阻断拒绝工具的断言。

后续 PostgreSQL 旅程再次暴露另一恢复竞态：普通输入恢复和预算控制信号同时对原 Session 发起工作，宿主拒绝第二个维护租约。预算续办现在按目标会话检查，原输入和主人补充统一经过既有恢复调度；兄弟会话可在自己的许可范围内继续。新增双库屏障覆盖两个入口分别先到，均只有一次原输入恢复、零个重复预算唤醒；最新预算/控制/容量86项通过、1项SQLite跳过。最新真实 Loader 完整Skill＋预算 SQLite/PostgreSQL 各27项通过，含冷/热子任务真实工具操作。

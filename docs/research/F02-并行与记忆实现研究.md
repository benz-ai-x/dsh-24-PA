# F02 并行事项与记忆维护：实现前研究记录

日期：2026-10-06。范围：P04/P05/P06/P07/P42/P36/P43/P44（#8–#15）。本文记录 F02 在 F01 已验证基础上的增量事实与设计决策；通用 dsh API 面见 [M0+F01 研究](M0-F01-兼容性与装配研究.md) 及既有四篇研究，不重复。

## 复用的已验证事实

- `ctx.fs.writeText(target, content, {kind:'replaceIfVersion', version}, signal, {mode:'workspace-write', workspaceRoot})`：版本条件原子写，旧版本报 `FS_STALE_VERSION`（F01 工作区绑定与原型记忆均已用）。F02 的 JSON 记忆权威继续走此通道，不引入第二套存储。
- `subagents.sendMessage(sender, targetId, content, options)` 对空闲 child 开新 turn；运行中 child 在 step 边界接收。`interrupt(childId, {kind:'user', parentSessionId})` 停止当前 turn（不清业务状态）。
- `sessionController.prompt` 的 `requestId` 去重、`agent-preset/conflict` 收养检查、`turn/end` 事件过滤（`event.data.turn` 对齐 assistant 消息）——F01 e2e 均已覆盖。
- 原生 settlement 通知（"Background subagent <id> finished…"）在 child 回合结束后投递到父会话（`packages/subagent/subagent/src/continuation-messages.ts:100-133`）；父会话被唤醒产生的模型回复不映射 Inbox 时不会外发（F01 行为），F02 的恢复补报显式落 Outbox。

## F02 新增设计决策

1. **消息路由表**（P05）：`pa24.message_route(message_id PK, channel, work_item_id, inbox_id, kind, created_at)`。Outbox 实际发出后按 dedupKey 前缀登记 `message_id → 事项/收件`；飞书回复带 `parent_id` 时查表固定目标：事项已完成 → sendMessage 续原 child；运行中 → steer 补充；未知/过期引用 → 明确告知，不回退投递。路由在 PG，重启不漂移。
2. **恢复代次**（P07）：`work_item` 增加 `recovery_gen int default 0`。恢复输入递增代次并写入 child 消息；'processing' 收件行重置 'received' 重派（requestId 幂等）；'admitted' 未交付行重启后无法可靠归属 turn → 标记并提示本人重发，不猜结果。用户停止（status stopped）不复活。
3. **角色注册表**（P44/P04）：`src/roles.ts` 的 `WorkerRoleDefinition {id,name,persona,brief,actions(handler),available}`。内置五类：memo 可用，calendar/tasks/reminders/handwriting 注册但标记未实现（delegate 拒绝并列出可用项）。`runtime.registerRole` 校验重复/空定义，失败保留旧注册；e2e 用「资料摘要 digest」演示注册→委派→回执。
4. **记忆权威与变更集**（P42/P43）：工作区 `.24pa/memory.json`（schemaVersion/revision/records，条目含 id/category/topic/content/source/sourceVersion/status/validUntil/updatedAt/updatedBy/reason）＋追加式审计 `.24pa/memory-log.jsonl` ＋变更集 `.24pa/changesets/CS-*.json`。整理＝只读分析（重复/矛盾/过期候选）→ 本人指令以 expectedRevision 原子应用整批 → 撤销＝逆变更集（记录 after 指纹，后续变化冲突则拒绝）。不做任何定时/后台整理。
5. **权限**：`pa24_memory` 搜索对所有角色开放；put/delete/apply/undo 仅本地顶层24私助会话（运行时校验 + 工具 allow 列表双层）。

## 测试计划

单元：MemoryStore（CRUD/版本冲突/坏 JSON/审计/变更集应用与撤销/检索边界）、角色注册校验。
e2e（真实 Loader/隔离 PG）：五项备忘并行（maxWorkers=5）各自完成并回传；回复旧消息固定路由到原事项并续办；运行中重启→恢复代次续办、停止事项不复活；本地会话记忆新增→检索→更正→变更集整理→撤销→重启核验，越权写入被拒；面板记忆页正文/筛选/分页；digest 新角色注册委派。

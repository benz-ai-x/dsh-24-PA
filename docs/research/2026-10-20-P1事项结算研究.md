## 固定宿主契约

读取本机 dsh `1600d8a1e140dcde43a1a0941940a0480712c011` 的公开服务源码：

- `SessionStore.flush(session)`（`packages/core/session/src/index.ts`）等待全部持久化监听者，任一失败则拒绝；返回 false 表示没有监听者参与，不能当作完成持久化。回合结束本身不等待刷盘，插件应调用此公开 checkpoint，不能直接写 Session 文件。
- `sessionQuery.readSession`（`packages/session-query/session-query/src/index.ts`）能冷读并重放校验全历史，不创建 Agent；但 `cold-read.ts` 会为未闭合回合追加只读 `interrupted` 结束标记，不能把它当作完成证明。
- `sessionPersistence.open(id, 'read')`（`packages/session/session-persistence/src/index.ts`）不取得写归属，可读取另一 writer 的已持久前缀；handle 提供 header、inheritedEventCount、read、close。采用它核对真实冷记录，无需模型启动或新增会话写入器。
- `startActivation` 返回原输入 messageId，`sendMessage` 返回补充输入 messageId，但不能由调用者预设这些 ID。接纳与返回之间存在窗口，不能只在返回后往同一可能失效的 DB 写一条关联作为恢复保证。
- 原始事件区分 inbox 接纳和实际消费；须重放 `agent/inbox/spliced` 与 `user/message`，核对目标 turn。`interrupted` / `forked` 不是执行完成；真实失败回合只交付失败结果。

## 决策与边界

WorkItem 生命周期在向宿主交付输入前保存本次执行标识，绑定账本 UUID、原工作区路径、父子会话、generation；原生输入带相同标识。这样 DB 在执行后不可写，仍可从宿主独立持久历史找回实际消费输入及对应完成回合。新补充输入获得新标识，旧结果不能替代它；停止和新代继续仍按当前行及 generation 校验。

宿主 adapter 收拢公开读取、flush 和证据核验；WorkItem module 收拢执行关联、结算、重试与冷恢复。结果与 Outbox 仍在同一事务提交，并在提交时核对执行标识/代次。仅重做本地结算，不再调用模型或平台动作。

运行时采用有上限退避的自动重试；工作区 lease 约束每次结算，切换后不把旧证据写进新账本。完成证据缺失/不匹配或只有中断标记时明确待核对；历史记录没有新关联时保留已有重启核对续办语义。新关联的存储/服务临时故障保留重试，不能据此重新执行原任务。

## 失败回归

`tests/e2e/work-settlement.e2e.mjs` 在真实 Loader、默认两个槽位、真实 SQL Outbox 插入故障下执行三个备忘（受控平台文档创建）。基线 SQLite 两例均按预期失败：同 Host 故障解除后两条 running、一条 queued；重启虽完成但原工作进入 generation 1。后续验收要求全部 generation 0、三个文档、六次 Worker 模型请求及三个结果 Outbox，不允许以新回合续办冒充补结算。原失败日志 `/tmp/pa24-v16-red-loader-sqlite.log` 将随验收归档。

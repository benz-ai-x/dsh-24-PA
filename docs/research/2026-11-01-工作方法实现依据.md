# 工作方法实现依据

核对日期：2026-11-01。基线：`e06e4cff30fd67721537093e135e2fc2b48c330d`，24PA 0.2.1-rc.5.3，宿主依赖 0.2.1-rc.5。

## 来源与结论

- [FranklinCovey 七个习惯](https://www.franklincovey.com/courses/the-7-habits/)：原则包含主动性、清晰成果、优先级、协作及持续更新。作为产品判断准则，具体产品行为是本项目设计。
- [GTD 官方流程](https://gettingthingsdone.com/what-is-gtd/)：收集、澄清、组织、回顾、行动。用于把事项变成可执行下一步，不增加必须学习的理论界面。
- `src/digest-service.ts` / `src/daily-planning.ts`：现有重点依赖到期任务顺序，容量采用固定工时，候选块采用固定小时。新流程独立使用真实来源和可用区间，不沿用这些假设。
- `src/source-todo.ts` / `src/source-calendar.ts`：已提供带来源、分页完整性、新鲜度的全量查询；普通首页查询读取保存观察，显式规划执行可核验原平台。
- `src/skill-package.ts` / `src/task-plan-access.ts`：原生 Skill 的业务动作需明确契约和后台白名单。两个新 Skill 只开放查询和规划草稿写入，交互式确认保持独立。
- `src/repo/*` / `src/db.ts`：工作账本已绑定单一工作区，双后端使用同一迁移列表；采用追加迁移与修订账本，无新外部平台 API。
- `src/runtime.ts` / `client.js`：`home` 组合快照及对话草稿入口可直接复用；首页不应触发业务执行。

## 取舍

近期重点和每日安排属于有期限、有采纳状态的业务计划，保存到工作账本；不自动采集为长期记忆。模型负责语义判断，程序验证版本、引用、时间可行性和状态依据。原简报与计划不静默升级，模型成本随新 Skill 的启用可见。

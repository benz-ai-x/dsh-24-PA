## 实现决定与可验证边界

1. 重复任务模板由一个 module 收拢规则身份、首实例、跳过/停止、恢复和后继推进，runtime 仅保留业务入口。身份包括标准化完整规则（星期、时区、目标清单）；创建模板及首实例一个事务。同模板控制与生成串行，实例终态及后继推进一个事务。停止保留已生成对象；跳过只推进当前实例。恢复区分未外发、已持久远端回执、未知结果，未知不盲重试；已成功/未知分支均推进未来发生。错过多次时沿用“只处理已记录的当前发生，再推进未来”的有限补偿，禁止积压洪峰。
2. 等待事项保留账本。同源创建串行，历史多 active 同源明确报告歧义，不任意合并；已结束后新建为新等待。每个明确检查点绑定稳定 ID 的原生一次性计划和内置 agent 轨 `waiting-followup` skill。模型只读当前等待事实，询问本人；平台校验等待状态/检查点身份，询问次数与 Outbox 同事务。一次检查点只询问一次，询问后清除检查点，继续等待由本人设置下次时间；不沿用旧 tick 每小时无授权重复询问。免打扰通过新原生检查点延期，取消/收到与延迟查询交叠时 CAS 拒绝旧结果。原生创建结果未知保留意图并使用既有 PlanLifecycle 对账，不重复建任务。
3. 时钟提醒只支持 once/daily/weekly 并写原生日历。every、来源跟随及强制 ledger 参数明确拒绝并说明智能 skill 路径。旧 F05 代码保留，Host 不启动它；恢复时停止旧 active/paused、取消未发送历史意图并保存处置原因，不擅自迁移成新日历对象。公共稍后/暂停/恢复/跳过不再接纳旧引擎执行；App 控制不声称已完成。
4. reminder_cancel 使用备份原渠道、原事件与完整周期范围；没有归属或平台结果未知不能伪报停止。归档默认保留提醒，显式 stopRules=true 才逐项停止原生与历史规则，并返回失败和仍存在的提醒。列表输出实际渠道、事件、委托状态，原始 start 标为首次安排，未知下一次时间不伪装成 nextDueAt。

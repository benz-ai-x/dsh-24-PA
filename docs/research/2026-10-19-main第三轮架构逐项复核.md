### R3-02 · Worker 动作参数声明与执行契约一致

**P1 / 收窄后确认 / PR-A / [R3-02 / #172](https://github.com/benz-ai-x/dsh-24-PA/issues/172)**

确认的事实：

- 实际 tools.apply 注册的 pa24_work 参数 additionalProperties=false，缺少 handler 所需 taskId/guid、due、title/attendees、plannedAt/estimateMinutes、seconds/reason 等。
- 实装 dsh-tools 的 validateJsonSchemaValue 对 {action:task_get,taskId:task-1} 报 taskId 未声明；同一实装 ToolRuntime 执行裸注册 definition 时仍将 taskId 传入 handler，结果成功。

反证、更正和范围：

- 保留为模型可见工具声明与业务动作需求不一致；撤销/禁止表述为所有宿主必拒绝额外参数、目前任务操作全不可用。
- 现有 E2E 脚本模型能提供未声明参数并成功，与真实宿主不自动校验裸 definition 相容；这不能证明真实模型能根据声明稳定生成这些参数。
- 本次未连接真实模型 provider，schema-constrained 生成的实际影响属于未量化风险，不等同已观测 provider 拒绝。

验收：

- 逐项以真实注册 schema 校验正式支持动作的最小有效 payload；每个必需字段有可发现声明，拒绝多余字段的策略一致。
- 另设实际 ToolRuntime 执行测试，分别报告 schema 校验与宿主执行行为，不把它们混成一项断言。
- 现有 role/action 权限继续生效；不要为解决 schema 放开任意额外工具。

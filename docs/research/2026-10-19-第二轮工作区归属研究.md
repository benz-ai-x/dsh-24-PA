# 第二轮工作区归属研究

基线 b78dcbb，规格 2.12 §5/§13、ADR-0001；用户已授权七项修复。

## 实证与已有契约

- 公开 bind + FakeFeishuTransport.inject、真实 SQLite 的暂停探针复现：dispatcher 在 establishSessions 等待，切到 B 后把 A 原文提交给 B 会话。源为 runtime.ts 851、1401、1494；不是 transport 准备门禁的问题。
- 真实 React DOM + 生产 writeWorkspaceConfiguration、临时文件探针复现：A 草稿在 B 快照后仍可写入 B。client.js 1044/1126、panel.ts 的保存转发与 runtime.ts 1000 共同缺少提交归属。
- 宿主安装包 @deepseek-ai/dsh 提供 SessionController queue prompt、稳定 requestId、flush 与 turn/end；沿用既有 F01/F02 研究，不新增宿主接口。停止使用现有 AbortSignal。

## 方案与验收

1. 飞书委托接收 module 集中 dispatcher、待回传与退役检查。切换先暂停新认领，有 processing/received/admitted 输入或在途处理时明确拒绝；完成/失败后可重试。停止等待正在执行的认领链退役，再关闭账本；重启按既有已接纳消息核对策略处理。
2. 每次成功激活生成不透明绑定身份，随快照提供。面板编辑从草稿到提交携带此身份，后端在串行门内核对；同路径重新绑定也视为新身份。可信本地工具调用默认捕获调用时身份，避免排队后落入另一工作区。
3. 前端工作区绑定变化时重建编辑草稿并清空密钥；快照请求按序接纳，旧响应不覆盖后发请求。保留原有同工作区字段级补丁和并发合并语义。

测试须先失败再通过：原会话等待与待回传切换、完成后切换、停止与恢复；旧/缺失保存身份拒绝，A→B→A旧身份拒绝；真实 DOM 草稿与密钥跨工作区隔离。测试 adapter 不代表真实平台验收。

# R3-A：执行边界与宿主契约

基线：main `8f70020a2f3808c3afb899e88092ee430d222efd`；安装 SDK `0.2.1-alpha.2`（真实 Loader CLI 为 `0.2.1-rc.1`）。用户已于 2026-10-19 授权开始六组修复。本文件落实 #171/#172/#180/#182/#183/#184 的实现前研究，复用 [逐项复核](2026-10-19-main第三轮架构逐项复核.md) 与其独立进程、真实 ToolRuntime/Cordis、SQLite/PG 证据。范围遵循 SPEC 的工作区归属、原发起会话回传和 ADR-0001。

## 已核实契约

- `@deepseek-ai/dsh-tools/lib/index.js` 导出的 `validateJsonSchemaValue` 拒绝 additionalProperties:false 中未声明的字段；原生 ToolRuntime 注册裸 definition 不替调用方完成同样的校验。因此补全 schema 是模型可见接口修复，不能声称所有实际运行都被 schema 阻断。
- `dsh-api-session-controller/lib/index.js` 将 prompt.requestId 写为 `user/message.source.rpcId`；`dsh-session/lib/types/types.d.ts` 的 turn/end 只有 turn/reason。不能按会话 FIFO 推断输入已被消费。
- `dsh-subagent/lib/types/index.js` / types.d.ts：startActivation 返回 messageId/result/dispose；指定 childId 可关联首条输入，dispose 处置 exact activation。sendMessage 返回 MessageId，但使用 steer，可能进入当前回合。继续已停止事项须等待旧执行终结，再接纳续办。
- drainDescendants 是依赖接收者的服务方法；调用必须保留 subagents receiver。
- Node 文件系统：预写完整的非空目录后 rename 发布，对现存非空目录替换失败。仅删除已确认死亡/本人的唯一 owner 文件名，随后 rmdir；新持有目录非空，旧回收/释放不能删除它。不能使用“比较 token 再盲删共享路径”作为 CAS。

## 方案比较与选择

比较了显式 workspace context、每次激活构造 owned module graph、统一 execution lease 三个独立设计。完整资源图长期更强，但会重构当前约 328 处资源读取和多个业务 module。此次产品只允许一个活跃工作区，选择并发 execution lease：所有异步入口在接纳时持有归属，切换/身份变更关闭接纳、等待回执落库后才替换资源。嵌套调用复用 lease，业务之间不全局串行；转换不能等待自身；宿主结果处理不得排在等待它的切换队列之后。

宿主关联以真实消费输入的 rpcId/messageId 为证据；无证据不消费新输入。冷启动从 stateDirectory 独立绑定记录发现工作区，手工 bind 与冷启动共用恢复顺序。角色目录先完整校验和持久化，再一次性生效，切换不继承前工作区动态角色。

Host 锁选非空 owner 目录，旧 JSON 只用于兼容检查活跃旧进程；新协议不依赖可被旧 release 误删的共享文件。无法保证同时运行不遵守新协议的旧版抢锁代码；升级继续遵守单 Host 约束。无法解释的记录保守拒绝，不把空/坏记录当死进程。

## 验证要求

公开 runtime 接口覆盖后台检查及已停止在途外部回执的 A→B 归属、身份重载接纳竞态、旧回合晚到、prompt 接纳后 flush 失败、冷启动发现与手工恢复队列、角色写失败/切换。Host 锁使用真实独立进程竞争，并验证晚释放不删除新锁。schema 使用实装校验器和真实注册 definition。SQLite/PG 及真实 Loader/Session 回归后记录结果；不执行真实账户写入或部署。全部结果由实施记录补充，不以设计草图冒充通过。

## 旧锁升级与恢复

新协议使用 `host.lock.d/owner-<uuid>.json`；未发布的 `.host-lock-*` 准备目录不持有锁，崩溃不阻碍后续启动。有效旧 JSON 的存活 PID 继续阻止新版启动；确定死亡的旧 PID 可自动恢复。旧版空/损坏 `host.lock` 无从证明是否仍有旧进程初始化，必须保守报错；退出同一状态目录的全部旧 Host 后，保留该文件副本、移走旧 `host.lock` 并重启即可恢复，不需删工作区账本或会话。不要同时启动仍使用盲 rename 的旧版本。此恢复路径是单 Host 升级维护步骤，不能用文件年龄冒充进程死亡证据。

实装 schema 只支持 scalar type 与 oneOf，不支持 type 数组、anyOf 或 minimum/maximum 的运行时校验。Worker schema 使用支持的子集表达可空字段和两种参会人形式；数值范围仍由业务入口验证，并以真实 ToolRuntime 执行另测。

实际 Loader 补充：SessionController.resolveAgent 拒绝解析受 subagent routing 管理的子会话。续办使用实际父 Agent 调用 subagents.drainChildren(parent, [childId]) 排空指定子会话，再 sendMessage；不排空其他并行事项。旧接口版本只从宿主公开 agents 注册表检查活跃子会话，不用顶层 SessionController 强行接管。

实施结果见 [R3-A 实施验收](2026-10-19-R3-A实施验收.md)。原生 Schedule 通过隔离端口调用，避免将创建计划时的执行归属传入未来回合。

# F12 运行维护与数据恢复：实现前研究记录

日期：2026-10-07。范围：P37/#43、P38/#44、P39/#45。基线同前（`/tmp/dsh-baseline`，dsh 0.2.1-alpha.1；用户 harness 检出仍在 rc.2 标签）。

## 一手核对结论（基线源码）

1. **原生 Schedule 归档闸**（`packages/schedule/schedule/src/index.ts:172-184`）：`workspace/session-activity` 事件里 `this.list({sessionId})` 有 active 任务时拒绝归档（archiving stop 删除行而非投递进关闭会话）——即"运行中的原生计划默认阻止不安全归档"由 dsh 原生提供；24PA 需要做的是**归档前处置自己挂的计划**（digest/task 模板经 reminder/digest 控制；原生 schedule 归档前删除）。
2. **会话归档 API**：SessionController 无显式 archive remote；归档经 workspace session-activity 流程。24PA 侧可交付的可靠形态＝`maintenance_archive_check`（盘点：运行中 Worker/active 原生计划/PG 提醒规则/未发 Outbox）＋`maintenance_archive_execute`（明确 stop → 处置原生计划与 PG 规则 → 回读结果；部分失败逐项说明；取消不复活）。真实 Workspace/Session 归档操作由 dsh 面板/入口完成，24PA 不越俎代庖——工单要求"复用真实 Workspace/Session 归档"，即检查与处置对齐原生闸门，而非另造归档。
3. **备份面**：PG（pg_dump schema pa24）、工作区（AGENTS.md/.24pa/**含记忆/修订/原稿/裁片）、dsh 域（$DSH_HOME/sessions + storages）。凭据**永不**进备份（仅记录"凭据引用清单"＝环境变量名）。恢复＝先恢复 PG 与目录再重启 Host（既有启动对账：inbox processing 重派、admitted 提示、running 恢复代次、Outbox unknown 核对）——P07 恢复路径已交付，本票补"备份产物＋清单＋水位＋恢复前对账报告"。

## 设计决策（落地契约）

1. **归档检查/执行（P37）**：`pa24_maintenance` 工具（本地24私助会话专用，动作 `archive_check`/`archive_execute {confirmStop}`）：
   - check 返回三类清单：运行中 Worker 事项（含恢复代次）、**原生 Schedule**（接入会话上 active 任务，digest/prep 计划）、**PG 提醒规则**（reminder_rule/review_reminder active，属飞书外部提醒，单独展示与选择，绝不与原生计划混同）、未发 Outbox 计数。空闲但有计划→明确列出并阻止"直接归档"路径。
   - execute：confirmStop 必需（明确停止）。顺序：停止 Worker 事项（interrupt，用户停止不复活）→ 删除原生 Schedule（逐个回读，失败列出）→ PG 规则按 `stopRules` 选择（默认保留，外部提醒不静默停）→ 最终回读清单，部分失败逐项说明。用户取消（不带 confirmStop）＝无副作用。
   - 恢复显示不重建已删计划（digest resume 需显式；归档后 plan.status 保留 stopped/paused）。
2. **联合备份（P38）**：`maintenance_backup_create {targetDir}`（本地会话执行，spawn `pg_dump --schema=pa24`；打包工作区目录与 $DSH_HOME/sessions/storages 清单）→ 产出 `backup-manifest.json`（各部分存在性、大小、sha256、PG schema 版本与水位=LSN 不可得时用 max(id)/counts、创建时间、dsh/插件版本）。`maintenance_backup_verify {dir}` 校验清单与摘要、报告缺失部分；**恢复说明**文档化（先 PG 后目录、重启 Host、启动对账路径、旧 Outbox 对账不重放、JSON 记忆恢复检查 schema/revision 且较旧不覆盖较新）。恢复演练 e2e：旧库恢复到新 cluster→迁移→代表性数据可读。
3. **健康/预算（P39）**：`maintenance_health`（Lead 工具）＋面板 `health` 端点＋运行页区块：readiness（复用）＋各能力（模型路由有效性＝vision 路由已配置且 dsh 可解析、CLI 授权、同步新鲜度）＋预算统计（自 Host 启动：输入页数/裁片数、模型请求数、重试数、Outbox 队列延迟 p50/p95 近似＝sent_at-created_at、待核对操作计数、unknown 计数）＋数据流披露（普通模型输入/额外日志/保留期/全局开关影响；凭据不出现在诊断）。降级语义确认：模型不可用→仅模型工作暂停（固定提醒继续，P18 已证）；PG 不可用→停止接纳（已有）。持续异常通知＝console.warn＋健康页呈现（完全离线告警＝独立服务器监控，声明）。T20 整体验：明暗/窄屏/键盘/加载错误断线在面板健康区补齐。

## 测试边界

e2e（真实 Loader/隔离 PG/lark-cli 桩/mock LLM，DSH_BIN 基线副本）：归档检查（空闲但有原生计划→列出并需 confirmStop；执行后原生计划删除、用户取消不复活）；备份创建→verify→恢复到新隔离 cluster→迁移→代表性笔记/任务/提醒/等待可读、旧 Outbox 不重放；健康统计真实计数（识别一页→页数+1、裁片计入）＋降级（PG 停→健康页 error 而非假成功）。真实服务器异地备份与真实费用口径：未验证，另记。

# R3-F 记忆提交与撤销契约

对应 #174 / R3-04；实现前核对日期 2026-10-19。JSON 仍是唯一可编辑记忆权威（SPEC 的 P36/P42/P43）；不增加后台整理。

已核对安装版 `@deepseek-ai/dsh-fs 0.2.1-alpha.2` 的 `lib/types/types.d.ts:105–125` 及 `index.d.ts:221`：`writeText` 接受 createIfAbsent / replaceIfVersion，成功返回包含 version/before/after 的 FsWriteOutcome，版本不匹配抛 FS_STALE_VERSION。真实集成 Host 使用本机 dsh 0.2.1-rc.1 Loader，测试分别隔离 SQLite/PostgreSQL。

方案：先规范化自动 ID，按每个 ID 保存批前一次快照和最终快照；撤销每个 ID 只操作一次，并在同一串行修改入口校验完整记录和宿主版本。历史变更集缺 ID 或重复 ID 的前置快照无法证明时拒绝自动撤销。

记忆文件提交是成功判据。审计意图在提交前保存，记录提交前/后内容摘要与唯一操作 ID。提交后审计失败返回已提交 revision 和待补审计说明；下次读取只在权威 JSON 与摘要对应时补写审计，绝不回放记忆写入。无法判断的中断保留记录并阻止下一次修改，供主人核对。审计重试用操作 ID 去重。变更集保存失败发生在记忆写入前；记忆写失败后核对实际文件，避免把已提交结果报告为未提交。

不涉及真实飞书写入、线上迁移或主人已有文件修改；故障注入使用临时目录。验收结果在本组交付记录补充。

# F08 事项交办与持续跟进：实现前研究记录

日期：2026-10-06。范围：P13/#32、P19/#33、P22/#34、P23/#35。F03 任务契约、F04 日历/联系人解析、F05 提醒引擎与静默策略见各自研究文档；本文记录 F08 新核对的一手事实与落地契约。

## 一手核对结论（lark-cli 实测）

1. **对外发信**：`lark-cli im +messages-send --user-id <open_id> --text <内容> --as user --idempotency-key <key>`（`--user-id` 与 `--chat-id` 互斥；支持幂等键）。固定 argv + `--json` 信封与现有 `runLarkCli` 相容。
2. **任务分派**：`lark-cli task +assign --task-id <guid> --add <open_id,…> --as user --idempotency-key <key>`（write 风险级；平台真实接口，非近似）。收件人仍走 F04 已验证的联系人解析（记忆 `联系人：姓名` confirmed 记录＋显式 open_id，歧义必须澄清）。
3. **飞书原生重复任务**：`task +create` 未暴露 rrule/重复参数（`--help` 实测无 repeat 字段），任务清单级重复规则亦无 CLI 面。按 #34 验收「优先复用飞书；需要模板时使用 dsh 时间规则与 PG 唯一实例」——首版走模板路线并如实说明。
4. **周期时间规则**：dsh-schedule `createEveryScheduleRecord` 最小间隔 60s（MIN_EVERY_INTERVAL_SECONDS，F05 已核）；`resolveRecurringOccurrence` 只给最近一次错过的发生——恰好是实例补建的正确语义（暂停期间不无界回补）。

## 设计决策（落地契约）

1. **交办与发信（P13）**：tasks Worker 新增 `outreach_send`（目标人=显式 open_id 或记忆 confirmed 联系人唯一命中；歧义澄清，绝不静默换人；**必须携带本人明确指令依据 instruction**，仅"帮我起草"时工具拒绝发送并返回草稿）；`task_assign`（对已存在任务加分派成员，instruction 依据必需）。两者均 staged 幂等操作（action_operation，params 哈希键）：结果未知不自动重试，先核对。执行记录（含平台 message_id/操作号）入账本可查。资料、笔记内容、等待事项的到期询问一律不构成对外沟通授权。
2. **来源跟随提醒（P19）**：`reminder_create` 增加可选 `linkSource`（task guid 或 calendar event id）；链接时快照来源指纹（任务=summary+due、日程=summary+start/end）。**发送前复核**：派发时实时读本地投影/任务表比对指纹——来源取消/改期则该实例取消并通知"来源已变更"；投影不可刷新时提示新鲜度而非照发。**事后更正**：日历同步或任务更新发现来源指纹变化时，对已按旧指纹发送的提醒补发关联更正（竞态窗口收敛）。多个会话关注同一来源按业务键（rule id）天然合并；不重写飞书原生重复规则。
3. **重复任务模板（P22）**：`pa24.task_template`（title/tasklist/schedule record/status）＋ `pa24.task_template_instance`（id=模板:dueIso 唯一键，status pending/generated/skipped/failed）。有界物化 tick（默认 30s）：到期实例经 staged 操作创建真实飞书任务（幂等键=实例 id）并回填 task_id；暂停/停用期间不回补历史（dsh-schedule 语义只补最近一次）；`task_repeat_skip` 跳过本次（取消未生成实例）；`task_repeat_stop` 停止以后；`task_repeat_update` 修改以后；已完成历史保留。四态（完成本次/跳过本次/修改以后/停止以后）分别落账。
4. **等待事项（P23）**：`pa24.waiting_item`（内容、来源说明、检查点、状态 waiting/received/canceled、关联提醒）。检查点到期只**询问本人**（Outbox 文本，复用静默扣留）；没有合法可读的回复来源时不声称"未收到/已自动监测"。`waiting_mark`（收到/继续等/改时间/取消）同步调整检查点提醒；重复事件按业务去重键（来源+主题）不重复建等待项。跟进默认提醒本人，绝不自动给他人发催办（与 outreach 的显式授权边界一致）。

## 测试边界

e2e（真实 Loader/隔离 PG/真实 lark-cli 桩）：发信需指令依据、草稿不发送、目标歧义澄清、重复执行幂等、任务分派回执；任务改期后链接提醒取消＋已发旧提醒补更正；模板跨两个实例生成真实任务＋跳过/停止＋重启恢复；等待项到点询问、收到结束、改期取消。真实飞书送达与真实联系人可达性：未验证，另记。

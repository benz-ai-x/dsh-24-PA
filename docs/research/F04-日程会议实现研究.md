# F04 日程与会议安排：实现前研究记录

日期：2026-10-06。范围：P10/#19、P11/#20、P12/#21。CLI 契约核对本机 lark-calendar skill 参考；基础机制沿用 F01–F03。

## lark-cli 日历契约（skill 参考核对；e2e 以桩验证，实机另记）

| 命令 | 关键参数 | 说明 |
|---|---|---|
| `calendar +agenda` | `--start/--end <date>`、`--calendar-id` | 已取消日程由 CLI 过滤；无单事件 get，刷新走窗口查询 |
| `calendar +create` | `--summary --start --end <tz-aware ISO> --attendee-ids ou_a,ou_b` | 参会人即邀请；创建即发送邀请，因此必须先完成解析与授权确认 |
| `calendar +update` | `--event-id [--summary/--start/--end/--add-attendee-ids/--remove-attendee-ids]` | 重复日程例外需按规范处理（v1 明示范围，例外深度归后续） |
| `calendar +delete` | `--event-id` | 取消日程 |
| `calendar +freebusy` | `--start --end --user-id` | 主日历忙闲＋RSVP |

## 设计决策

1. **投影＋水位**（P10）：`pa24.calendar_event`（upsert by event_id，窗口内消失者标 canceled）＋`pa24.calendar_sync_state`（窗口、complete、last_error、syncedAt）。查询＝先同步再读投影；同步失败不冒充空日历，返回“投影可能过期”。窗口上限 62 天，防一次性拉全量。分页/增量游标以窗口重扫实现（v1 服务器单人日历规模下足够；游标失效即重扫重建，天然满足“可重建”）。
2. **写路径**（P11）：create/update/cancel 走 F03 验证过的 staged 操作（幂等键、结果 unknown 不自动重试、写后以平台回执回填投影）；变更前后范围由 Lead 在对话中展示（persona 约束＋工具描述）。
3. **会议邀请**（P12）：`meeting_schedule` 要求 `instruction`（本人明确邀请指令）；参会人来源仅两种——显式 open_id 或已确认记忆联系人（`联系人：姓名` 主题＋`ou_` 正则）；一个名字多候选/零候选 → 整单拒绝且不创建事件（创建即邀请，不能“先建后邀”）。忙闲不臆造：query/busy 返回新鲜度。
4. **取消与外部编辑**：取消写投影（canceled）；外部编辑由下次窗口同步覆盖（upsert by event_id）。

## 测试边界

桩日历为追加式事件日志（每 event_id 取最后记录，支持 canceled/attendees）；e2e 覆盖 创建→改期→取消（回执＋投影一致）、冲突查询与新鲜度、记忆解析邀请、同名歧义拒绝且零写入。真实飞书日历分页截断、重复日程例外、freebusy 实机行为待实机验收（另记未验证）。

# F15 研究：飞书接入配置向导（AI 可读指南 + nextSteps 导航）

日期：2026-10-07。研究先于实现完成；本文记录来源、实测与取舍。背景：用户在本地体验环境（`~/DSH-Space/pa24-local`，端口 3211）与24私助多轮对话仍无法完成飞书接入配置，要求为「飞书接入」提供 AI 配置前阅读的 markdown 指南。

## 一、失败根因（2026-10-07 实测取证）

环境实测：lark-cli 1.0.87（`/opt/homebrew/bin`）；profile `24PA` 绑定应用 `cli_aa095a18afb89bb4`，`auth status --verify` 显示 **bot 身份 ready、user 身份 missing**（"no token in keychain"，hint=`lark-cli auth login`）；工作区 AGENTS.md `mode=demo`、`folderToken`/`tasklistId` 为空；start.sh 密钥两行未取消注释。

1. **知识缺口（根因）**：预设系统提示词仅一句"飞书接入用 pa24_connection 做只读检查"；完整配置链路（建应用/权限点/长连接事件/发布/授权/资源标识/切换顺序）无任何 bundled 文档，模型只能凭记忆猜。
2. **可代办却不知道**：`lark-cli auth login --help` 明确是 **Device Flow 且面向 AI agent**（原文："For AI agents: … use `--no-wait --json`, send the verification URL (or QR code) to the user as your final message … run `--device-code` in a later step"）。Agent 本可发起授权、转交链接、收尾。
3. **顺序死锁**：`mode=feishu` 校验要求 ownerOpenId/folderToken/tasklistId 非空；后两者需 user 身份授权后才能获取，而授权未完成——Agent 无阶段概念，反复原地打转。
4. **密钥/重启边界**：App Secret 仅存钥匙串（提示词禁读禁回显）；env 变更必须重启宿主进程（`pa24_workspace reload` 只热载 AGENTS.md），Agent 无法自重启所在宿主。
5. **旧构建无终端**：pa24-local 当时安装的是 F13 前构建，本地会话无 bash，即使知道 lark-cli 命令也无法执行。

## 二、产品实际依赖的飞书能力面（源码枚举）

宿主 SDK 直连（应用/bot 身份，`src/feishu.ts`）：
- `im.message.create`（text / interactive 卡片，receive_id_type=open_id，带 uuid 幂等）
- `im.messageResource.get`（下载图片/文件）
- `WSClient` 长连接 + `EventDispatcher` 订阅 `im.message.receive_v1`、`card.action.trigger`

lark-cli（`--as user`，18 处调用点，runtime.ts）：
- `auth status --verify`（诊断）
- `calendar +create/+update/+delete/+agenda`、`calendars primary|get`
- `task +create/+update/+complete/+search/+assign`、`tasklists get`
- `docs +create`（`--doc-format xml --parent-token … --content -`）＋`+fetch`/str_replace 编辑
- `drive files list`

对应授权面：**用户身份按域圈定 `im,task,calendar,docs,drive`**（auth login 的 `--domain` 原生支持，避免在指南里硬编码精确 scope 名）；应用侧权限点（发消息/读消息资源/接收单聊消息事件/卡片回调）以开放平台控制台关键词给出，**精确 scope 名待真机核验**（见"未决"）。

## 三、lark-cli 契约要点（实测）

- `auth login`：Device Flow；`--no-wait --json` 立即返回验证 URL/设备码，`--device-code <code>` 完成授权；`--domain` 可重复/逗号分隔（可用域含 application…im…task…docs…drive、all）；`--exclude` 排除；`--recommend` 只要自动批准域。`auth qrcode` 可出二维码。
- `auth status --verify`：返回 `identities.{bot,user}`（status/openId/tokenStatus/userName）、`verified`；user 缺失时 message 直接给 hint。
- `config init`（app-id / app-secret-stdin / brand）、`config bind`（绑定工作区）、`config show`、`config remove`、`keychain-downgrade`。
- 全局 `--profile <name>`；24PA 侧 `config.larkProfile` 必须与 CLI profile 一致。
- 结果信封：`--json` 输出 `{ok, data|error}`；`src/lark.ts` 按此解析，超时归"结果未知"。

## 四、设计取舍

1. **指南随插件打包**（`packages/24pa/feishu-setup.md`，进 `files`）而非写入工作区：单一权威、随版本更新、不碰用户文件（模板规则"不覆盖已有文件"）。
2. **工具暴露而非依赖文件读取**：`pa24_connection` 新增 `action=guide`，运行时从包根读取并带插件版本；对本地会话（有 read）与未来其他入口一致，不依赖 cwd。
3. **nextSteps 而非阶段状态机**：`inspectAccess` 已有成熟状态机（auth: missing/unbound/mismatch/unverified/error；资源: missing/unchecked/error/ok；source: changed），本次只做"状态→下一步文案"纯函数映射并附指南锚点；结构化 `setupStage` 枚举留待观察后需要时再加。
4. **顺序铁律写进指南与 nextSteps**：env（App ID/Secret，本人填写）→ AGENTS.md（mode=feishu＋资源标识）→ 重启宿主 → `/24pa` 端到端；AGENTS.md 可 reload，但 env 与 mode 切换统一以重启为准（transport 在宿主启动时建立，保守可靠）。
5. **不做面板内嵌指南**（可选项 B 暂缓）：client.js 有用户未提交的配色调整，避免混入；指南首要服务对象是 Agent。

## 五、未决 / 真机待验

- 应用侧权限点的精确 scope 名（控制台搜索词给出：发送消息、获取消息中的资源文件、接收单聊消息、卡片交互回调）；待真机按控制台实际名称核对后修订指南（指南内已注明"以开放平台实际显示为准"）。
- `lark-cli auth login --domain …` 实际请求的 scope 集合未在真机走通（本机 user 身份未授权）；首次真实接入时核对 auth status 输出与指南一致性。
- pa24-local 切换验收依赖用户完成：浏览器授权点击、钥匙串密钥填入 start.sh、重启。

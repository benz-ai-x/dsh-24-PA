## 固定版本与已核验契约

| 接口 | 已验证行为与实现约束 |
|---|---|
| Schedule 时间规则 | 公开 `createAt/Every/Daily/Weekly/CronScheduleRecord` 和 `resolveRecurringOccurrence`；间隔最小 60 秒，每月用明确时区的 cron，非法月日期跳过。沿用相同构造与解析计算预览，避免 UI 和实际触发两套算法。 |
| 原生触发 | `source.kind=schedule` 的消息含原 schedule ID、occurrence_at、prompt；先向 Session 入队及 flush，再记 delivery。周期触发仅取最近一次并前移。原生接受不代表业务执行，1 小时有效期与暂停／代次检查在业务准入做。 |
| 原生变更 | create 无调用方幂等键；未知不能重建。delete 不撤回已投递输入。沿用 PlanLifecycle 的持久 mutation、generation 与唯一原回执恢复。 |
| pre-step 等待 | 宿主先 claim 输入，再调 pre-step；reject 产生 blocked turn，无模型请求，也无 step/start。必须先保存被消费的完整输入，恢复时重新核验并沿原输入身份处理。 |
| 中途等待 | 已进入的 step 与后续 blocked turn 可分开；原会话历史包含已完成工具动作，补充后可在同一 Session 开后续 turn。Run 不能等同于一个 turn。 |
| 执行计时 | 持久 step/start—step/end 覆盖模型与该步工具；拒绝前、排队及已结束 step 之后的人工等待不在区间内。Session event 观察为同步通知，不能把异步 observer 当模型前的持久屏障；模型前校验走 pre-step／request，工具前仍走 execute。 |

## 隔离真实宿主探针

证据：[插件](evidence/2026-10-23-manticore-m02/native-probe-plugin.mjs)、[驱动](evidence/2026-10-23-manticore-m02/native-probe-run.mjs)、[结果](evidence/2026-10-23-manticore-m02/native-probe-result.json)。原可执行目录位于 `/private/var/folders/8x/zbvzzwh525lfw_ldp529f4lm0000gn/T/pa24-m02-native-probe-xabut61i`，含由仓库测试 helper 派生的 Host／模型替身；测试 profile 已停止并清理。探针是宿主契约研究，尚不算正式 M02 双库产品验收。

- 首步阻断：0 模型调用、0 step，完整保存 1 条输入；重启后沿原 message ID 继续，最终只出现 1 条模型可见原输入和 1 次模型调用。
- 中途等待：真实工具完成后 blocked，保存上下文；等待及重启后在原 Session 继续。两个实际 step 合计 **594 ms**，墙钟 **3218 ms**，等待／停机未混入执行区间。
- 原生一次触发：catalog 转为 inactive，lastDelivery.messageId 与收到的 schedule 输入一致；业务前阻断时 0 模型调用。删除原生计划后已投递输入仍保留，必须在业务层拒绝暂停／旧代次触发。

## 采用的模块与迁移方向

1. **沿用计划身份。**扩展 `digest_plan` 的配置与回收信息，保留原 ID、schedule ID、generation、时区、投递选择和既有发生记录。通用配置经同一个 PlanLifecycle 管理；手动启停和各类阻断分别保存。旧计划按原绑定迁移，不隐式创建新原生计划，也不替换主人个人 Skill。
2. **沿用运行引擎。**扩展 M01b 的 `skill_run`、工具／输入／原生证据和 WorkItem 关联，新增计划触发、尝试、等待、时限和结果投递信息。内置／文件来源以已选来源和内容指纹捕获不可变包，不伪造个人副本；管理版本仍使用现有 Skill 事务锁。运行与 turn 分开，未结束的等待恢复沿原 Run；已结束显式接续沿既有机制新建 Run。
3. **后台权限。**仅普通业务 Skill 和明确支持的确定性模板；角色／接入向导拒绝。本地编程 Skill 必须另建适用于后台的业务范围。静态资源读取复用固定包，不重新读取工作区文件。只读网页必须由宿主实际挂载、明确声明及运行时门禁共同允许；不能因一个工具名绕过动作和资源范围。
4. **绑定和准入。**启用／重配保存平台、实际身份、资源和主人投递目标；后续默认变化仅展示差异。每次执行与写入验证当前登记和实际权限。触发按计划、代次和发生时间防重；同计划只有一条未结束运行，工作区并发有界，过期／重叠／拒绝留事件而不冒充执行。
5. **等待、重试与时钟。**输入、多个阻断、累计用时、尝试编号均持久保存。等待时结束活跃计时，恢复前逐项核验；预留预算阻断接口供 M08 使用，不把预算管理提前塞入本批。计时以属于本 Run 的实际步骤区间为依据，并持久检查点及剩余期限；停止／重启不把累计清零。未知动作仍阻止原运行及跨运行新动作，明确未执行的暂时错误才最多三次尝试。
6. **结果与投递。**在事务中先保存执行结果及变化基准，再入现有 Outbox；通知配置和接收主人固定，语音／文本独立记录。普通结果过期仅取消推送；异常通知保留到免打扰结束。补投复用原 Outbox，不能重新执行 Skill。
7. **查询和入口。**计划列表／编辑／预览／复制／回收与运行记录分别提供全量筛选和准确计数分页；运行详情包含尝试、等待、动作、结果、投递及接续。旧 WorkItem／digest 记录缺少字段时如实标明，不推算不存在的版本或用时。

- SQLite/PostgreSQL：旧计划与发生记录迁移、Skill 禁用／更新并发、计划暂停／回收与正在执行的竞争、触发去重和全局并发；实际写入目标 A 改默认 B 后仍使用 A，移除／撤权阻断。

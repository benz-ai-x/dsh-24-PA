## 采用的模块与迁移方向

1. **沿用计划身份。**扩展 `digest_plan` 的配置与回收信息，保留原 ID、schedule ID、generation、时区、投递选择和既有发生记录。通用配置经同一个 PlanLifecycle 管理；手动启停和各类阻断分别保存。旧计划按原绑定迁移，不隐式创建新原生计划，也不替换主人个人 Skill。
2. **沿用运行引擎。**扩展 M01b 的 `skill_run`、工具／输入／原生证据和 WorkItem 关联，新增计划触发、尝试、等待、时限和结果投递信息。内置／文件来源以已选来源和内容指纹捕获不可变包，不伪造个人副本；管理版本仍使用现有 Skill 事务锁。运行与 turn 分开，未结束的等待恢复沿原 Run；已结束显式接续沿既有机制新建 Run。
3. **后台权限。**仅普通业务 Skill 和明确支持的确定性模板；角色／接入向导拒绝。本地编程 Skill 必须另建适用于后台的业务范围。静态资源读取复用固定包，不重新读取工作区文件。只读网页必须由宿主实际挂载、明确声明及运行时门禁共同允许；不能因一个工具名绕过动作和资源范围。
4. **绑定和准入。**启用／重配保存平台、实际身份、资源和主人投递目标；后续默认变化仅展示差异。每次执行与写入验证当前登记和实际权限。触发按计划、代次和发生时间防重；同计划只有一条未结束运行，工作区并发有界，过期／重叠／拒绝留事件而不冒充执行。
5. **等待、重试与时钟。**输入、多个阻断、累计用时、尝试编号均持久保存。等待时结束活跃计时，恢复前逐项核验；预留预算阻断接口供 M08 使用，不把预算管理提前塞入本批。计时以属于本 Run 的实际步骤区间为依据，并持久检查点及剩余期限；停止／重启不把累计清零。未知动作仍阻止原运行及跨运行新动作，明确未执行的暂时错误最多自动重试三次（首次加三次重试，共至多四次尝试）。
6. **结果与投递。**在事务中先保存执行结果及变化基准，再入现有 Outbox；通知配置和接收主人固定，语音／文本独立记录。普通结果过期仅取消推送；异常通知保留到免打扰结束。补投复用原 Outbox，不能重新执行 Skill。
7. **查询和入口。**计划列表／编辑／预览／复制／回收与运行记录分别提供全量筛选和准确计数分页；运行详情包含尝试、等待、动作、结果、投递及接续。旧 WorkItem／digest 记录缺少字段时如实标明，不推算不存在的版本或用时。

## 执行入口补充核验

- 真实宿主 `agent/request-error` 采用注册适配器的重试策略，默认可能重试五次；局部监听不能假设自己先于全局重试插件。实现读取持久 `assistant/attempt` 的规范化失败，在每次 `agent/request` 屏障前限制本 Run 的重试次数；既有宿主仍负责退避，不复制请求循环。只接受明确的 HTTP 429、502/503/504 暂时拒绝，传输未知不自动重发业务动作。失败与后续成功仍在同一 Run 内。
- 定稿“最多自动重试 3 次”按首次加三次重试实现；此前研究中“三次尝试”的措辞已修正，规格未改变。源码：`packages/llm/llm/src/retry-policy.ts`、`packages/llm/llm-deepseek/src/transport.ts`、`packages/core/agent-loop/src/agent.ts`，均为上文固定宿主版本。
- 受管任务的持久等待使用 `pa24_run action=wait`；该控制工具不授予业务或维护权限。本地与业务运行共用此入口；本地普通对话仍可使用宿主 `ask_user_question`。受管 Skill 声明后者时在启用／预览前明确提示改用 `pa24_run`，避免宿主临时前台问题的阻塞用时、迟到答案和 Run 账本产生两套恢复机制。
- 本地恢复用原顶层 Session 的 prompt；业务恢复通过实际发起父 Agent 的公开 `subagents.sendMessage`，不把 managed child 当成顶层 Session。补充先持久化，接纳回执或消费证据锁定唯一原生输入；接纳结果未知不重发，终态不被迟到补充恢复。
- 已验证 SQLite/PostgreSQL 各 4 项真实 Loader 初测与既有 19 项运行回归；后续扩充到暂错、独立阻断、超时核对后保留失败事实。最终数量和双轴结果在批次验收时汇总。

## 运行控制评审后的恢复验证

固定 `74fc8bf` 的双轴评审发现六项问题：请求边界超时未停止原生执行、补充接纳后崩溃无法唤醒、运行详情旧回包覆盖、取消回调继承失效租约或被配置变更阻挡、接纳与采用混淆、模板缺少计时。修复不改变定稿范围：

- `agent/inbox/spliced` 仅证明接纳／提取；`user/message` 才证明内容进入模型上下文。授权阻断或未采用时崩溃后，恢复原消息身份和正文。宿主恢复会为原未结束回合补 interrupted 记录，只有未进入模型上下文的回合可以按此规则恢复；已有模型或工具动作的中断继续核对。
- 本地仍用公开 `runMaintenance`、inbox 与 `followup` 重排原输入。业务 Worker 通过实际父 Agent 的公开 `subagents.sendMessage` 冷恢复；控制消息只引用已持久保存的原消息 ID，在 pre-step 替换为原输入，已采用则拒绝控制信号。控制消息不进入模型、不授予额外权限，也不伪造第二条业务补充。关键契约来自固定宿主 `agent/runtime-types.ts` 的 PreStepDecision 与 `subagent/manager.ts` 的冷恢复行为，真实 Loader 测试验证了原 ID 只采用一次。
- 宿主自己的 agent-instructions 更新可能在当前监听器之后进入 inbox；其原生来源证据进入运行记录，仍受固定工具和当前权限门禁。它与公开 prompt 产生的 user 输入分别核验，不能把宿主规则变更误判为新的用户交办。
- 超时保存终态与独立的停止意图；实际取消、后台作业结束和回执保存分开。未完成停止在恢复时继续核对。取消拥有独立的工作区控制租约，配置变更先等待工作及取消回执全部结束；模型请求回调不等待自己的回合变为 idle。
- 模板使用同一累计时钟和尝试记录。取消信号仅作用于本次模板；已启动 CLI 先 TERM 再有界 KILL，后续读取边界检查取消。两种账本下，1 秒限制的真实 CLI 均只写入 before，约 1.5 秒内终止并保存超时记录；配置变更在回执后完成。

新增故障注入仅安装在临时测试 profile，使用原子替换状态文件，能够停在原生 pre-step 后的未采用窗口并强制终止测试 Host。模型替身按实际 Run 输入路由，父会话原生通知不消费 Run 的测试脚本。覆盖本地／业务的首条输入阻断、补充后权限变化、崩溃恢复、双击、终态迟到输入、有限重试、工具超时和配置等待期间取消；界面测试覆盖 A 操作回包不能覆盖已选 B 详情。测试使用隔离账号与本地替身，不包含真实业务平台动作。

固定 `df78efa` 复审关闭原六项，并补充发现停止确认的准入缺口与用户取消后自动恢复。修复后，接续及全新同 Skill 运行在事务中检查未完成停止、未决原生作业及人工核对证据；工作区／身份切换也保留该阻断。人工核对可记录原始未决证据，但不能代替尚未完成的停止控制回执。恢复前读取原生用户／父级取消及 inbox 取消记录，不把明确取消当作停机恢复；内部恢复移动保留原输入身份。恢复派发在首个异步读取前互斥，防止双击与轮询交错。

# F05 个人提醒与免打扰：实现前研究记录

日期：2026-10-06。范围：P15/#22、P18/#23、P20/#24、P21/#25。时间引擎复用结论来自[存储与调度研究](第一轮审核-存储与调度复用.md)；本文记录落地契约。

## dsh-schedule 公开函数（签名核对，源码 packages/schedule/schedule/src/domain.ts）

- `createAfterScheduleRecord(ScheduleId(id), prompt, afterSeconds, now, title)` / `createAtScheduleRecord(..., atIso, ...)`：一次性；`now` 毫秒。
- `createEveryScheduleRecord(..., everySeconds, ...)`：有最小间隔（MIN_EVERY_INTERVAL_SECONDS=60，实测以函数报错为准）。
- `createDailyScheduleRecord(..., {time:'HH:mm:ss', time_zone}, ...)`；`createWeeklyScheduleRecord(..., {time, time_zone, weekdays:[1-7]}, ...)`：time_zone 走 `canonicalizeTimeZone`（显式 UTC/IANA）。
- `resolveRecurringOccurrence(record, acceptedAt)` → `{occurrenceAt, nextScheduledAt?}`：只给最近一次错过的发生——恰好符合“过期循环只补一次”的既定设计。
- id 需 `ScheduleId()` 品牌；包在 Host profile 内可解析（peer 声明 0.2.1-alpha.1，本地 checkout 直连验证）。

## 设计决策

1. **规则/实例/发送三层**（P18/P20）：`pa24.reminder_rule`（kind/text/record(jsonb)/status/next_due_at/time_zone/origin_expression）→ `pa24.reminder_occurrence`（id=ruleId:dueIso 唯一键幂等；status pending/sent/skipped/snoozed/canceled；deferred_until；origin_occurrence_id 关联稍后实例）→ Outbox（dedup `reminder:{occurrenceId}`，平台接受状态可查）。不在原生 Agent Schedule 挂任务（原生交付是 Session inbox，非飞书发送）——每规则唯一执行归属在业务账本，无双发。
2. **派发状态机**：active→materialize（once 完结规则；recurring 推进 next）→ claim（SKIP LOCKED）→ 停止→取消实例；暂停→扣住；静默（休假/安静时段）→ deferred_until=窗口结束，不丢弃；正常→ Outbox＋sent。once 规则 completed 状态仍派发其已物化实例（修复过的关键语义）。
3. **免打扰来源**（P15/P21）：记忆权威 topic「休假」（confirmed+validUntil）与「通知偏好」（正文含“安静时段 HH:mm-HH:mm”，工作区时区，跨日窗口支持）；派发时实时读取，无缓存；偏好写入仅本地24私助会话（P42 边界）。
4. **崩溃与重复**：实例唯一键＋Outbox dedup 双幂等；tick 异常仅告警不终止 Host；重启后从账本恢复（due 规则重新物化）。

## 测试边界

e2e（真实 Loader/隔离 PG/真实时钟短窗）：一次性提醒发出＋仅报平台接受、取消停止后续、稍后唯一关联实例、重启后触发、休假扣住 4s 后补发。every/daily/weekly 的规则创建经真实 dsh-schedule 校验（类型/时区/星期非法被拒），长周期到期与 DST 实例留待实机（另记未验证）。

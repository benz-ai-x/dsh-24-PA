# F11 审核笔记的行动与可信查询：实现前研究记录

日期：2026-10-07。范围：P34/#41、P35/#42。复用结论：F06 版本/指纹/审核裁决、F10 候选行动选择/执行契约（(minutes,index) 幂等键模式）、F09 planningFacts/今日概览骨架。基线同前（`/tmp/dsh-baseline`，0.2.1-alpha.1；用户 harness 检出仍在 rc.2 标签）。

## 设计决策（落地契约）

1. **审核后行动（P34）**：handwriting 角色 `note_adopt_actions {noteId, versionId, indexes[], instruction}`：
   - **使用前核验**：目标版本必须 `approved`（内容批准）且当前文档指纹仍匹配（`currentFingerprint` 比对；changed/unknown 均拒绝，含未审/superseded/stale）。行动记录同时保存出处（候选引文）、日期原话（due 原文）与解析值（ISO）。
   - **复用 P27 契约**：幂等键＝`note.action:<noteId>:v<version>:<index>`（笔记版本＋行动身份）；任务分支复用 taskCreate（`_operationId` 覆盖）；重复选择返回已有对象；结果未知拒绝盲重试。批准（review_decision）与行动授权（action_operation+instruction）分别落账。
   - **候选结构化**：`note_submit` 的 candidates 兼容字符串与 `{summary, sourceQuote?, due?}` 对象（日期原话＝due 原文，解析值＝parseDue 结果）。
2. **修订影响（P34）**：发布新版本（republish/再识别）时，扫描该笔记旧版本产生的行动操作（id 前缀 `note.action:<noteId>:`），对每个已建对象发**变更建议**（差异概述＋“是否调整由你决定”，绝不静默删除/覆盖）；dedup 键＝(note, 新版本)，重复修订不重复打扰。
3. **可信笔记状态（P35）**：handwriting 角色 `notes_search {query}`（只读）——按主题/关键词检索笔记，返回**逐条核验过当前有效性**的引用：版本号、审核人与时间（review_decision）、当前指纹状态（matches=可作为已确认事实引用；changed/unknown=明确标注"已变更/无法核验，不得当作最新事实"）；给出可打开的文档链接；未审核内容标注 unverified。**同一决定多版本**：每版本独立成行，不合并、不因曾通过而继承。
4. **今日概览与晨报（P35）**：`planningFacts` 增加 reviewedNotes（最新版本 approved 且当前 matches 的笔记，取最近 3 条，含版本/审核时间/链接）；等待项与待审队列 F09 已入概览/晨报——本票核对"缺数据注明"语义（reviewQueueCount=-1 时显示"无法读取"而非 0）。会话历史不默认拼接（只给对象链接）。

## 测试边界

e2e（真实 Loader/隔离 PG/lark-cli 桩/mock LLM，DSH_BIN 基线副本）：结构化候选→批准→只选两项（仅建两个）→重复选择幂等→过期审核（文档编辑后版本 stale）拒绝→再修订产生变更建议且不重复→notes_search 多版本与失效标注→概览含已审笔记与等待/待审。外部成功但回执丢失（unknown）注入与真实识别质量：声明未验证（staged 语义与 F10 同源，已被 F10 用例覆盖的任务分支复用）。

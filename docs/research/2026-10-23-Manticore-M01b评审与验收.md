# Manticore M01b 评审与验收

范围：#214；比较基线 `91aff7c96a59cab2cf00fa2eaf379008079d55a2`，首轮固定实现提交 `6d620e0`。真实宿主固定为 `1600d8a1e140dcde43a1a0941940a0480712c011`。生产账号、真实业务投递和部署不在本轮隔离验证内。

## Standards

- [P1] 并发重试会重复启动同一运行。`admit()` 返回原 Run 后两个调用都执行 `launch()`；实际 SQLite 复现同一请求模板执行两次。违背 SPEC 的稳定 requestId 去重要求。
- [P1] 重新核对旧运行会停止当前交办状态。A 核对后接续 B，A 收到迟到回执再核对时无条件把共享 WorkItem 改为 stopped，实际复现 B running / WorkItem stopped。违背独立接续与停止语义。
- [P2] 子任务编程权限与 accepted ADR 不一致。实现支持本地 Skill 原生编程子任务，但 ADR-0001 仍规定仅本地顶层会话开放。依据 domain.md，权限决定不能静默覆盖。

Standards：3 项，最高 P1（并发重复启动、旧运行改写当前交办）。

## Spec

- [P1] 核对旧运行会停止正在接续的交办。应仅让当前运行更新交办状态。依据产品定稿“同一交办关联多次运行”和“迟到回执修复原记录”。
- [P2] 删除 Skill 后丢失历史及未结束运行的管理入口。目录与详情拒绝已删除条目，原运行无法停止或核对。依据产品定稿“保留历史快照和结果”和 #214 用户入口、异常恢复同一 PR 闭环。

Spec：2 项，最高 P1（旧运行核对影响正在接续的交办）。

## 修复与验证

- 原子认领 pending Run；只有认领者可启动原生执行。双库服务层并发请求均返回同一 Run、仅执行一次；真实 Loader 并发请求验证一条 Run、一次模型调用。
- WorkItem 保存当前 Run 指针；状态、进度、结果和核对仅由当前 Run 更新。双库回归覆盖 A 核对、B 接续、A 迟到证据重新核对，B 和交办均保持 running，B 可正常完成。
- 目录保留已删除 Skill 并明确标记；详情允许查阅版本、下载和管理原运行，禁止编辑、启用、复制和新运行。双库回归验证删除后历史可读、原运行可停止、新准入被拒绝。
- ADR-0001 明确 Manticore 本地运行与原生编程子任务的受限授权，配置/记忆维护权限不向子任务扩散。
- 修复后：构建与客户端语法检查通过；运行事务与工具挂载 37 项通过；SQLite/PostgreSQL 各 14 项真实 Loader 测试通过。全量单元回归和界面验收继续进行。
- 首轮全量回归 828 通过、7 失败：失败来自旧工具挂载测试夹具缺少新依赖，补齐后该文件 7 项通过；未把夹具问题当作产品通过。

独立复审在 `27b915f` 通过：Standards 原 3 项清偿（独立复跑双库 4 项）；Spec 原 2 项清偿（独立复跑双库 6 项）。两轴均未发现新增问题。

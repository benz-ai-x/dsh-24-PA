# Manticore 来源登记实施契约

范围：M03 / #216，基线 `76d33d36f5ff412ddb72f5c2cd86c9355d810852`。沿用[多来源与渠道核查](2026-10-20-Manticore-多来源与渠道核查.md)的固定 CLI 契约；本文补充 S1–S3 的本地配置、身份、观察与办理设计，不表示渠道真机验收通过。

## 配置与证据

AGENTS.md 的 `sources` 保存来源登记、分域默认、公司／项目映射和可选会议时长，仍是唯一可编辑配置。登记声明使用意图，不携带“已授权”开关；实际读写、身份、原生容器和检查时间由只读检查写入账本证据。固定飞书 profile 不扩展为多账号，企微授权范围与真正日历容器分开。

旧配置缺少 `sources` 时产生确定性的迁移候选，保留原字段和原生对象关联；本地保存确认后物化为同一配置块。读取、迁移、重载都不发起远端创建。缺身份或 `primary` 尚未解析时显示待核验。明确空列表表示已移除，不恢复旧默认；重复迁移不追加同一来源。

来源 ID 标识登记项，平台对象身份与来源成员关系另存。身份、资源、使用范围变化使已有能力证据失效；名称变更保留来源 ID。来源移除留下历史及原目标，阻断新的写入；恢复已发出的操作仍使用原操作记录，不由新默认推导。

## 集中边界

- `source-config`：校验非秘密配置、生成旧配置迁移候选、按明确来源→公司／项目映射→默认解析唯一目标。必要信息不全、多个匹配或不可写均返回可修复错误，不降级到另一来源。
- `SourceRegistry`：对登记、检查与目标快照集中验证；数据库只存检查证据和历史，不反向覆盖配置。快照固定平台、真实身份、资源和登记指纹；执行前重验当前登记与权限。
- 来源对象仓库：分开保存对象、来源成员关系及分源观察状态；只有完整的同范围观察可以使该来源下消失的成员失效。其他来源或历史关联不受影响。失败保留缓存与最后成功时间，不伪报全空。
- 日程服务：消费同一来源解析和观察接口，输出聚合范围、角色筛选、冲突与时间证据。跨平台同名／同原生 ID 不合并。修改只允许解析出的原定位；取消整场、本人退出、移除本人提醒及重复系列范围分别表示。

关键边界测试使用实际 SQLite／隔离 PostgreSQL，覆盖配置冲突、原生 ID 碰撞、单源失败、移除来源、默认变化与重启。完整功能另需真实 Loader／Session 与浏览器验收；模型和平台传输可替换，平台授权和真实设备效果单列。

## 本次补充核查

- 本机版本仍为 lark-cli 1.0.87、wecom-cli 1.3.4。只读 schema 确认飞书 `calendars.get` 的 `role` 才是当前身份权限，`permissions` 是公开范围；第三方日历即使返回 owner 仍只读。`primary` 返回列表，须按 owner 的 open_id 唯一解析后读取实际日历，不能保留别名当冻结目标。
- 飞书 [auth status 固定源码](https://github.com/larksuite/cli/blob/v1.0.87/cmd/auth/status.go) 返回 appId、有效用户身份和 verify 结果，来源绑定使用应用与本人标识；不保存 token。企微 whoami schema 仅给双身份说明，解析真人和机器人 ID，不由姓名识别身份。相同用户 ID 换应用／机器人须重新登记，重复检查不能默默覆盖已绑定身份。
- 企微 todo list schema 的状态参数是数组 `status_filter`，通过 `--status-filter '["proceed"]'` 显式查询；不是单值 `--status`。固定官方[日程查询文档](https://github.com/WecomTeam/wecom-cli/blob/f9b28151dc8d42f703db624fc9b26723c3c93fc5/skills/wecomcli-calendar/references/calendar-agenda.md)仍只承诺当前前后 30 天。公开多日历文档 93647/93648 再次读取失败，未采用第三方摘要作为当前授权可用性证明。
- 飞书 `event.attendees.list` 需要遍历 `has_more/page_token`；群参与者不能用已废弃的 `chat_members` 字段猜本人关系。已安装官方 Node SDK 1.74.0 的 `calendarEventAttendeeChatMember.list` 和类型声明给出 `GET /open-apis/calendar/v4/calendars/:calendar_id/events/:event_id/attendees/:attendee_id/chat_members`。固定 CLI 无对应 typed command，可用其原生 `api GET` 与同一固定 profile/user 身份，显式分页；不会引入另一个凭据机制。
- 以上仅运行版本/help/schema、读官方源码与已安装 SDK；没有调用真实身份、资源或业务写入。S1 的配置、来源检查适配及并发编辑共 62 项隔离测试通过，S2 对象关联继续验收。

## 已落地的查询和办理边界

schema 20 分开保存来源登记、权限身份证据、平台对象、来源成员及观察。平台对象按领域／平台／真实身份／原生对象标识区分；同一会议的副本只有原组织者日历和实例 ID 相同才合并。成员保留各自完整快照、角色、忙闲、提醒、权限及核验时间，后读副本不改写另一来源的旧正文。合并结果只在所有所选位置都为 free 时视为空闲。

完整对象范围与完整角色证据分别表示。飞书使用原生 instance_view，按小于 40 天分窗；触及 1000 项保护上限时继续分割，不能拆解到足够小的窗口则报告 partial。参与人和群成员均验证分页结束标志；角色未知时“全部可见”仍展示对象，按参与关系筛选则报告不完整。企微只核验授权范围的前后 30 天，系列实例未完整展开时报告 partial；没有本人标识的 creator_name 不作组织者证据。

查询、卡片、忙闲和每日规划使用同一聚合服务。内部忙闲读取全量，不采用首页作为完整时段；普通浏览和健康页只读保存的证据。来源停用不影响其他启用来源的完整性，明确点名停用来源会被拒绝。晨报附来源与查询缺口，读取失败不报“无日程”。

写操作先冻结平台、应用／机器人及本人身份、真实资源、登记版本和实际请求，再经既有外部操作账本保存平台接受回执。成功后的单对象回读比较主题、时间、取消状态及提醒设置；平台接受与回读一致性分别返回。未知操作不再调用创建；持久接受回执后的本地失败按原快照补账，来源移除也可修复历史但不恢复可查询成员。请求摘要递归规范化字段顺序，避免 PostgreSQL JSONB 键序变化误判重试。旧候选、规划和提醒继续识别原账本键及渠道，不拿新默认替换原目标。

Feishu 创建／修改／取消／本人提醒编辑和明确参会人邀请分别留回执；邀请失败只重试邀请。缺主题用“会议”，时长只取明确输入或已保存预设。系列仅在实例／系列标识和操作范围匹配时办理。企微支持已核实的创建、修改／取消，修改／取消还须有同一身份和登记版本的原创建凭证；指定日历容器、可靠外部组织者证据、邀请、本人提醒编辑及 Feishu 本人退出等当前未接通路径明确返回适配差异。

新独立提醒使用 0 分钟提前量，在请求的时刻提醒；历史记录保留原提前量。会议取消本人提醒只清空提醒，不删除会议。新会前准备计划绑定原身份、资源和日程，生成前后重新核验；同一原生 ID 在其他日历／平台的变化不误停本计划。规划和晨报已接入聚合观察；待办来源登记／检查先交付，待办业务接入由 M04 完成，界面和指南均说明该阶段边界。

## 宿主入口复验

固定 Host `1600d8a1e140dcde43a1a0941940a0480712c011` 的 `api/session-controller/src/agent.ts:createSession/reuseLive` 会按请求预设复用空会话；浏览器启动的默认工作区连接可能把原本的 pa24 空会话改为 standard。真实导出的 session.v4.jsonl 已观察到 `agent-preset/selected: standard`。只按缓存 ID 打开会落入错误入口。

面板打开本地会话时现重新解析实际 Agent 预设。发生变化时保留原会话，采用原生 create 返回的实际 Session ID 建立新的 pa24 入口，并保存归属；并发打开经同一门限复用入口。真实浏览器已验证先进入标准空会话，再通过日程草稿进入 pa24，复制内容可粘贴且不自动发送。两种账本的真实 Loader 测试同时覆盖该场景。界面没有伪造业务结果。

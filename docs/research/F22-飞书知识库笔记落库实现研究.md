## 2. 关键契约（真机实测）

### 2.1 核心：docs +create 直接接受 wiki 节点作父级（✅ 实测通过）

`lark-cli docs +create --help` 官方声明：`--parent-token string  parent folder token or wiki node token`。

实测链路（my_library 中建临时节点验证，已清理）：

```
wiki +node-create --as user --space-id my_library --title "验证节点"
  → node_token: HKIbw…  obj_token: NnwRds…  obj_type: docx  space_id: 7521…
printf '<markdown>' | docs +create --as user --doc-format markdown \
    --parent-token HKIbw… --title "…" --content -
  → document_id: FR5JdEGs…  url: https://…/docx/FR5JdEGs…
wiki +node-list --space-id 7521… --parent-node-token HKIbw…
  → data.nodes[] 含 {obj_token: FR5JdEGs…, parent_node_token: HKIbw…, obj_type: docx}
```

结论：**CLI 自动为 docx 建 wiki 节点并挂到指定父节点下**；返回体与 folder 路径同形（`data.document.document_id/url`）。24PA 两处创建**只需换 parent token 来源，管道零改动**。

### 2.2 配置解析与只读探测

| 命令 | 用途 | 返回要点（注意字段名） |
|---|---|---|
| `wiki +space-list --as user` | 向导按名称找知识库 | `data.spaces[]`（**非 items**）：space_id/name/space_type |
| `wiki +node-get --node-token <t>` | 用户贴知识库链接→解析 space/node | `data`：node_token/obj_token/space_id/title |
| `wiki +node-list --space-id <id> [--parent-node-token <t>]` | 资源可读性探测 | `data.nodes[]`（**非 items**） |

### 2.3 身份与权限语义

- 知识库/节点是用户个人资源，统一 `--as user`（与现有 docs 路径一致）；bot 身份列出的是应用所属空间，不采用。
- 用户令牌下次调用自动刷新（needs_refresh 状态实测无碍）；refresh 有效期至 2026-10-15。

## 3. 已知边界与坑（实测踩到）

1. **url 形态**：docs +create 返回 docx 直链（`/docx/<id>`）而非 `/wiki/<node_token>`；挂入知识库后飞书会跳转 wiki 视图（通知/审核卡片沿用返回 url，与现行为一致，不改）。
2. **node-delete 语义**：删除挂有子文档的容器节点必须 `--obj-type wiki --yes`（返回 `include_children: true, status: success`，异步但即时 ready）；误传 `--obj-type docx` 报 131005 `document not found by token`。24PA 流程不删文档（退回走版本状态机），此坑仅测试清理需知。
3. **stdout 提示行**：wiki 域命令在 JSON 前混入 `Found N node(s)` 等人类可读行；JSON 解析取首个 `{` 起（现有 `runLarkCli` 信封三态解析已兼容同类前缀，实现时回归验证）。
4. **title 回读**：markdown＋`--title` 组合下返回体 `document.title` 为空——现有代码只依赖 document_id/url，不受影响；勿新增对返回 title 的依赖。
5. lark-cli 版本 1.0.87→1.0.97 升级与本迭代解耦（README 版本矩阵另行跟进）。

## 4. 方案与取舍

**选定方案：配置 `wikiNodeToken`，创建路径按「wiki 优先、folder 回退」换 parent token。**

- 配置：AGENTS.md 新增可选 `wikiNodeToken`（知识库入口或分区节点链接 token）。已配置 ⇒ 备忘与手写待审文档都建到该节点之下；未配置 ⇒ 沿用 `folderToken`（存量零影响）。两字段允许并存，wiki 优先。
- 写入：`runtime.ts` 两处 create 的 parent 取 `config.wikiNodeToken || config.folderToken`；创建失败提示文案「体验目录」改中性（目录或知识库）。
- 生命周期：审核卡片、批准/退回、`docs +update` 版本迭代全部按 doc_id 工作，挂载位置无关，**零改动**；不引入删除/移动逻辑。
- 诊断：`feishu.ts` 资源探测加「知识库」行（配了 wikiNodeToken 时 `wiki +node-get` 只读探测）；`connection.check` 自然覆盖。
- 面板：资源行数据源 `resourceRows` 增第四行「知识库」（client.js 现有渲染逻辑自动带出，仅加一行数组＋说明文案）。
- 向导：不新建向导命令——配置经既有「对话维护配置」路径完成（「把我的知识库『工作笔记』配进来」→ space-list 按名解析 → node-get 校验 → 写 AGENTS.md），feishu-setup.md 补「复制知识库节点链接」步骤与示例。
- 提示词：memo/notes persona「保存到配置的飞书目录」→「保存到配置的飞书目录或知识库」；PROMPTS_VERSION bump。
- 测试：config 单测（字段可选/优先级/非法值）；stub lark-cli 补 `wiki +node-get/+space-list` 与 wiki-parent 的 `docs +create` 行为；e2e 一条「备忘保存进知识库」（断言 stub 收到 wikiNodeToken 作 parent）。

**否决的备选**：路径 B（`docs +create` 建我的空间→`wiki +move` 移入）——多一次异步 move＋轮询＋失败恢复（孤儿文档），且 `--parent-token` 直挂已验证成立，无采用理由。待审文档「批准后移入」方案——用户语义即「写完了让我审核」，直接建在知识库，退回走版本状态机，无需移动。

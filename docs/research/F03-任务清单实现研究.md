# F03 任务与项目清单：实现前研究记录

日期：2026-10-06。范围：P08/#16、P09/#17、P17/#18。基础事实沿用 [M0+F01 研究](M0-F01-兼容性与装配研究.md) 与 [飞书接入研究](飞书接入与审核机制.md)；本文记录 F03 增量契约与决策。

## lark-cli 任务子命令契约（本机 lark-task skill 参考，实测于桩）

| 命令 | 关键参数 | 语义/边界 |
|---|---|---|
| `task +create` | `--summary`、`--due <date\|"+2d">`、`--tasklist-id <guid>`、`--idempotency-key <key>` | 幂等键为平台侧去重；响应含任务 guid/url |
| `task +update` | `--task-id <guid>`（可逗号分隔多个）、`--summary`、`--due` | 无 CAS；无“清空 due”的确认契约 |
| `task +complete` / `task +reopen` | `--task-id <guid>` | 写操作；显示 ID（t104121）被拒绝，须用 guid |
| `task +search` | `--query`、`--completed=false`、`--due "-1d,+7d"` | 查询/刷新投影用；**无单任务 get 命令** |

无 `task +delete`：平台（经 CLI 暴露面）不提供删除/取消——F03 的 `task_cancel` 如实返回能力边界（可修改标注或完成归档），不伪造取消。

## 设计决策

1. **staged 操作复用 P14 契约**：create/update/complete 均以 `action_operation` 稳定键幂等；结果未知（超时/丢响应）标 `unknown` 且拒绝自动重试，要求先 `task_get` 核对（研究结论「云端超时先对账」）。
2. **投影非权威**：`pa24.task` 保存 due/planned/estimate 与同步水位；写路径在每任务串行门内先重读投影＋尽力远端刷新（`+search` 按 guid 命中才回填），只覆盖本次明确修改的字段，避免旧投影静默回退他人/本人直接在飞书的修改（P09「冲突不静默覆盖」在单 Host 语义下的落地）。
3. **门与幂等层级**：进程内 per-guid Promise 门（v1 单 Host，ADR-0001）＋操作幂等键＋平台 idempotency-key 三层；跨 Host 协调属 F12 运维范围。
4. **截止/计划/估时分离**：due 送平台；planned_at/estimate_minutes 为本地计划属性（Motion 调研结论），不写入飞书任务。
5. **项目采纳**：拆解建议由 Lead 在对话中给出；`project_adopt` 仅按本人采纳创建真实任务并关联（opSuffix=项目+序号保证部分失败重试的键稳定）；进展只读实际任务状态。不订票/付款/对外提交（P17）。
6. **刷新新鲜度**：`task_get` 返回 `stale`（本次远端核对未成功即为 true），失败不冒充成功。

## 测试边界

桩 CLI 以追加式任务日志（每 guid 取最后记录）模拟平台，保留幂等键与 JSON 信封；e2e 覆盖创建/链接/重复复用/修改/完成/远端刷新/项目采纳与进展。真实飞书租户的 update/search 匹配率与 due 相对语法待实机验收（另记未验证）。

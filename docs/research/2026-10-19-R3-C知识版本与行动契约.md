## 已核对的接口

- 本机 lark-cli 1.0.87 的 `docs +fetch --doc-format xml --detail full` 默认全文（不传 scope），返回同一响应中的 content、revision_id、reference_map。局部 fragment/excerpt 不足以批准整稿。reference_map 是 `block_type → ref → 真实属性`，不能丢弃再解释图片。证据为本机 CLI help 与 `skills read lark-doc/references/lark-doc-fetch.md`；仅只读契约查询，无账号读写。
- 图片 token 可经 `docs +media-download --token --output ... --type media --as user` 下载，读取字节摘要；不能把 token 改变当成换图。使用明确 `.bin` 临时路径、大小上限与内容格式核验，失败保持 unknown。动态 synced_reference、sheet、bitable、whiteboard 等不是完整静态内容，当前不展开时明确拒绝整稿批准。
- XML 结构解析采用已安装 saxes 6.0.0，并显式声明生产依赖；使用 fragment 模式和公开 tag/text/close 事件。作者 [接口文档](https://github.com/lddubeau/saxes) 与本机 README 一致：只接受良构 XML，不扩展 DTD 外部实体。该库已归档，因此固定版本；不把其当作 HTML 容错器。
- dsh 0.2.1-rc.1：沿用 A 组真实 Loader 证据与 WorkItemLifecycle.admit 的单宿主接纳队列。笔记活动检查移入既有准入边界；会议按来源事件串行接纳，持久 lifecycle 包含未知创建，不能绕开另起计划。原生 Schedule 沿用 PlanLifecycle 回执恢复，不新增调度器。

## 实施决策

1. 版本由一个完整读取结果产生正文、规范化、资源摘要及 revision；republish 不再二读混用。人工编辑后清空过时派生摘要/转写/候选，标记未重建；批准原稿不重新赋予旧行动参数可信性。检索/晨报明确不消费未重建派生资料。
2. 指纹保留标题、文本、列表/表格结构、图文位置和图片字节摘要，忽略提供方 ID/token/渲染元数据；仅登记格式的审核状态行可排除。旧版指纹保守失效，需重新发布/审核，不静默继承旧批准。
3. 原稿只有 collecting 可追加；任一后续状态保持批次关闭。同一平台 message 的已保存页先查询并恢复回执，不再下载/另建笔记；保存后的通知或 inbox 故障如实报告后续未完成。
4. 审核卡复用未过期的持久 token 对；过期后新一代 token 产生新 Outbox 身份，正文不变不新建内容版本。状态同步从当前文档实际登记行更新并读回；pending/failed 均可恢复，旧版本决策不能覆盖当前版本。
5. 纪要生成身份由同次保存意图、候选及明确修订标记决定；兼容已有纪要身份，重试不复制。候选执行持久化主人指令与来源编号；笔记候选保留关联 unknowns，只有明确逐项澄清才允许选定行动，并保存澄清依据，不篡改已审快照。
6. 会前资料分别报告各来源的成功空结果/失败/未授权；不把无关最近纪要当上次纪要。notes_search 失败显式失败；planningFacts 项目读取失败进入 missing，保留其他已取得事实。

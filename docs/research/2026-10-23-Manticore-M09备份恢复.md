## 结论与范围

复用现有 `WorkspaceBackup`、双库 `PaDb.backup()`、账本归属检查、原生 Session 冷读取和 M06 `planMemoryRestore`。本轮需要补的是：**备份、校验、恢复演练的独立持久事实；实际资源引用核验；只作用于隔离副本的恢复准备与检查；启动执行前的待核对事项**。不增加周期备份，不提供全自动覆盖当前工作区。完整产品依据为 [Manticore 定稿「备份与恢复」](../planning/24PA-Manticore-产品定稿.md#备份与恢复)、[SPEC §7/§11/§12](../24PA-v1-SPEC.md#7-会话及外部动作的恢复)及 #222。

三处必须避免沿用旧测试的误解：

- 个人受管 Skill 的完整包、不可变版本与运行快照在账本，`.dsh/skills` 只覆盖文件来源；仅拷贝该目录不足以恢复 Skill 管理。[SkillRepo](../../packages/24pa/src/repo/skill.ts#L8)、[SkillRunRepo](../../packages/24pa/src/repo/skill-run.ts#L12)
- 审核快照在 `note_version.doc_snapshot/content`，原稿和裁片分别在 `.24pa/originals`、`.24pa/crops`。现有备份测试构造的 `.24pa/revisions`、`.24pa/memory/backup-probe.json` 只是集合复制夹具，不能证明实际审核/记忆对象恢复。[审核发布](../../packages/24pa/src/handwriting-pipeline.ts#L447)、[F12 旧夹具](../../packages/24pa/tests/e2e/f12.e2e.mjs#L147)
- 正常重启的防重机制不能代替旧备份恢复的对账：旧 `pending` Outbox 会被领取；备份后已经发生、但旧账本没有记录的远端动作仍未知。隔离演练必须禁用调度、模型、入站和出站消费者；只复制后查表不能宣称“恢复后不会重发”。[OutboxRepo](../../packages/24pa/src/repo/outbox.ts#L53)、[OutboxDelivery](../../packages/24pa/src/outbox-delivery.ts#L34)、[启动恢复](../../packages/24pa/src/runtime.ts#L979)

## M06 JSON 与 tombstone 接缝

稳定接口已在 M06 提交，从 `memory.ts` / `memory-model.ts` 导出：

```ts
planMemoryRestore(current: MemoryFile, backup: MemoryFile)
// => { file, added, protectedIds, conflicts, currentRevision, backupRevision }
```

`MemoryFile` 读取支持 schema 1/2；`tombstones` 仅 `{ id, deletedAt, revision, mutationId }`，不得保存正文等额外字段。同 ID 不得同时出现在记录或墓碑中。函数验证两份输入但不写盘；合并两边墓碑，当前墓碑优先；保留所有未被墓碑禁止的当前记录；只补当前不存在的备份记录；同 ID 内容不同时保留当前并列入 conflicts。候选 schema=2，revision=`max(current, backup)+1`，不伪造 `lastMutationId` 提交证明。[模型与纯规划](../../packages/24pa/src/memory-model.ts#L228)、[M06 契约](2026-10-23-Manticore-M06记忆生命周期.md#数据与接口契约)

M09 的调用规则：

1. 先核同一工作区身份，解析当前与备份 JSON；不存在和坏 JSON 分开。坏文件不能作为空当前文件参与合并。预览绑定双方内容摘要、备份 manifest 摘要及当前 workspaceBinding；隔离准备前再核，过期则重做。
2. 展示新增、被删除标记保护及冲突 ID；正文比较留在本地详情，不写入摘要/运行诊断。即使备份 revision 更高，也不静默覆盖当前同 ID 记录。
3. 候选 JSON 只写入隔离目录，原文件及原备份保持不变。恢复旧 changesets/audit 也可能带回永久删除正文，必须在副本完成墓碑清理并核磁盘结果后，才能记录该项通过；不能只合并 memory.json。
4. 现有 `MemoryStore.search` 可重试派生清理，但 `memory-audit-pending.json` 的前后摘要不匹配会形成待核对警告。恢复不能删除这份证据后假称成功；须将未决提交、坏修订和清理失败列为阻断，必要时给 M06 增加专用、可测试的隔离派生清理入口，而不是在 M09 重写清理算法。[审计/清理](../../packages/24pa/src/memory.ts#L82)
5. 保留 tombstone 只保护现存或可提供的删除证据。若现场完全丢失、唯一备份早于永久删除，系统没有依据推知后来的删除；演练须说明删除证据覆盖到何时，不能声称已保留不存在的证据。原始旧备份、源资料及历史会话按既定各自保留政策处理，不因恢复准备而改写。

以上是对已批准“不覆盖较新记忆/删除记录”的实施约束，不扩大为自动合并并覆盖生产数据。

## M09 的实施缺口与最小接口建议

以下是实施准备，不是已实现 API；最终名称在集成基线确定，M06 纯接口保持不变。

| 缺口 | 建议交付行为 |
|---|---|
| 无持久备份/校验/演练记录 | 一个备份维护 aggregate，按 `create / verify / restore_check` 分类型保存 workspace UUID、请求幂等键、开始/结束、状态、备份路径/manifest 摘要、来源版本、各步骤结果及错误；后两类关联同一备份，不覆盖旧结果。运行中断可见，重试新记录或明确接续，不把中断更新成成功。若用账本，迁移号已协调预留 **31**。 |
| 现有 watermark 仅四表计数，且在账本 snapshot 之前读取 | 保留旧字段兼容，新增每个集合/账本的采集起止、实际快照 schema/owner、文件和关联覆盖；恢复以快照实际读取为准。在线复制的时间差如实展示，不能把不同时点的 count 当原子水位。[现有 watermarks](../../packages/24pa/src/repo/maintenance.ts#L8) |
| verify 无内容兼容性/引用检查 | 保留“清单摘要匹配”这个事实，另外记录 schema/宿主格式兼容、账本实际身份、记忆可解析、Skill 包完整、资料/会话/附件关联检查。未检查不是通过；清单缺失/损坏/错身份不报完整。缺可选附件目录只有在不存在必需引用时才成立。 |
| 无隔离恢复准备 | 本地明确请求 `prepare/check`：目标须空目录、位于现场和备份源之外，拒绝 symlink/非空覆盖。只复制副本/导入新临时账本、检查原生 Session；保存逐项事实。PG 只接受明确的隔离目标或引导用户提供独立恢复环境，不能沿用生产 DSN。 |
| 无旧备份执行准入 | 隔离副本带明确恢复阻断；不装载或不启用调度/模型/入站/Outbox。列出现存运行、计划、pending/sending/unknown 投递、未知外部操作、已知远端对象及原渠道/身份/容器。核对保持原记录，不能把未知标成功、换渠道或创建新对象试探。实际恢复到现场前必须完成这些步骤，普通重启流程不是替代。 |
| 面板只有静态说明 | 只读列表/详情显示三类状态、范围/时间/版本、实际目标和未完成步骤；区分空/错误/离线缓存。创建、校验、准备恢复经本地维护会话或与其一致的显式动作，带 workspaceBinding/请求 ID；点击查阅不启动模型、导出或实际恢复。 |

建议代码归属：`backup.ts` 保留集合/清单职责；新恢复准备模块负责隔离、内容检查与步骤证据；独立 `repo/backup.ts` 负责记录；runtime/panel/client 仅接线。不改写双库备份引擎或 M06 领域算法。根 M02 使用迁移 27、M05 使用 29，本模块若持久化新增表使用 31，实施前再次确认共享迁移顺序。

创建成功是“备份产物形成”，校验成功是“指定检查通过”，演练成功是“指定隔离副本完成约定检查”。三者不能互相推出。当前备份所含账本快照不可能包含其创建完成后才写入的成功记录；manifest 摘要是产物关联依据，恢复到旧账本后可显式导入该备份的检查记录，不能伪造一条旧快照内不存在的完成事实。

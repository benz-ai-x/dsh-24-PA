# F07 多页笔记与集中复核：实现前研究记录

日期：2026-10-06。范围：P30/#30、P33/#31。F06 结论（图片准入、指纹、审核令牌）见 [F06 研究](F06-手写审核实现研究.md)；本文记录 F07 新核对的一手事实与落地契约。

## 一手核对结论

1. **单请求图片上限**：llm-deepseek `DEFAULT_MAX_IMAGES_PER_REQUEST = 600`（`packages/llm/llm-deepseek/src/request-pricing.ts:22`，可配 `maxImagesPerRequest`）。24PA 笔记页数上限 50（F06），远低于适配器上限；一次识别请求携带全部页面图片没有适配器障碍。
2. **裁片可行**：`sharp@0.35.3`（与宿主 harness 同版本，便于 store 去重）自 0.33 起纯预编译二进制分发（平台包 `@img/sharp-*` 为 optionalDependencies，无 postinstall）。本机在 `--ignore-scripts` 下 `npm install` 后 `extract()` 裁片实测成功；插件经 `dsh plugin add --ignore-scripts` 安装依赖同理（F01 起 pg/lark-sdk 依赖即走此路径）。裁片实现放运行时 `import('sharp')`，缺失时明确报错（不假装已生成裁片）。
3. **坐标变换**：模型返回归一化区域（0–1，相对原稿左上），运行时用 `sharp(original).metadata()` 取原稿固有宽高换算像素框并夹紧（≥16px、不越界）；变换记录（区域、来源页 sha、裁片 sha）随版本内容存档，区分 reliable（模型给出区域）/estimated（夹紧或放大过）/page（无区域，引用整页）。
4. **提醒语义**：F05 的 `reminder_rule/occurrence` 是面向内容的通用规则，无"版本失效即停发"绑定；审核催办单独建 `pa24.review_reminder`（绑定 note+version），派发时实时核对版本仍为 pending_review，否则整单取消；静默窗口复用 F05 `silencePolicy`（扣住不丢弃）；限频＝每日模式两次发送间隔 ≥6h、累计 3 次后自动结束（防止长期骚扰；需再次催办由本人重新发起，计数入行）。

## 设计决策（落地契约）

1. **多页识别（P30）**：移除 F06 的单页限制；一次委派识别整份笔记（≤20 页/批次，超出如实要求分批——预算边界，不用模型自报成本）。`note_submit` 扩展：`pages[]`（逐页转写，页号必须对应已保存页且不重复）、`doubts[]`（页号＋类别[数字/人名/缩写/日期/否定/勾选/不清]＋原文引文＋可选区域＋可靠度）、`diagrams[]`（页号＋说明＋可选区域；保留原图＋文字说明，不做矢量重绘）。跨页重复＝同 sha 页已被 F06 收集层拒绝；"漏页"在文档逐页转写节按实际页号呈现，缺号即缺页（不臆造）。
2. **裁片与指纹**：发布前对带区域的疑点/图示生成 PNG 裁片（`.24pa/crops/<note>/`），文档"疑点与定位"节逐条标注页码＋区域＋裁片，裁片经 `docs +media-insert` 插入；回读完整性检查升级为 图片数 ≥ 页数＋裁片数。指纹继续由 F06 的 `fingerprintOf` 扩展第三组输入（裁片 sha 列表）：页序（sha 顺序）、疑点文本（含区域坐标）、裁片内容任一变化都改变指纹；已批准旧版本不因新候选失效（沿用 F06 supersede 语义）。
3. **审核队列（P33）**：`pa24_notes queue` 与面板 `notes.queue` 列出 awaiting_review/needs_rereview/returned 的笔记（最新版本号/状态/文档链接/最近核验结果与时间/页数/在途催办）；完成审核后自动移出（版本状态推进）；"更新失败"（verify unknown）与"审核失败"（returned）分别显示。dsh 手写审核页只读＋打开飞书文档，无网页批准按钮（批准只经飞书卡片）。
4. **审核提醒（P33）**：`pa24_notes remind`（绑定当前 pending 版本；once 延迟/绝对时间，daily 每日）＋`remind_control`（snooze/pause/resume/cancel，只动提醒不动审核状态）；派发复用 Outbox＋静默扣留；版本离开 pending_review（批准/退回/stale/superseded）时单事务取消在途催办——旧版本提醒不再催审。重启后 pending 催办按账本继续。
5. **基线对比（P30 AC5）**：e2e 以同一视觉路由对单页（F06 流程）与多页（F07 流程）各识别一份样本，断言两条路径经同一版本发布/审核管线；不引入第二套模型 runtime、不做默认双模型 OCR。

## 测试边界

e2e（真实 Loader/隔离 PG/真实 lark-cli 桩/mock LLM）：三页笔记逐页转写＋区域疑点裁片落盘与入档、指纹覆盖页序/疑点坐标/裁片、队列与空队列、催办发出－批准后取消－稍后/暂停、静默扣留补发、重启恢复催办；单页与多页共用同一审核管线。真实多页中文手写样本与真实裁片定位质量：未验证，另记。

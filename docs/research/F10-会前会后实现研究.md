# F10 会议资料与纪要行动：实现前研究记录

日期：2026-10-06。范围：P26/#39、P27/#40。基线同 F09（用户 harness 检出已切 0.2.0-rc.2，按规格基线 0.2.1-alpha.1 以 `/tmp/dsh-baseline` 副本验证）。F09 已核实的原生 ScheduleService 契约与 digest 幂等骨架直接复用。

## 设计决策（落地契约）

1. **会前准备（P26）复用智能计划骨架**：`meeting_prep_enable {eventId, leadMinutes}` 在 `pa24.digest_plan` 建 kind=`meeting_prep` 的计划（schedule_spec 存 eventId/leadMinutes，原生 Schedule 一次性 `at`＝日程开始−提前量，仍只挂接入会话）。到点唤醒 Lead 委派 calendar Worker `meeting_prep_build {planId}`：
   - **发送前复查会议状态**：实时读日历投影——日程取消/不存在/改期（开始时间变化）即不发送过时准备包，输出说明并跳过（改期后由本人按新时间重设）。
   - 资料检索限定授权范围：备忘（主题/关键词匹配＋近 30 天）、相关项目任务、记忆 confirmed 事实；**没有材料如实说明**，不编造议程；输出＝议程建议＋带出处的问题清单＋资料链接，标注会议与 WorkItem。
   - 日程变化联动：F08 `notifySourceChanged('calendar', …)` 同时停止绑定该日程的 prep 计划（schedule_spec.eventId 匹配），旧准备包不再生成。
2. **会后纪要（P27）**：memo Worker `minutes_build {topic, content, eventId?}`——把本人提供的材料整理为纪要（决定、待确认问题、疑问、行动建议、未知项），经既有 memo 文档管线（创建＋回读）保存飞书纪要；候选行动（含出处引文、责任人/日期原话、未知项）存 `pa24.minutes.candidates`，**纪要生成≠行动执行**。
3. **候选行动选择/执行契约（供手写链复用）**：`minutes_adopt_actions {minutesId, indexes[]}` 只对选定且信息足够的候选执行：有 start/end → 日历时间块（staged）；否则 → 飞书任务（staged，幂等键＝minutes:索引）；重复选择返回已有对象；创建结果未知先核对（staged unknown 拒绝盲重试）；部分选择与部分失败逐项返回。执行结果回写 minutes 行并保留原文关联。
4. 边界：资料权限不足（读取失败）如实列出；生成失败后到"有用时段"恢复＝计划可重试（once 计划由本人重设；幂等键防重复）。

## 测试边界

e2e（真实 Loader/隔离 PG/lark-cli 桩/mock LLM，DSH_BIN 基线副本）：会前包端到端（含资料缺失如实、取消联动停止）；纪要生成（文档回读、候选带出处）→ 选择性采纳（只建选定项、重复幂等、未选不建、失败逐项）。真实会议语料质量与真实飞书文档并发：未验证，另记。

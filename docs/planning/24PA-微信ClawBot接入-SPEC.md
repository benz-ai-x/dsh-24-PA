## 入口、身份与权限

1. 首版每工作区一位主人、一个活跃微信绑定，飞书和本地入口可以继续并存。微信入口配置独立于现有飞书业务配置；不把微信用户 ID 写进 `ownerOpenId`，不通过把 `mode` 改成微信来排斥原业务来源。
2. 主人在电脑端已授权工作区发起绑定，扫码结果作为候选身份展示，再明确启用到该工作区。昵称、任意第一条消息或模型推断不能证明主人身份。登录失败或取消不替换原本地绑定；若平台已使原凭据失效，须如实提示重新登录，不能承诺外部授权可回滚。
3. 绑定固定持久工作区身份、微信机器人账号、主人微信身份、接入会话和持久绑定代次。账号更换、注销后重新绑定创建新代次；正常重启、重载或确认同一身份的凭据续期保留原代次、会话、游标和结果归属。不得复用每次激活都会变化的 `workspaceBinding` 充当持久代次；它继续用于界面草稿并发校验。
4. 每个微信绑定使用专属24私助远程接入会话，保留自己的历史，Worker 挂在实际发起父会话。会话登记与角色识别必须在首次工具挂载/模型回合之前生效，并在收件派发和每次业务调用复核。退休会话的远程身份仍须持久可识别，不能因解绑删除映射而落入 `local-robot`。
5. 微信允许现有远程业务交办、进度、续办及有效业务记忆检索，继续受 `enabledWorkers`、业务 Skill 放行面、来源权限和逐步授权约束。F55、媒体及其他未交付能力在准入时明确拒绝。配置/密钥/长期记忆维护、Shell、任意文件、听记 MCP、外部编程代理和本地任务型 Skill 不随微信接入开放；不得借跨入口查询、续办或控制本地 Skill 绕过此边界。
6. 首版只接收已绑定主人的私聊文字；其他发送者、群事件、旧绑定或错误工作区均拒绝业务准入并留必要证据。不支持的图片、语音等明确说明，不伪造识别结果。
7. 工作结果固定到创建时的原入口及身份。主人跨入口查看的是经过远程权限筛选的业务摘要、进度及可披露结果，不直接返回完整 `job.inspect`/运行档案中的本地 Skill 包、工具调用、提示和配置。不因另一个入口查看、补充或新默认设置改变已有结果目标；本地任务型 Skill 的维护继续在电脑端办理。

## 电脑端绑定与维护

- 在现有「接入与设置」增加微信接入卡/详情，不改变一级导航；原 16 卡的功能与显隐偏好保留，新增微信卡是本次明确增量，原卡片数量不作为扩展上限。提供连接微信、二维码/必要验证码、取消、刷新失效二维码、启停、重新登录和解绑。二维码只在主人主动连接时申请，普通浏览不触发外部登录或发送。
- 展示账号、是否启用、连接状况、最近真实收信/发送及必要下一步；未绑定、扫码中、待确认、连接中、已停止、需重新登录、错误和未验证分别表示。“已登录”不等于“收发已验证”。
- 账号启用、切换、重绑和解绑沿用 F52 的只读预览及执行时版本复核方式，新增微信账号/代次和受影响收件、工作、投递的实际统计。现有 F52 只识别飞书等配置，不能直接覆盖微信。阻断按受影响归属判定，不无条件把无关飞书待审或投递算成微信阻断。停用停止新轮询、新准入和新发送；尚未派发的收件也须复核，不自动提交。已授权在途业务可结算到原账本。
- 存在旧身份未结收件、执行、待发或未知结果时，拒绝直接切换/解绑并指向处理。明确未发送的内容可由主人在电脑端放弃该次投递并保留结果及记录，以免永久阻塞解绑；unknown 必须先核对，不能用放弃操作抹除可能已经发送的事实。未结束执行沿既有停止与回执流程结清。
- 发出的 HTTP 请求不能因停用而声称已撤回；返回结果仍归原身份。重启或配置应用失败不得同时启用新旧两个消费者；状态如实显示“已保存未生效”。
- `bot_token`、`context_token`、二维码授权和验证码按凭据处理；专门保存且不回显，不进入 AGENTS.md、模型提示、普通日志、诊断导出或业务备份。传输层先提取凭据，再持久化清洁的消息信封，不能把含 token 的原始平台 JSON 写入 Inbox 后寄希望于备份文件名过滤。扩展现有密钥字段、嵌套/字符串脱敏与导出检查；回复 token 按账号/主人/会话/代次隔离。
- 电脑端执行中英文、明暗主题、键盘、焦点及 1280×800、1440×900、1920×1080 验收，不新增手机网页。微信原生客户端扫码及私聊不改变本产品的电脑端界面范围。

## 收件、执行与结果回传

### 收件与游标

采用二维码登录和 iLink 长轮询，按账号与绑定代次管理游标。每批先校验消息身份，并将接纳或拒绝结果持久化，再推进对应游标；无需等待模型或 Worker 完成。游标与接收记录使用同一事务或经故障验证的先后提交关系。

去重键至少包含渠道、账号、绑定代次和可靠原消息身份，原消息标识保持精度。消息缺少可靠身份时隔离并明确记录，不能临时随机造 ID 后声称可去重。重复/重投不重复委派或写业务对象；绑定切换、停止和重启的迟到响应不能写进新身份。

复用 Inbox 接纳、宿主 Session 持久化和实际已消费消息的回合结算，并补齐重启恢复。现有 `InboxLifecycle.recover` 会将已接纳输入统一拒绝并提示重发，微信不能直接沿用：按原请求/消息身份查持久宿主事件、WorkItem 和出站关联，已完成只补账，已排队或消费的不重提交，证据不足进入待核对。宿主接纳超时或 flush 未确认时也保留原请求；不以“请重新发送”替代核对，不承诺所有中断模型回合都能无损自动续跑。

微信消费者归现有 runtime 生命周期管理；长轮询等待不占住整个工作区切换锁，轮询返回后在归属校验和短事务内落账。停用/退休通过可取消请求与代次校验阻断迟到回调，单账号不得有两个活跃消费者。只抽取必要的远程消息信封、入口绑定与结果目标，不另建一套业务执行器。

### 交办与既有业务

微信接入既有 Lead/Worker、交办查询与控制。日历和待办继续使用已登记的飞书/企微来源；明确操作范围、原平台对象和回执，业务外部操作仍有自己的幂等与未知结果规则。备忘与资料继续沿已有文档授权和审核流程，微信首版不批准资料版本。绑定微信不自动补齐业务来源授权、不切换 `mode`，体验模式不得将演示结果称为真实业务办理。

一次交办可先得到已接纳/排队的准确反馈，较长工作完成后无需新的微信来信也能尝试回传；不能在缺少依据时报告已完成。回复某事项优先使用可靠关联；首版支持明确事项编号续办，无原生消息号时不假造引用关系，歧义须定位原事项。

### 投递和回执

所有普通回复、事项结果、帮助/拒绝提示及恢复通知通过持久 Outbox，记录原账号、接收者、绑定代次及显式输入/工作/结果关联；不依赖拆分 `dedup_key` 推导关联，不把全局 `notifyOwner` 默认出口改成微信。消息引用路由按渠道、账号、代次及原生消息号隔离，有真实原生号时才登记。长文本按核验限制分段，固定分组、顺序与每段标识/状态；部分成功不重发成功段，前段 unknown 时先核对再继续，避免乱序和重复全文。

分别记录本地投递标识、客户端请求 ID、平台接纳依据、可选原生消息号及错误。需修改当前 Adapter/Outbox/恢复以 `message_id` 唯一判断成功的契约：明确接纳但无原生号也能持久结算；生成 client ID 不代表接纳，也不能填成原生号。HTTP 与业务返回码分别判断；平台接纳不等于设备送达、已读或主人验收。

明确未发送且可重试的错误有界重试；发送后超时、崩溃或响应不明进入 unknown，不自动重发。已有平台接纳证据只补本地记录。首版提供电脑端核对、处理及必要补投入口，覆盖普通回复、状态提示、Worker 结果及分段；当前 PlanResults 仅支持关联运行的投递且“已收到”要求原生号，必须扩展。核对绑定原出站、版本、主人及依据，无原生号可记录本人确认依据而不伪造号；补投不重新运行 Worker。

平台回复上下文是否可用须由 WX-R01 记录。结果目标固定，发送前可解析该账号/主人/会话/代次内最新有效 token 引用，不能把旧 token 永久冻结进 Outbox，也不能跨绑定借 token。每段发送前及异步准备后复核归属；上下文过期/缺失/被拒时保留结果并说明受限，不静默改投，不无限等待，也不把尝试算成功。当前无法保证任意延迟或任意时刻发送。

### 存储与恢复闭合

SQLite/PostgreSQL 共用迁移契约并保留旧飞书/企微数据。持久绑定、退休身份、游标、清洁收件、结果目标、接纳证据、分段和核对记录须进入联合备份/恢复的完整性检查；即使微信接入会话尚未创建 WorkItem，也纳入必要宿主会话导出。凭据单独恢复。恢复目标实例在明确核对身份与切换前不启动微信消费/发送，不能把恢复演练当作生产接管；恢复不得盲目重发。

## F54：微信管理周期服务

复用 F50 的 PlanConversation、TaskPlanService、旧计划兼容路径和可信主人输入机制。首版新建限定晨报、晚间复盘、周回顾、单次汇报；既有管理限定这些常用业务计划的查询、改时间/时区（依规则适用）、周几/单次时点、暂停/恢复及语音选择。仅纳入既有远程业务授权可管理的计划，不因 `list` 返回某行或 `control` 接受 ID 就放行任意本地任务型 Skill。会前准备、等待跟进、任意复杂规则编辑、迁移、删除与面板“立即运行”不借本次接入开放。新晨报沿智能规划默认并明示模型使用，明确固定模板选择得到保留。

这里对本地 Skill 的限制针对任意手工任务和本地工具维护；F50 已放行的智能晨报仍是允许的业务计划，沿既有计划/来源/动作授权执行，不因此开放任意 Skill 选择或执行。

最近结果查询须新增受限的业务结果投影：名称/计划 ID、状态、最近运行时间、可披露结果及投递状态；没有结果或来源不可读时明确说明。当前 `PlanConversation.list` 只有 recentRun 元信息，不能冒充已有结果正文接口，也不直接把完整计划授权行或本地运行档案返回微信。

创建、改时、恢复和语音调整展示时间/时区、Skill/执行方式、启停选择、投递渠道与接收者、必要权限，再采用真实后续微信原文确认。首次委派、可靠原生引用和明确事项编号续办都须保留真实文本/来源/身份，并以宿主实际消费和 Worker 采用为依据，不能用模型摘要代替。确认绑定工作区、主人及微信绑定代次、原父会话、具体预览和版本；当前 15 分钟预览策略继续使用。模型 confirm 参数、旧消息、另一个账号/入口、重启前预览或变化后的版本均不直接写入。

暂停/停止沿 F50 已采用的主人原文要求，不增加无意义确认；对计划的“停止”表示暂停未来触发及未启动排队，不代表停止正在执行的运行。用户要求中止当前运行时另定位原工作并沿既有授权/停止流程办理；没有覆盖该运行的远程授权时转电脑端处理。多份同类/同名计划先定位原对象；重复确认不重复创建或启用，保存后启用失败保留原暂停草稿。

管理计划不会改变其后台执行会话归属、通知配置或既有授权快照。确认凭证使用真实微信发起父会话，计划执行 context 继续用原业务执行会话，两者不可混用。旧计划无需迁移仍可常用管理；旧计划没有固定授权快照时保留其既有通知解析语义，不能声称所有旧计划都已有冻结接收者。原 Skill、语音、历史、授权阻断保持；调整仍向飞书发送语音的计划不意味着实现微信语音。F54 不新增微信通知选项。

## F55：后续周期结果通知

本项以 WX-R01 对目标通知场景的真实可用证据为进入实施的条件；未验证或不可用时保留待研究状态，不能仅因字段存在而上架微信通知选项。不得写死未经依据的“24 小时/10 条”等窗口或额度。

满足条件后，允许主人为明确选定的计划预览并确认微信作为结果目标；保存固定账号、主人、绑定代次和权限依据，默认通知变化不改绑旧计划，不迁移旧执行会话。在途运行继续使用原快照。首版周期微信通知只发文本；若原计划开启语音，预览须明确请求主人选择文本或保留原渠道，不静默关闭 voice。原飞书/企微和飞书语音不退役。

复用 PlanResults 的先保存结果、投递单独记录、免打扰、有效期、错误模式和核对/补投。账号/授权变化、token 不可用或超期时如实受限/过期，结果可从电脑端查看；发送失败不得重新办理已完成的业务。若平台允许的发送条件不足以满足所选计划，应在启用前说明限制并拒绝不可兑现的配置。

## WX-R01 检查点与实施门槛（纳入 #279）

在 #279 内记录脱敏证据和结论，不另设研究工单；保留验证门槛，合并工单不等于验证通过：

- **基础结论 A**：目标版本可用二维码授权；入站真实身份、稳定消息身份和游标行为明确；普通回复与一个实际延迟异步结果可核验；成功/失败/未知回执的判定有依据。未通过 A，F53 不进入正式实现；可先完成独立隔离探针。
- **通知结论 B**：列明测试账号/版本、观察时间、测试间隔、有无新入站/context token、响应与用户可见结果。只报告实测条件；不能从少量成功推导无限有效。可判为可用、有条件可用、不可用或未验证。
- A 不通过或因缺账号未验证，#279 保留未完成并记录阻点；可继续隔离探针和离线契约准备，不能宣称正式集成可用或真实账号已验收。A 通过后完成 F53/F54 的实施与验收才能关闭 #279。B 未验证不妨碍首版在 A 范围内完成，但 #281 继续后置；仅 B 的可用条件覆盖拟交付场景时才放行 F55。原 #278 的归并关闭不是 A/B 通过证据。

既有 `client_id` 不作为服务端去重保证；没有可查询原生回执时采用 unknown 与人工核对，不为了让研究通过而编造已读或必达结论。

## 不在本次实施范围

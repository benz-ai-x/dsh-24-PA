### 终端与证据边界

- 本产品的界面设计、开发与验收只考虑电脑端，不考虑手机端。T20 覆盖 **1280×800、1440×900、1920×1080** 电脑视口及明暗主题、键盘、焦点和 reduced-motion，不设置手机断点、390px 或触控验收。飞书／企微原生 App 的既有平台能力边界不变。
- 五卡工单指定的技术基线为 dsh `0.2.1-rc.3`＋24PA `0.2.1-rc.3.1`。正式实现沿用现有 dsh 客户端、RPC、配置和账本契约，具体缺口与交付任务以各票正文为准。
- 原型只约束布局、信息优先级、SVG 角色、交互和状态构图。示例对象、计数、时间、短哈希、授权文案及内存中的即时切换不构成真实能力；正式验收必须读取同一工作区的真实配置、快照、账本和外部对象，不能把静态 HTML 或示例数据当生产组件与完成证据。

### Skill 完整包目录树与只读文件预览（#240）

- 内置原件、当前工作区获胜来源、受管当前／历史版本均提供对应完整包的文件清单；受管删除后的历史只读版本仍可查。目录树由全部打包文件的包相对路径派生，单文件包与目录包都可查看，不虚构原始目录，也不额外承诺空目录。
- 清单与文件正文必须来自同一不可变版本或同一捕获快照，展示真实文件大小、内容 SHA-256 短显及快照信息；服务端完整性比较使用完整哈希。切换 Skill、版本、文件或工作区时，旧清单、旧正文和迟到响应不得串入新快照。
- 文本按严格 UTF-8 与 NUL 检测提供只读预览，空文件、二进制、解码失败和超限截断分别呈现；完整内容仍经既有 ZIP 下载取得。界面与 API 只暴露包相对路径，不开放任意目录浏览或服务器绝对路径。
- 打开目录、选择文件、预览及复制路径不执行脚本、不安装依赖、不启动模型，不发布、启用或写业务对象。原型中的多文件目录、版本号和短哈希只是演示，不能据此给内置原件虚构资源或持久版本。

### 待办五档持久默认角色（#243）

- 每份待办来源的持久默认角色支持 `all`（全部授权可见）、`responsible`（我负责的）、`following`（我关注的）、`assigned`（我交办的）、`creator`（我创建的）。新个人来源仍默认 `all`，新公司／项目来源仍默认 `responsible`；已有合法配置值原样保留。
- 默认查询使用本次明确角色，未指定时使用该来源已生效的默认角色，不把非 `responsible` 值回退成 `all`。明确角色只替代本次查询的默认角色条件，其他筛选与授权不变，随后查询仍按来源默认值。
- 负责人、创建者、关注人和实际分派关系分别核实，角色证据不全仍标记范围不完整。修改默认角色不扩大授权，不改绑既有对象或计划，也不使来源范围证据失效。
- 配置抽屉先保存草稿；只有配置校验、保存、重载完成并重新读取生效来源后，才更新默认写入徽章、默认角色和后续对话草稿。保存冲突、写后未生效、失权或失败来源如实显示，不自动换目标或冒充已核验。

## 工作对象与权限

| 对象 | 职责 |
|---|---|
| Skill | 保存指令、参数、资源、运行限制和完成标准 |
| 定时任务 | 保存时间、Skill、参数、启停及投递选择，每次触发关联运行 |
| 日历／待办来源 | 登记个人、公司或项目的查询和写入资源 |
| 日程／待办 | 原平台上的时间安排／业务工作；以平台状态为准 |
| 助理交办（WorkItem） | 主人要求助理完成的目标，保留来源、完成标准与固定回传位置 |
| 运行记录 | 当次输入、版本、动作和结果；自动尝试与投递作为子记录 |
| 提醒／审核凭证 | 前者表达提醒方式；后者证明主人批准了具体内容版本 |

- **归属与权限：**一工作区一位主人、唯一助理预设；Worker 归实际父会话，结果回发起入口，浏览页面不改变归属。WorkItem 的身份和历史不变，不转换成平台待办。
- **本地与后台：**有权限的本地顶层会话可手工使用脚本、文件、网页和听记；飞书与 Worker 不继承本地扩展权限。后台仅用获准业务工具、只读网页及当前 Skill 包快照内的静态资源，不获得任意文件、Shell、听记、安装、配置维护或记忆整理能力。
- **授权：**Skill 只能收紧权限；引入新工具、资源或操作范围须重新确认，既有授权不反复询问。接入向导在本地运行，persona 不作为普通定时任务。
- **来源通则：**日历与待办来源均登记平台、资源标识、名称、用途、实际授权范围、默认筛选、读写状态和核验时间。写入顺序为“明确来源 → 已配置的公司／项目对应关系 → 默认来源”，一次只选一个；歧义、未登记或不可写时补问，不擅自换目标。登记不扩大授权，移除不删除远端对象或历史。
- **查询与变更：**查询覆盖全部已登记来源，包含非助理创建的对象；默认写入目标不限制查询。显示实际范围、筛选口径和核验时间；部分失败、无权、范围不全、旧缓存与真实空结果分开，不以局部结果冒充完整总览。面板普通查看、搜索和刷新不启动模型、业务执行、远端写入或定时任务。
- **结果证据：**回执说明实际动作、来源、影响范围、可核实状态和原对象入口。外部结果未知先核对，不盲重试；已知成功的动作不重做，只补缺失关联或投递。平台接受、设备送达、已读、业务完成和主人验收分别表述，不因失败自动换渠道或收件人。
- **数据：**默认 SQLite，可显式选 PostgreSQL；JSON 是记忆唯一可编辑权威。工作区 AGENTS.md 保存规则与非秘密配置，凭据沿用专门机制，不进入提示、普通导出或备份。

## Skill 管理规则

### 创建与导入

- 内置、个人、导入 Skill 统一管理，区分可运行、缺依赖、未验证、禁用等状态。
- 快速创建支持自然语言草稿、编辑、试运行和保存，也保留文件入口；参数定义类型、必填校验、预期结果和完成标准。草稿随时保存，启用前检查结构、参数、依赖和授权；试运行推荐但不强制，未试运行须标注。
- 上传 Markdown 或 ZIP，支持 SKILL.md、scripts、references、assets；下载完整包和依赖说明，排除凭据、计划参数及运行历史。
- 同名默认副本，明确更新才生成版本并展示影响；重命名不破坏绑定。内置原件保留，可复制为个人版本后编辑换绑；确定性模板改参数，自由改行为生成标明成本与灵活性差异的智能副本。
- URL 安装和 Skill 市场不进入本轮。persona 可查看、下载、复制，职责替换不作为普通运行能力。

### 运行与版本

- 预览与真实执行分开；无法无副作用预览时说明。试运行和正式运行均记录实际动作，不以示例替代。
- 更新展示受影响计划；兼容且权限不变时用于后续运行，在途输入、资源、版本固定。内置升级检查兼容性和新增权限；缺依赖或授权的计划暂停，个人副本独立。
- 可查版本、回退。禁用阻止新运行并暂停相关计划，当前运行继续，停止须另行发起；重新启用不自动恢复计划。
- 删除被有效计划引用的 Skill 前先换绑或删除计划，保留历史快照和结果。重跑可选原快照或当前配置，均产生新运行并重验权限、依赖；原环境不可恢复时说明。

## 定时任务与运行规则

### 配置与列表

- 保存名称、Skill、参数、时间、时区、运行限制、结果与投递、启停及授权依据。同一 Skill 可有多计划；空白、预设、复制共用表单，可存为暂停或校验启用。复制也须确认本计划工具、资源和操作范围。
- 启用或显式重配时，将写入目标绑定到具体平台、身份和资源。全局默认、来源登记或项目映射变化须展示受影响计划；原目标仍登记且有权时继续使用，不自动改绑。修改计划仅影响后续运行，在途快照不变。
- 每步仍检查当前登记、计划授权和实际权限。资源移除或权限撤销阻断相关新运行与尚未发出的动作，提供修复入口；旧快照不绕过撤销，已发出动作继续核对。
- 支持一次性、每天、周一至周五、每周、每月、间隔和高级规则，保存前预览未来触发。周一至周五不等于法定工作日，不存在的月日期跳过；时区初取工作区，后续不随全局修改。
- 既有计划迁移保留参数、时间、启停、投递和原关联，避免重复触发。列表可按关键词、状态、Skill 筛选，显示时间规则、下次运行与最近执行、投递；空记录与读取失败分开。

### 暂停与删除

| 操作 | 结果 |
|---|---|
| 暂停计划 | 阻止未来和未启动的排队运行；当前继续，停止须另发指令 |
| 恢复计划 | 恢复未来触发，不补主动暂停期间的次数 |
| 暂停后立即运行 | 手动暂停可单次运行，结束仍暂停；依赖、Skill、授权或人工阻断须先解决 |
| 停止运行 | 分别显示请求与实际结果，保留已完成动作和未知结果，不改变未来计划 |
| 删除计划 | 进入回收并留历史；有运行时选择等待结束或停止后删除 |
| 还原计划 | 恢复为暂停，重验配置、依赖与授权后启用 |

启停选择与阻断原因分别保存，修复只解除对应原因，不清除其他暂停、禁用或失败状态。

### 并发与故障

- 同一计划不重叠，重叠触发记录跳过；全局并发有上限。停机漏触发只考虑补最近一次，默认有效期为触发后 1 小时；过期跳过，一次性计划进入需处理。
- 默认执行时限 **15 分钟**，可配置；模型和工具调用计入，排队、等待主人或预算放行不计入。累计执行时间与等待状态持久保存，恢复及内部重试不重置时限；达到时限仍未完成则超时，保留动作和未知结果。
- 缺信息、授权或预算时保存上下文、告知所需处理并阻止计划后续重叠触发，等待不计最终失败。解除全部运行阻断并重验权限、依赖、可执行状态后，**未结束的运行沿原记录继续**；已停止、超时或结束的运行不被迟到回复复活，显式接续才新增运行。
- 明确未执行的暂时错误最多自动重试 **3 次**，归同一运行。未知动作必须先核对，新触发、重跑或接续不能换操作标识绕过；迟到回执修复原记录。
- 缺权限或依赖暂停相关计划；连续 **3 次最终运行失败**才按连续失败暂停并通知，不计内部重试。执行成功但投递失败只补投。

### 结果与投递

- 先保存结果；可仅保存、投飞书或企微，接收者限主人。计划初取默认通知设置，之后用自身保存值；飞书可开启语音并附完整文本，二者分别记录，企微用文本。
- 默认每次完成通知，可选仅变化或仅异常。仅变化以最近一次成功结果为基准、首次通知；比较对象和规则须可靠明确。
- 普通投递遵守免打扰，主人明确预约的投递时刻可覆盖。普通结果默认在触发后 **1 小时**内投递，过期留存不推送；失败或需人工处理的通知在免打扰后送达，不因普通结果过期丢弃，不随内部重试重复通知。
- 计划、Skill 版本、摘要和正文／链接／文件结果保留至主人清理；详细诊断默认 **90 天**，可配置。

### 执行与配置验收场景

| 场景 | 必须成立 |
|---|---|
| 默认或项目映射 A 改 B | 显示受影响计划；既有计划仍用已登记、有权的 A，显式重配确认后才用 B |
| 移除 A 或撤销权限 | 阻断相关新运行和未发出动作；已发出动作核对，旧快照不绕过权限 |
| 多项阻断 | 修复资源只解除资源问题；预算放行可恢复仍可执行的原运行，主人对未来触发的暂停保持 |
| 执行 2 分钟、等待 20 分钟 | 同一运行剩余 13 分钟，重启亦然；不新增运行或失败计数，实际执行累计达 15 分钟才超时 |
| 等待期间停止 | 迟到补充或放行不复活；明确接续新增运行、关联原交办，不重做完成步骤 |
| 写入未知后停止，再次触发 | 先核对原动作，不借新运行重复写入；迟到成功回执只修复记录或补投 |
| 通知过期，下次结果相同 | “仅变化”继续静默，基准仍为上次成功执行结果，而非送达结果 |

## 待办与多来源管理

### 定位与来源登记

“待办”管理原平台业务工作，本地与飞书均可办理。来源可以是平台清单或授权可访问范围，不假设飞书与企微结构相同，登记和路由遵循来源通则。

- 个人来源默认全部授权可见待办；公司和项目默认“我负责的”，可改为全部。明确查询“我关注的”“我交办的”等角色时，**替代默认角色条件**，其他明确筛选继续生效，不扩大授权或永久改设置。
- 负责人、创建者、关注人、实际分派关系分别核实；不能互相替代。来源、默认筛选、公司／项目映射和默认写入目标由参数配置维护；计划影响及升级按相应章节办理。

### 对话办理与意图区分

- “记个待办”只记录，“帮我完成”建立助理交办；明确两者都要才关联执行，意图影响操作且不明时补问。创建成功不代表业务完成。
- 提取内容、来源、负责人和截止时间；明确为本人记录却未说负责人时，**默认主人负责**，明确指定他人则依指令。已知无法落实时先说明并提供身份、授权或负责人处理入口，解决前不换责任关系创建；部分创建沿原对象处理。
- 未给截止时间保持未设置；相对日期按工作区时区解释，回执写明具体日期或时间。截止、投入时间、提醒分开，不因截止自动建日程或计划。
- 缺必要内容、对象或人物有歧义时保留输入补问，信息授权充分则执行。分派及通知他人须明确指令。
- 完成、延期、修改、取消都定位原待办并遵守平台语义；多候选先定位，删除不充当完成。合并对象操作先确定来源和影响，仅存在不同影响且指令不明时补问，不为绕过权限换来源。回执包含实际负责人、截止和业务状态。

### 聚合查询与卡片展示

- 在全部登记来源的授权边界内，按本次角色或默认角色，再结合来源、项目、状态、截止等条件筛选，注明口径。
- “今天还有哪些事没完成”先汇总逾期、今日到期，再呈现所需未完成项；无截止时间单列，时区用工作区设置。
- 计数来自完整筛选结果，支持分页、核验和原对象入口。仅确认同一待办才合并，保留各来源关联、角色与权限，不按同名合并。
- 角色无法核实、查询失败或覆盖不全须说明，不报“全部完成”。关联交办可跳转运行记录，业务状态与助理进度分开。

### 待办验收场景

| 场景 | 必须成立 |
|---|---|
| 本地或飞书创建“周五前提交 A 项目方案” | 唯一来源，默认主人负责；原入口回执，“我的未完成待办”可查，负责人和截止与平台一致 |
| 不能设置负责人／明确指定他人 | 前者先说明并处理，不把关注或未指派报成本人负责，部分创建不重建；后者不被默认本人覆盖 |
| 无截止或必要信息缺失 | 不猜期限；保留已知信息补问，不擅换来源 |
| 多来源聚合 | 含飞书、企微及非助理创建对象；个人默认全部，共享来源默认本人负责，角色依据真实关系 |
| 明确角色覆盖默认 | 项目来源中 A 由主人负责且不在其关注／交办集合中，B 由同事负责但主人关注且交办；默认查 A，关注／交办查 B，其他条件与授权保留，随后默认查询仍查 A |
| 完成或延期 | 更新原平台状态或截止，多候选先定位，不创建重复对象 |
| 合并待办变更 | 原对象、角色、权限可追溯；来源与影响明确后仅做对应动作 |
| 部分查询失败 | 保留可用结果并说明缺失范围；失败、缓存和真实空结果分开 |
| 记录与执行 | 只记录不启动业务；交办可补充、停止、接续、验收，状态与待办分开 |

## 运行记录与助理交办

### 助理交办详情

- 交办保存原请求、目标、完成标准、固定来源及关联对象；独立交付物分别立项并可关联。信息授权充分可直接开始，详情串联全部运行。
- 卡片独立列出进行中、待我处理和异常交办；交办与运行分别计数，按全部数据统计，提供关键词、状态、来源和历史分页。待处理及未解决异常跨日期保留。
- 展示真实阶段、已完成内容和下一步；步骤总数可靠才显示百分比。执行、等待主人、等待外部结果分开，说明需要什么以及如何继续。
- 补充绑定原交办，区分收到与采用；下一可控步骤应用，错过执行点说明影响。停止不撤销既有动作或关联待办；完成以目标和证据判断。
- 需验收的交付物可接受或退回，普通明确操作不额外验收；部分完成列未完成项。结果含摘要、动作、产物、问题和接续建议。
- 未结束运行解除等待后恢复原记录；结束后显式接续新增运行、保留原交办；新目标建关联交办，仅带所选上下文。完成步骤不重做，未知先核对，旧记录和未来计划不随接续改写；建议不自动成为新交办。

### 运行档案与查询

- 一次运行一条主记录，内嵌动作、自动尝试和投递；标明手工、计划、试运行、重跑、接续来源。预览单列；跳过、过期、拒绝有原因但不计执行，普通聊天、心跳和主动暂停期间未触发时点不造记录。
- 首页统计近 **24 小时**运行、执行失败、投递失败，未执行事件单列；未解决异常跨日保留。默认看近 **7 天**，支持 30 天、自定义时间、标题／摘要／标识及来源、交办、计划、Skill／版本、执行／投递状态筛选，准确计数分页，跨卡保留筛选。
- 保存触发及实际时间、输入与资源快照、版本、动作回执、完成依据、结果错误、投递目标和后续关联；排队、执行、等待分别统计，显示已用时限、剩余时间及原因。
- 补投、重跑、接续和核对分开；后续解决留关联，不改旧失败事实、不把未知变成功或自动恢复计划。旧数据缺字段如实显示。
- 可导出筛选结果、单次结果及预览后的脱敏诊断；删除计划或 Skill 不删历史。

## 日程与多日历管理

### 定位与日历登记

“日程”支持本地或飞书对话办理时间安排，并汇总个人、公司、多个项目组日历。日程由原平台保存、提醒由原生 App 承担；定时任务负责到时运行 Skill。

个人日历默认全部授权可见日程；公司、项目默认主人参与或组织的日程，可逐份改为全部。参与关系不明须说明范围不完整。登记、映射、默认日历及会议时长在参数配置维护，遵循来源通则、计划绑定与旧配置迁移规则。

### 对话创建与会议占位

- 提取日期、时间、主题和明确给出的参会人，按来源通则选择唯一日历；相对时间按工作区时区解释，影响执行的歧义先补问，回执写明日期、起止时间、时区。
- “明天上午9点帮我安排一个会议”：缺主题用“会议”；未给结束时间也无时长时，采用主人预设并在回执说明，未设则先补问。占位不猜参会人，邀请按明确指令，人物有歧义先核实；必要信息齐备直接办理。
- 成功须有实际对象依据。改期、取消仍定位原日历对象，换默认不搬旧日程；失败与未知按通则处理。

### 多日历聚合与卡片展示

- “下午我的日程怎样”：确定日期、时段、时区，查询全部登记日历，按各自范围筛选，再按时间汇总起止、主题、来源与冲突。
- 仅确认同一日程才合并，保留各来源原对象、角色及权限，不按同标题合并；冲突提示不自动调整安排。
- 今日、下一场和详情支持日期、时段、日历筛选及核验，提供带上下文的创建、改期、取消入口。查询不全或仅有旧缓存须标明，不能断言“没有日程”或“全部空闲”。

### 原生提醒与后续变更

- 时钟型提醒写入原生日历；条件判断、持续跟进用智能 Skill，通用事件订阅不默认提供。既有助理创建、明确接管或迁入的提醒保留关联，查询可见不等于获准修改。
- 合并日程变更须确定唯一操作来源和影响；个人安排与整场会议等效果不同且指令未明确时补问，不为写入方便换来源，回执说明实际影响。取消、退出、删除等语义先验证。
- 单独提醒显示实际提醒时刻，会议提醒显示开始时间与提前量；只开放已核实的重复和变更能力，不静默换引擎。重复提醒区分本次、以后、全系列，不支持的引导原生处理。
- 独立提醒取消可删除对应日程；业务会议“取消提醒”只移除提醒，不删会议。再次提醒建关联新提醒。
- 日程内提醒跟随改期；待办截止生成的独立提醒保留原依据，来源变化标为需处理并重新确认，不承诺跨对象自动同步。
- 平台状态为准，缓存带核验时间，操作后核验、冲突显示差异；查询失败不认定取消。迁移先盘点时钟型与条件型，验证新路径再切换，防止双重投递。

### 日程验收场景

| 场景 | 必须成立 |
|---|---|
| 两入口创建占位会议 | 唯一日历，缺主题用“会议”，采用已设时长、不猜参会人；原入口列明具体时间、日历、默认值 |
| 缺时长、目标或写权限 | 保留输入补问，必要条件齐备前不创建、不换日历 |
| 指定公司或项目 | 明确日历优先，其次映射，最后默认；无跨平台重复创建 |
| 多日历查询 | 覆盖全部登记项及非助理创建日程；按来源范围汇总冲突，共享日历切为全部后包含非本人参与对象 |
| 查询不完整 | 显示失败日历、无法核实的参与关系及数据时间；与真实空结果分开 |
| 合并日程取消 | 保留来源、角色、权限；不同影响且指令不明时不写入，明确后只做对应动作，不把个人退出报成整场取消 |
| 原生提醒与变更 | 时刻时区准确；取消提醒不删会议；原生编辑可核验，助理离线仍提醒；重复与未知操作防重 |

## 手写审核与行动授权

### 内容与版本

- 首页按笔记统计待审、退回、需重审、核验异常，历史批准不能掩盖当前未审。原稿、识别副本、转写、草稿和冻结待审版本分开，保存文件、页序与来源。
- 桌面对照、窄屏切换；标清 AI 推断和疑点来源页／可靠区域，不把坐标或模型自信当准确率。重点核对人名、数字、日期、否定、勾选；相对日期留解释依据，不确定项可待确认。
- 保存草稿与发布版本分开，发布展示正文、原稿页序、疑点及候选行动差异；重新识别不覆盖主人修订。历史入口读原快照；影响内容或行动的标题、文字、图片、顺序等变化需重审，纯状态同步不造假重审。

### 审核与执行

- 主人在飞书批准具体版本，面板提供查看、编辑、差异、核验、前往审核和重发入口；重发不重识别或生成内容。
- 批准、作为已审知识使用、执行行动前核验版本和主体；旧卡、过期卡、变更内容或错主体不能批准当前内容。
- 候选行动逐项列来源、动作、参数，可补充、选用或忽略。内容批准后仍需明确授权所选行动与最终参数，记录主人、版本和授权；改源导致版本变化须重审，缺字段只阻断相应行动。
- 行动跨版本、排序保持稳定关联，旧授权不扩展到新内容；外部对象更新先提建议，删文字不删对象。发布、通知、决定保存、状态同步和执行分别记录；已审但同步失败、行动失败分别呈现。
- 默认不催审；主人可设跟进计划，遵循当前版本、通知去重、免打扰及运行记录规则。

## 结构化记忆

- 每条是一项事实、偏好、项目背景或决定，含主题、来源、确认依据、范围、时效、修订；全文笔记、知识库、聊天及权限配置另有归属。
- 显示完整正文和真实计数，可按正文／主题／来源、类别、状态、时效、项目查询；过期、停用、冲突、回收项有入口。
- 仅主人本地发起维护，入口带标识、内容、版本；明确单项可直接执行，批量先展示变更集供选择。明确“记住”可作依据，推断和抽取仍是候选，手写批准、落库或模型判断不构成记忆确认；旧记忆缺依据如实标注。
- 普通工作按需检索有效相关记忆；未确认仅作线索，关键参数核实，过期／停用／冲突不作当前事实。当前指令优先，但不自动改长期偏好。
- 合并留来源；冲突按范围、时间、依据决定合并、分范围保留、替代、纠正或暂缓，不简单用最新覆盖。确认、有效性、来源核验分开，来源失效不等于事实必错；来源变化、不可访问、过期分别处理。
- 停用退出普通检索；回收退出业务检索；永久删除正文和可恢复版本，仅留无正文标记。原资料、会话、记录、备份各自处理，旧备份不得无条件复活已删记忆。
- 修订可追溯，撤销形成新修订并比较当前完整字段；手改 JSON 可识别，坏文件报错，不清空或用缓存冒充当前内容。

## 接入与配置

### 飞书

- 飞书承担日常交办和版本审核，本地承担本地交办及维护；接入卡管身份、能力、诊断，参数卡编辑，工作区管生效范围，健康检查聚合。
- 核验主人、固定 CLI profile 用户、应用及企业身份；不凭同名、首个发信人或其他 profile 替代。不一致阻断相关操作，证据不足待核验；局部失败只影响依赖能力。
- 接收、发送、回调、用户授权、资源读写各有证据。只读检查不发消息或造对象；实际测试另行触发，显示目标、结果、残留与清理，可选未用能力保持中性。
- 修复入口定位字段并携带脱敏诊断与配置版本，修复后重验。保存与生效分开；身份、应用、企业、profile 变更须处理交办、待发及待审影响，历史保留旧归属。
- 统计覆盖合格主人入站、平台回执及完整待发／失败／未知集合，标时间与依据，不混渠道或将近期无活动当故障。

### 企业微信

- 仅日程、待办和单向推送，不收信；日程、待办沿各自来源与角色规则跨平台查询、唯一写入，通知渠道独立，旧对象、计划、运行、待发保留原身份渠道。
- 日程基础为授权查询、创建、取消；改期、修改、复杂重复、邀请等先核实接口。待办目标含既有对象查询、创建、修改、延期、完成、取消；不以删除代替完成，不以关注人代替负责人。能力不足记录交付差异，不能把适配器缺失说成平台不支持。
- 真实提醒时刻与时区、原生日历提醒和机器人推送分别验收。推送为文本／Markdown，语音转文本；续办指向原交办及本地／飞书入口，审核仍回飞书。平台回执、本地投递标识、真实消息标识分别呈现。
- 核验主人、授权真人、机器人绑定及 CLI、分域授权、读写、推送证据；共享环境换绑定须重验，身份不符不用旧缓存执行。只读检查与真实测试分开，测试对象及残留可定位。
- 已启用能力每 **6 小时**只读巡检；同一问题持久去重，默认每天最多提醒一次，遵守免打扰；通知失败留面板告警，不改投。
- 续期核验只解除对应阻断，不清除主人暂停、人工等待或连续失败状态；未知先核对，补投不重做。

### 听记与知识库

听记仅本地按需查询、读取、整理转写与纪要，保留来源、提炼候选行动并接续审核授权。复杂整理、源资料修改须本地明确指令；不自动改源、全库同步或写记忆。保存文档或记忆分别走其确认流程。

工具挂载不等于可读，材料内指令不构成授权；听记以真实资料类型审核，不冒充手写。独立编辑器、完整播放器、音视频及全库管理不属本轮。

知识库配置节点后笔记直接保存其中；未配置才回退文档目录，已配但失败不改投。换落点不搬历史文档，审核状态不因位置改变。

### 工作区与参数

- 工作区负责目录、绑定、来源、生效版本与重载；参数统一维护业务参数、模型路由、语音、密钥及两类来源、筛选、公司／项目映射、各自默认目标和会议时长。
- 保存先校验、写源再应用；失败留输入，区分未写入与已写未生效，应用失败保留旧配置。不覆盖工作规则；并发、旧页面或迟到请求不覆盖另一工作区的新状态，存储后端切换走迁移。
- 来源、默认或映射变化展示既有计划影响，遵循具体资源绑定；新默认用于后续未指定目标的对话及新建／显式重配计划。身份、渠道、工作区切换处理在途影响，新版本重验，不沿用旧成功证据。
- 密钥只写不回显，显示是否提供及实际来源，沿用环境覆盖和工作区密钥库规则。

### 旧配置迁移与验收

可唯一识别的旧日历、待办范围、授权身份、分域渠道与默认目标形成初始登记；日历待办分别迁移，保留明确旧筛选，其余用来源默认规则。保留对象、交办、计划、运行和结果关联，确定的计划目标形成绑定，不扩大授权、不创建远端对象或重复计划。

缺身份、资源或映射的项保留已知信息并显示待核验及补齐入口；阻断相关操作，其他已验证来源可用，补齐后沿原关联恢复，不显示成空数据。

| 场景 | 必须成立 |
|---|---|
| 完整旧配置升级 | 原目标、身份、渠道、默认选择及关联保持；无新增远端日历、清单、日程、待办，无重复计划触发 |
| 旧配置缺信息 | 显示缺失项，保留原关联，相关操作受阻但不报“无日程／待办”；补齐核验后恢复，其他来源不受牵连 |
| 中断后再次迁移 | 不重复登记或建计划，不覆盖已确认的新配置；未完成项可继续，历史可追溯 |

## 健康与预算

- 健康证据带范围、时间、配置版本、影响和下一步。普通刷新读已保存诊断，全量／分项检查只读；真实消息、资源写入、模型试用、资料读取单独触发，标动作与费用。
- 未启用、未运行、未检查、未验证、部分可用、故障分开；无活动不等于故障，读取失败不报零，进程启动或配置存在不等于业务能力验证。
- 模型预算显示实际模型路由、统计时段、用量来源与覆盖范围；进程计数不冒充长期用量或供应商账单，费用未知如实显示，估算说明依据。
- 到限前预警，到限暂停新的受管模型步骤并保存进度；主人可放行一次，绑定交办／运行与范围，不长期关闭限额。沿用执行计时和恢复规则，只解除预算阻断。
- 已发请求可能继续计费，估算不承诺精确账单封顶；原生日历提醒、已有结果保存继续工作。

## 备份与恢复

- 展示存储、健康、备份范围／时间、校验及恢复状态；SQLite 与 PostgreSQL 按各自一致性要求备份。
- 覆盖账本、必要会话、原稿附件、审核快照、JSON 记忆、规则、非秘密配置、个人 Skill 包；凭据与授权缓存走专门机制，本地备份不宣称完整复制远端。
- 备份完成、校验通过、恢复演练分别确认；缺失或时间不一致须记录。恢复先查兼容性及完整性，在隔离位置验证，再处理当前运行与工作区，不无条件覆盖较新记忆或删除记录。
- 外部写入或投递前核对远端对象和旧待发，避免复活、重建、重发，凭据另恢复。本轮仅备份、校验、引导恢复，不含全自动覆盖恢复或未配置的自动周期。

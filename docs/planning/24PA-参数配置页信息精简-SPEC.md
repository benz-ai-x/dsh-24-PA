## 问题与目标

本轮目标：删除日常配置页中不帮助主人选择、操作或判断结果的信息。每项展示必须回答至少一个问题：**当前怎么设置、能不能用、需要我做什么。** 完成标准是逐项删除或改写冗余内容，不能只把原内容原样放进折叠区。

### 配套入口与状态规则

- 「工作区与配置」已有技术证据展示继续使用。「维护配置」入口同时承接环境变量引用名和 PostgreSQL 凭据；PG 凭据子区在任何当前后端下均可按需进入，密钥值与引用名都可维护。复用既有参数/密钥服务、权限和保存边界；这是本票待实现的小范围配套，不新增一级导航或另建配置系统。飞书与语音等日常密钥仍在参数页维护。
- 密钥值只写不回显，显示是否已提供及实际来源。PG DSN 留空保持、填写后替换、明确清除后删除工作区值；引用名通过参数保存链路办理。清除工作区值不会删除宿主环境变量，引用名编辑也不代表修改环境变量本身；存在环境覆盖时说明实际使用来源，不报已清除全部凭据。
- SQLite 下保存 PG 凭据只作后续准备，不启动 PG 业务账本或迁移；PostgreSQL 的活跃连接变化、后端切换仍按既有重新绑定/迁移约束办理，不能承诺保存即可热切换。因既有规则被拒绝时保留输入、解释原因与原有办理路径，不以删字段为由撤销维护能力。
- 参数页只显示语义状态；底层哈希、版本核验、工作区绑定和并发检查继续执行。证据无法读取或已过期时明确待核验，不用默认绿灯代替。
- 当环境变量覆盖表单密钥时，仍提示“当前使用环境变量，修改这里不会覆盖它”。密钥值不回显；留空、修改、清除三个动作语义保持。普通查阅不读取或导出秘密值。
- 来源、参数、密钥仍按各自原有保存边界办理；用户能分清哪些修改尚未保存。错误、未生效和修复入口不能随长说明一起删除。

### 影响提示的时机与范围

固定顺序：**修改相关字段 → 只读核对并显示影响 → 主人点击保存 → 服务端再次校验 → 写入或拒绝。** 需要主人判断的影响必须出现在触发写入前；失败后的解释只补充执行结果，不能作为首次影响说明。

| 修改类型 | 保存前说明什么 |
|---|---|
| 接入模式、主人/CLI 身份、飞书应用凭据或其引用等可能改变接入身份的项 | 当前已知的在途交办、待发/未知投递及待审限制；沿既有身份和账本归属规则，不因看过说明就允许转让主人或跳过阻断。 |
| 日历/待办来源的身份、资源、启停、读写声明、默认目标、公司/项目映射，以及渠道选择 | 明确新增请求与已有对象/计划各自如何处理；新默认不自动改绑旧对象或计划，需要重新核验的来源如实说明。 |
| PG 凭据、引用及连接准备 | 明确当前实际使用来源、仅保存准备还是受活跃连接限制，以及是否需要按原流程重新绑定；不自动迁移。 |

仅改音色、来源名称等不涉及上述边界的普通参数，不增加在途统计或额外确认；其他既有业务提示保持。影响说明复用已知配置差异、绑定和证据，不建设通用影响计算系统；缺少精确受影响数量时写明未核验，不拿全部交办/计划总数代替，也不报零。

提交时重新核验工作区、配置版本、权限和原有阻断条件；条件变化则在写入前拒绝，保留草稿并更新说明，待主人重新保存。若已写入但应用失败，仍如实反馈“已保存未生效”，不能说成未写入。只读核对不启动业务、不发送消息、不自动确认授权。

## What to build

主人发送一页手写笔记，得到原文转写、整理内容、疑点和原稿链接组成的飞书草稿。

**功能 PR：F06 · 手写笔记整理与人工审核**。本组 4 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F02 并行事项与记忆维护。

**依赖理由：** P28 提供原稿，P14 提供文档创建与回读；这是最早可演示的手写整理闭环。

**覆盖规格：** 用户故事 65, 70, 74, 75, 76；测试组 T11。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] Lead 委派手写 Worker，经 dsh 视觉路由和附件处理图像；验证请求真的包含图片，主助理与视觉模型可分别配置；能力缺失准确报错，识别 Worker 无人工批准及外部行动工具。
- [ ] 转写、摘要、AI 建议、未知项和候选行动分离，相对日期保留原话与解释依据。
- [ ] 使用可核验模板写草稿，明确尚未经人工审核；正文和资源回读完整后才发送待处理链接。
- [ ] 每个识别/写入阶段保存恢复依据与模型版本，重试不重复创建文档。
- [ ] 自动化验证单页中英混排夹具到真实文档适配与持久回执，另记录真实飞书/视觉试验边界；本票只产生候选，不把桩输出当识别质量。

## What to build

主人在 dsh 本地24私助会话归档事项或工作区会话前看到运行工作、原生计划和外部提醒，明确停止或保留后获得实际结果。

**功能 PR：F12 · 运行维护与数据恢复**。本组 3 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F11 审核笔记的行动与综合查询。

**依赖理由：** 需要 P24 的真实原生计划及其已有活动控制，以及 P18 外部提醒，才能验证两类处置差异。

**覆盖规格：** 用户故事 50, 51, 91；测试组 T06, T10。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 从本地24私助会话复用真实 Workspace/Session 归档；运行 Worker 或 Lead 上的 active Schedule 默认阻止不安全归档，不能只隐藏列表。
- [ ] 明确停止并归档时先处置相关活动和顶层 Lead 上的原生计划；child 不应存在 schedule；部分停止/删除失败回读并说明。
- [ ] PG/飞书外部提醒单独展示保留或停止选择，不与原生计划混为一谈。
- [ ] 恢复显示不自动重建已删计划，归档会话的迟到入队遵守模型门禁并对账。
- [ ] 测试空闲但有计划、同时停止/发送、部分删除失败与用户取消不复活。

## What to build

部署者选择本地目录作为 24私助工作区，用标准 dsh 装配启动插件，能看见配置、PostgreSQL 和宿主能力是否就绪。

**功能 PR：F01 · 工作区助理与随手记**。本组 5 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：无。

**依赖理由：** 无技术前置；这是部署者可独立演示的安装、选择目录与诊断流程，原型只供参考，不先抽取或改造其内存账本。

**覆盖规格：** 用户故事 2, 95, 96, 97, 98, 101, 102, 116, 117；测试组 T14, T15, T17, T20。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 复用原生工作区和目录入口绑定工作目录；首次创建规则必须经用户选择，已有 AGENTS.md 不覆盖；持久保存固定飞书接入会话及默认本地助理入口的独立绑定。
- [ ] AGENTS.md 的稳定规则由原生 instructions 加载，结构化非秘密配置经严格校验，包含固定 profile、主人、资源范围、时区、职责目录、并发和模型路由；凭据只保存引用。
- [ ] 通过真实 Loader 与预构建插件安装包启动常驻组合；显示实际 dsh/Node/CLI/SDK 兼容版本与缺失依赖，区分配置错误、PG 不通和宿主就绪。
- [ ] 直接连接 Docker PostgreSQL 的独立命名空间及受限账户，提供最小迁移与连接池配置；无 SQLite I/O，原生会话、附件和 Schedule 非 SQLite 持久化沿用宿主。
- [ ] 重载、初始化失败和停止均释放资源；第二活跃 Host 被拒绝；提供本票数据备份/恢复步骤，在隔离真实 PG 上验证启动、错误配置、清理及旧工作区保留。
- [ ] 统一中文产品/预设名24私助、英文名24PA与管理入口24私助工作区；沿用原有技术 ID 和数据标识。创建管理面板公共 SVG/主题/焦点基础，按阶段准确显示能力；完整数据页随所属功能交付。

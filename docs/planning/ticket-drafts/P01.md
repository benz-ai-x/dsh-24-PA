## What to build

部署者通过标准 dsh 装配启动 24PA，并获得可读的依赖、数据库和插件状态；可安全停止与重载。

**功能 PR：** F01 · 飞书助理与随手记（同组：P01、P02、P03、P14）。本票沿用所属功能分支及 PR；同组前置依据该分支的提交与通过的验收推进，跨组前置等待功能合并。本票在所属功能合并且验收通过后关闭。

边界：无前置；这是可独立验证的部署者流程，仓库现阶段没有必须提前重构的实现代码。

覆盖父规格用户故事：2, 95, 96, 97, 98。对应测试组：T14, T15。

通过真实 dsh 装配、会话与隔离 PostgreSQL 验证用户可见及持久结果；仅替换模型、外部网络和时钟等边界。依赖内部具体函数调用顺序的断言不作为验收。

## Acceptance criteria

- [ ] 使用真实 Loader 和测试用常驻组合启动，诊断能区分必要组件缺失、PG 不通和可服务状态。
- [ ] 直接连接现有 Docker PostgreSQL 的独立命名空间，提供本票所需最小迁移与版本检查；无 SQLite I/O。
- [ ] 保持现有会话、附件和原生域持久化，不为接入 PG 改写它们；不修改宿主 Agent loop。
- [ ] 重载、初始化失败和正常停止均释放连接及注册项；第二活跃实例被明确拒绝。
- [ ] 通过隔离真实 PG 与构建产物的启动/失败/清理测试；交付实际版本和必要配置诊断，不将健康探针等同飞书已连通。

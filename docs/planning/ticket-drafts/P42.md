## What to build

主人在24私助会话维护长期记忆，在记忆页直接阅读完整正文与来源、筛选和展开 JSON，修订可追溯且重启后仍可用。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** 需要 P41 的真实维护入口和文件权限边界；与 Worker 并行管理可独立推进。

**覆盖规格：** 用户故事 104, 105, 106, 108, 111, 114, 115, 116, 117；测试组 T17, T18, T20。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] JSON 是唯一可编辑记忆权威；文件保留 schemaVersion 与单调 revision，条目包含 id、类别、主题、内容、来源/版本或指纹、确认状态、有效期、修改人/时间/理由。
- [ ] 新增、修改、删除只接受获准本地顶层24私助会话中的本人指令，先读版本再以 expectedRevision 提交；飞书接入、所有 Worker、继承同一 preset 的 child 和后台自行入库被执行入口拒绝。
- [ ] 复用原生 fs 原子发布和版本条件，同一工作区只有一个活动写进程；过时版本、并发编辑与非法 JSON 拒绝，不清空原件或用缓存伪装成功。
- [ ] 提供可查看的修订记录；手工文件更改下次读取可见；删除后当前检索与派生索引不再返回正文，审计历史按保留策略与当前记忆分开。
- [ ] 真实本地24私助会话演示新增→读取→更正→删除→重启核验，覆盖中途退出、版本冲突、手工改动和权限拒绝；本票交付条目级维护，批量整理由后续票完成。
- [ ] 记忆页打开即加载实际 JSON，显示完整多行正文、主题/类别、已确认/待核实、来源、工作区时区下的更新时间；可展开修订依据、修改会话与原始 JSON。
- [ ] 提供关键词筛选、清空筛选、刷新、有界分页、总数/匹配数/revision，区分加载、零条、无匹配和读取错误并可重试。手工改动刷新可见，切换查询或工作区不被迟到请求覆盖。
- [ ] 所有写入继续经同一个24私助对话入口，面板不增加编辑表单或填入示例记忆；验证真实数据的正文、分页/搜索、错误恢复与明暗/窄屏/键盘可用性。

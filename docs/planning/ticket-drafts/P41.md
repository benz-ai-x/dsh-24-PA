## What to build

主人在 dsh 工作区原生维护会话修改 AGENTS.md 的规则与非秘密配置，校验通过后重载，能看到实际生效版本。

**功能 PR：F01 · 工作区助理与随手记**。本组 5 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：无。

**依赖理由：** P01 提供工作区和配置解析/生命周期；本票让维护者通过真实原生会话完整完成修改与验证，不依赖日常业务。

**覆盖规格：** 用户故事 101, 102, 103；测试组 T14, T15, T17。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 维护会话关联已选工作区，使用独立 preset 与原生文件工具；不另建专有配置表单，已有规则和不属于配置块的内容保留。
- [ ] 配置变更经 schema、路径、profile、owner、资源与 Worker/模型引用校验后应用，结果展示差异和生效摘要；坏配置保留最近有效值并说明错误。
- [ ] 秘密只允许凭据/环境引用，不把密钥写进 AGENTS.md、诊断、聊天或提交；禁止业务 Agent 通过任意文件能力绕过维护边界。
- [ ] 普通配置重载不丢已有 WorkItem 和原生会话；身份/工作区变更在活动工作存在时明确阻止或先完成安全停机，不能静默改写历史授权。
- [ ] 验证实际原生维护输入→文件修改→校验重载→新会话规则生效，以及坏配置、重复重载与已有工作保留；维护输出不发飞书。

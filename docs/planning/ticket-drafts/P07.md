## What to build

服务重启后恢复工作区 Lead 与未完成事项映射，按实际完成阶段续办或补报，已取消工作保持取消。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** 需要 P06 的控制与取消事实，并继承其前置的持久路由、原生父子关系及外部操作核对。

**覆盖规格：** 用户故事 52, 87, 90, 91, 112；测试组 T07, T08。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 从 PG 恢复工作区、飞书接入、本地助理入口、WorkItem、实际 parentSessionId/childSessionId 与投递目标，按需冷读或继续原会话；不批量唤醒历史，也不复制同 ID 会话或强抢 writer。
- [ ] 准入、Session flush 与回执保存各崩溃窗口分别对账；已接纳委托以 PG 为准，覆盖优雅 teardown 清 inbox 的情况。
- [ ] 原生 child 通知不是耐久父邮箱；原父会话冷却、通知丢失或结果提交后退出时，从账本补交实际 parentSessionId 并按 origin 回传；本地结果不得改投飞书 Lead，仅补缺少的发送。
- [ ] 区分本人取消、停机中断和外部结果未知；新恢复输入使用恢复代次，不能重放已执行工具或假设 resolveAgent 是 wake-only。
- [ ] 验证五项工作不同阶段重启、已完成不重做、取消不复活、会话/附件缺失与争用；未知外部写入复用已有操作核对契约。

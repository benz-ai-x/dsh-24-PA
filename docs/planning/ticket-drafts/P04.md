## What to build

主人用一段话交办多件事，由 Lead 拆成独立事项；按名称或编号查看和继续某项时，其他 Worker 继续工作。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** 复用 P14 已打通的 Lead→原生 child→持久结果→飞书路径；该票验证团队工作管理，不要求日历、任务、手写业务提前完成。

**覆盖规格：** 用户故事 38, 39, 40, 41, 42, 43, 44, 47, 48；测试组 T04, T05, T06。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 沿用首个备忘流程的 native continuable child，按每个 WorkItem 隔离上下文；专业职责注册为日程、待办/项目、提醒、备忘/资料、手写，未实现的业务动作准确显示不可用。
- [ ] 一段输入可拆分多个 WorkItem，先说明已接纳/排队，后由 Lead 汇报真实完成和来源；业务结果必须读持久回执，不能使用模型自述作为完成证据。
- [ ] 飞书可按名称或编号列表、查看和继续；同名/歧义澄清，不设置全局当前会话；继续已知事项恢复原 child，其他工作不被中断。
- [ ] 至少五项真实子会话可同时处于未完成状态，受独立模型并发上限控制；冷查询用原生列表/投影/历史，不用 follow 批量激活。
- [ ] dsh 面板只提供工作区/能力/事项/原生会话诊断入口；日常输入仍在飞书。验证五项可执行备忘工作并行/排队、复合委托、冷读与恢复原 child，不冒充尚未实现的业务能力。

## What to build

部署者联合备份 PostgreSQL、工作区配置/JSON 记忆、原生会话、原稿和审核快照；恢复后先核对外部状态，再继续服务。

**功能 PR：F12 · 运行维护与数据恢复**。本组 3 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F11 审核笔记的行动与综合查询。

**依赖理由：** 通知、原生计划、已审核行动及记忆修订都已有实际数据后演练联合恢复；各功能的基础迁移与故障测试不能延后到本票。

**覆盖规格：** 用户故事 94, 99, 101, 104, 108；测试组 T14, T15, T17, T18。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 备份清单覆盖 PG、工作区 AGENTS.md/JSON 记忆与修订记录、dsh 会话/原生域、附件原稿/快照和凭据引用，保存可核验水位及摘要，密钥按独立凭据策略恢复。
- [ ] 迁移有版本及失败恢复说明，不能只更新版本号或覆盖原有 dsh 域。
- [ ] 恢复检查缺失附件、会话和审核凭证，未完整恢复的能力不可假装就绪。
- [ ] 旧 Outbox 与飞书实际对象先对账，防止重复创建、旧提醒重放或过时审批覆盖。
- [ ] 演练真实隔离环境中的升级失败、旧备份恢复和代表性笔记/任务/日程/两类定时工作。
- [ ] 恢复 JSON 检查 schema/revision、来源与过期状态；较旧备份不能无条件覆盖较新记忆；恢复后维护会话可继续修改，派生索引可重建。

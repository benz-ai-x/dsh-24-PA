## What to build

主人回复某项旧消息或点击旧卡片时，补充和操作固定作用于原事项、对象及版本；不受其他工作进度影响。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** 需要 P04 的真实事项/子会话集合；对象级审核和提醒的业务校验由各自工单继续完成。

**覆盖规格：** 用户故事 45, 46；测试组 T05。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 持久保存平台消息到 WorkItem/child/业务对象的路由；卡片校验真实主体、目标版本、有效期和不透明动作标识。
- [ ] 明确事项与引用目标冲突时澄清；未知引用、过期或越权动作拒绝或进入待定路由，不回退投递到任意新工作。
- [ ] 每条输入分别保存路由决议，乱序或重复事件只处理一次；指代尚不明确时保留原输入，回答澄清后恢复原待定事项。
- [ ] 路由一经明确，不因重启、后台完成或其他对话改变；Lead 保留统一授权链，旧卡业务动作仍走目标的确定性处理器。
- [ ] 验证同时五项工作时回复旧消息、重启后旧卡、重复动作、迟到输入和同名冲突；查询另一事项不会改变动作目标。

## What to build

主人发送明确待办后得到真实飞书任务链接，能够查询和完成该任务。

**功能 PR：F03 · 任务与项目清单**。本组 3 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F02 并行事项与记忆维护。

**依赖理由：** P04 提供任务 Worker 委派，P36 提供按需背景；外部操作账本沿用前置 P14，再补齐任务平台的核对能力。

**覆盖规格：** 用户故事 5, 6, 8, 15, 88, 89；测试组 T01, T02, T08。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 将明确任务写入授权清单，必要歧义才询问；飞书实际对象为权威，返回操作编号和链接。
- [ ] 完成任务通过明确用户动作或飞书实际状态，不能从对话结束推断完成。
- [ ] 复用已有外部操作账本，补齐飞书任务的授权、操作意图、幂等/未知结果核对和资源协调；由待办 Worker 执行，Lead 回报真实对象。
- [ ] 网络响应丢失先核对远端，重复输入/按钮不盲目重复创建；并发更新读取最新状态。
- [ ] 验证固定 profile、范围拒绝、创建—查询—完成、部分失败及外部成功后本地退出。

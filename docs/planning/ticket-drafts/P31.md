## What to build

主人打开明确待审版本并批准或退回，飞书文档显示有凭证的人工审核状态。

**功能 PR：F06 · 手写笔记整理与人工审核**。本组 4 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F02 并行事项与记忆维护。

**依赖理由：** P29 提供可审核候选，P05 提供跨会话旧卡片的固定目标；不要求视觉增强 P30 先完成。

**覆盖规格：** 用户故事 77, 79, 80, 82, 83, 84；测试组 T12。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 区分可编辑草稿与服务器保存的指定候选快照，发布版本文档并回读指纹一致。
- [ ] 固定 revision 分页，正文/结构/原稿资源纳入指纹；系统区只按已登记块排除，未支持动态资源阻止整稿批准。
- [ ] 按钮绑定真实主人、原对象、版本、哈希、有效期；点击前重新核对草稿和版本，旧卡/越权/重放受控。
- [ ] 人工凭证、状态与文档同步 Outbox 同一 PG 事务提交；模型没有 approve 或任意改账本能力。
- [ ] 疑点须解决或明确保留未知；版本、审核人和时间可查；同步失败显示凭证已保存/标识同步中，回滚不留下半个批准。

## What to build

Lead 或 Worker 办理具体工作时，只检索相关 JSON 记忆与获准会话资料，给出来源、确认状态和有效期，避免混入全部聊天历史。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** P04 提供有权引用的原生工作集合，P42 提供可维护的 JSON 权威和版本；不要求把全部聊天历史写成长期记忆。

**覆盖规格：** 用户故事 33, 34, 37, 47, 104, 106, 109；测试组 T03, T04, T18。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 按关键词、类别、主题、状态检索 JSON，结果有界且包含 id/revision、出处、来源版本/指纹、确认状态和有效期；记忆只是背景，业务结果仍读权威外部对象。
- [ ] Lead/Worker 查询工具只读，执行器拒绝写入；只将命中条目放入当前上下文，手工文件变化下次读取可见。
- [ ] 派生索引与 JSON revision 对齐，可丢弃重建，删除正文不留在可检索索引；错误 JSON 明确报错，不返回旧缓存冒充新结果。
- [ ] 按授权引用其他业务会话时复用原生 query/session-reference，直接 ID 与列表同样校验 owner/allowlist；有界历史快照保留捕获位置，不能接管任意 coding 会话。
- [ ] 未审核笔记或未确认记录不因复述提升为事实；引用内容不增加工具权限。演示维护更正→Lead/Worker 检索、冷历史引用、过期/缺失/恶意材料与越权拒绝。

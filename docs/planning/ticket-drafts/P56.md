## What to build

手写识别的两个体验修复（研究依据：[F24 研究](../../research/F24-手写识别质量实现研究.md)）：

1. **视觉路由告警**：`vision-route` 健康项（runtime.ts:4286）从「路由存在即 ok」扩展为能力判定——路由模型与主助理模型相同、或模型名无视觉特征（vl/vision 等）时置 `warn`，message 明确「疑似非视觉模型，手写识别质量将不可用」；`pa24_connection` check/read 与向导同口径透出，nextSteps 指向模型配置节。不硬拒绝（允许测试链路继续），但必须显眼。
2. **待审文档精简**：handwriting persona v2 加长度纪律与输出分级——短笔记（转写≤80 字）只出「转写＋候选行动」；摘要≤100 字；AI 建议仅有价值时给；疑点只列无法辨认/矛盾项；相对日期并入候选行动注记不单列。`note_submit` 结构不变，仅 persona 纪律与待审文档渲染变化；快照测试同步。

后置（另发小迭代）：换视觉模型（GLM-4.5V/Qwen-VL 等）——接口已具备（workerModels.handwriting），改 AGENTS.md 一行＋宿主配 key 即可，待用户选定供应商。

**功能 PR：F24 · 手写识别质量**。单票单 PR。

**覆盖规格：** 用户故事 130；测试组随规格 2.0 落版时定（vision-route 告警判定、persona 快照为必测项）。

**验证边界：** Ops-Space 实例当前路由＝deepseek-flash（纯文本）应触发新告警；告警用启发式（同名主模型＋模型名特征），不做硬名单。旧待审版本与审核流程不受精简影响。

## Acceptance criteria

- [ ] 配置纯文本模型（如当前实例的 deepseek-flash）时，健康面板与 `pa24_connection` check/read 显式 warn「疑似非视觉模型」，nextSteps 指向配置指引。
- [ ] 配置真实视觉模型路由后 warn 消失、恢复 ok。
- [ ] handwriting persona v2 生效：短笔记待审文档只含转写＋候选行动；长笔记各段有长度纪律（快照测试锁定）。
- [ ] note_submit 结构与既有审核卡/凭证流程零回归（全量测试通过）。
- [ ] 真机：用户重拍一页笔记，对比精简前后文档长度与可读性。
- [ ] 文档同步：SPEC 2.0（故事 130）、索引与交付计划。

## What to build

主人通过工作区维护会话设置工作时段、缓冲、提醒与临时休假，飞书业务按需采用同一份有效 JSON 偏好。

**功能 PR：F05 · 个人提醒与免打扰**。本组 4 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F02 并行事项与记忆维护。

**依赖理由：** P36 已提供 JSON 及来源检索，其前置 P42 提供维护写入；本票补齐偏好的业务语义。

**覆盖规格：** 用户故事 33, 35, 36；测试组 T02, T09, T18。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 长期偏好只在本人发起的维护会话中写入 JSON，复用版本化 CRUD；飞书 Lead/Worker 只读，需修改时给维护入口，不能暗中写 PG 副本。
- [ ] 保存明确来源、confirmed/unverified 状态、时区与有效期；临时休假到期不覆盖永久设置，不从猜测创建长期事实。
- [ ] 读取时处理默认值、优先级与到期，回执说明采用的来源及规则；默认建议不能伪装成已确认偏好。
- [ ] 支持查看、更正、删除，手工文件改动下次读取可见；删除或过期偏好不继续从缓存生效。
- [ ] 演示维护设置→飞书读取及跨 Worker 一致性，并验证重启、有效期、冲突、删除、坏 JSON；提醒和规划消费效果由各业务票验收。

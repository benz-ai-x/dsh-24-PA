## What to build

主人在飞书说“记一下”或提交资料链接，Lead 委派真实备忘 Worker 保存飞书文档并统一返回出处，之后能按主题找回。

**功能 PR：F01 · 工作区助理与随手记**。本组 5 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：无。

**依赖理由：** P03 提供顶层 Lead 和准入/发送；本票是首个完整专业 Worker 与外部写入流程，后续业务复用其受控操作契约。

**覆盖规格：** 用户故事 8, 30, 31, 32, 38, 40, 44, 88, 89, 96, 112；测试组 T02, T03, T04, T08。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 由实际发起会话为备忘建立原生 continuable child，保存 WorkItem、origin、parentSessionId、childSessionId、职责和固定回传目标；子会话继承工作区，只开放必要工具且不递归生成 Worker。
- [ ] 使用固定 profile 和已选目录保存备忘、资料链接、主题与来源日期；执行入口校验主体、资源、指令依据和稳定操作键，不把文档内容当权限指令。
- [ ] 文档创建、分块写入、资源引用及回读都有持久阶段和实际回执；建立可复用 ActionOperation/资源协调契约；远端成功响应丢失先核对，不盲重建。
- [ ] Worker 完成写回持久结果账本，由 Lead 汇报操作编号和对象链接；接纳不等于完成，父 Agent 通知丢失可补报。
- [ ] 按主题、日期、关键词找回有出处的备忘；缺材料明确说明。真实 Loader/child/PG 验证保存—检索—打开出处、越权、部分写失败及恢复不重复建文档。
- [ ] 同一备忘流程分别从飞书和本地24私助发起，结果回到各自原父会话；本地结果不自动发送飞书，调用者不能通过伪造 parentSessionId 越权。

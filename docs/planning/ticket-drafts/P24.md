## What to build

主人开启晨报后，原生 Schedule 在指定时间唤醒工作区顶层 Lead，再委派 Worker 生成有来源的日程/任务简报。

**功能 PR：F09 · 每日规划与定期回顾**。本组 3 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F08 事项交办与持续跟进。

**依赖理由：** P07 提供智能工作恢复，P08/P10 提供实际任务/日历，P21 提供过期与静默投递策略；复用原生 Schedule，不能另建专用总控或在 child 上挂计划。

**覆盖规格：** 用户故事 2, 61, 62, 90, 96；测试组 T10。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 完整调用原生 Schedule，保存业务计划、原生 schedule、顶层 Lead Session 与稳定标识；只给 Lead 挂计划，child 不挂计划，支持开启/修改/关闭。
- [ ] 明确区分 Schedule 持久入队、模型工作完成和飞书平台接受；简报包含数据缺失与同步时间。
- [ ] 重复运行窗口不重复发布，未知创建结果按明确标识核对，不按标题相似盲建。
- [ ] 用 Lead 持久消息、规则标识与公开投递历史关联发生实例；不能仅靠同一个 Lead ID 关联。有限等待后进入 delivery_unconfirmed，暂停无法证明归属的发布/写入，不用当前时间猜实例。
- [ ] 使用 P07 工作账本恢复模型工作，过期晨报不补一串；测试 cold Session、入队后崩溃和回执写失败。

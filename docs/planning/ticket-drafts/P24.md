## What to build

主人开启晨报后，dsh Schedule 在指定时间唤醒专用 Session，生成有来源的日程/任务简报。

**功能 PR：** F09 · 每日规划与定期回顾（同组：P16、P24、P25）。本票沿用所属功能分支及 PR；同组前置依据该分支的提交与通过的验收推进，跨组前置等待功能合并。本票在所属功能合并且验收通过后关闭。

边界：需要 P07 的智能工作恢复、P08/P10 的真实资料及 P15 的时间偏好；无需先完成排程写入。

覆盖父规格用户故事：2, 61, 62, 90, 96。对应测试组：T10。

通过真实 dsh 装配、会话与隔离 PostgreSQL 验证用户可见及持久结果；仅替换模型、外部网络和时钟等边界。依赖内部具体函数调用顺序的断言不作为验收。

## Acceptance criteria

- [ ] 完整调用原生 Schedule，保存业务计划、原生 ID、专用 Session 与稳定标识，支持开启、修改和关闭。
- [ ] 明确区分 Schedule 持久入队、模型工作完成和飞书平台接受；简报包含数据缺失与同步时间。
- [ ] 重复运行窗口不重复发布，未知创建结果按明确标识核对，不按标题相似盲建。
- [ ] 投递历史有限等待；永久缺失进入 delivery_unconfirmed，暂停无归属发布和外部写入，不能按当前时间猜 occurrence。
- [ ] 使用 P07 工作账本恢复模型工作，过期晨报不补一串；测试 cold Session、入队后崩溃和回执写失败。

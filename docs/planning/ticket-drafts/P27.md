## What to build

主人提交实际会后文字材料，获得飞书纪要，并选定行动项创建任务或日程。

**功能 PR：F10 · 会议资料与纪要行动**。本组 2 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F09 每日规划与定期回顾。

**依赖理由：** P14 提供纪要文档；P11 及其任务写入前置提供两类行动的创建与回执，无需先有完整任务编辑。

**覆盖规格：** 用户故事 27, 28, 29；测试组 T03, T13。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 以用户提供或明确授权的材料生成纪要、决定、疑问与行动建议，资料不足不编造讨论。
- [ ] 文档和候选行动分别保存，候选包含出处、责任人/日期原话及未知项。
- [ ] 只对选定且信息足够的行动执行对应授权，保存到原文与外部对象的关联。
- [ ] 重复选择返回已有对象，创建结果未知先核对；纪要生成成功不等于行动已执行。
- [ ] 交付可供手写链复用的候选行动选择/执行契约，验证部分选择与任务/日程失败恢复。

## What to build

主人调整任务或说明做不完时，助理保留截止要求、延期原因，并避免不同 Worker 相互覆盖同一任务。

**功能 PR：F03 · 任务与项目清单**。本组 3 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F02 并行事项与记忆维护。

**依赖理由：** P08 提供真实任务与写入契约；P04 提供可验证的 A/B 并发入口。

**覆盖规格：** 用户故事 11, 15, 16, 53, 89；测试组 T02, T05, T08。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 区分截止时间、计划投入时间和估时；延期保留原因和剩余工作，不把计划改动当自动改截止。
- [ ] 支持明确修改/取消并回读实际结果；删除与取消按平台真实能力说明。
- [ ] 复用按资源协调和预期状态检查，多个 Worker 修改同一任务串行核对，不同任务可独立执行。
- [ ] 飞书用户直接修改后刷新投影，冲突不静默覆盖；重试返回已有操作结果。
- [ ] 演示 Worker A 修改、Worker B 用旧状态操作、外部编辑和取消后重复请求；不同资源可独立执行。

## What to build

主人使用飞书 App 拍照或发送图片文件，Lead 建立手写事项，返回稳定笔记编号、批次页序和可回查的实际接收原稿。

**功能 PR：F06 · 手写笔记整理与人工审核**。本组 4 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F02 并行事项与记忆维护。

**依赖理由：** P05 提供图片消息的固定事项归属、可靠接收与恢复前置；不依赖任务或日历业务。

**覆盖规格：** 用户故事 65, 66, 67, 68, 93；测试组 T11。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 飞书 App 图片与 JPEG/PNG/WebP 图片文件可进入手写事项；明确开始/结束批次及页序，重传同页识别，不自动合并不同讨论。
- [ ] 保存飞书实际返回原始字节、摘要和消息来源，区分压缩图片与文件原图。
- [ ] 限制格式、大小、页数和解码预算，反馈缺页、方向、模糊等可确定质量问题。
- [ ] 通过现有附件能力保存原件和派生副本，原件不会被缩放识别图覆盖。
- [ ] 收取/下载中断可按编号继续；演示三页收集、重复页、损坏资源和原稿核对，不要求本票识别文字。

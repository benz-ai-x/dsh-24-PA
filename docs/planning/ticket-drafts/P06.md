## What to build

主人可以对指定事项追加普通工作、明确补充或停止，收到实际影响说明；其他 Worker 继续执行。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** P05 提供目标固定与本人输入归属，控制必须作用在确认的 WorkItem 而非全局当前会话。

**覆盖规格：** 用户故事 48, 49, 91；测试组 T06。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] Lead 普通新输入走 queue，明确补充才 steer，明确停止才 interrupt；Worker 并发有界，排队/执行状态可查。
- [ ] 明确继续原事项恢复同一个原生 child；业务补充均经 Lead 形成授权依据，原生诊断入口不会把无关 Web 输入广播到飞书。
- [ ] 停止当前 turn、保留后续排队与全部停止分别依据本人指令处理；每次业务工具执行前检查 WorkItem 仍可执行。
- [ ] 取消原因耐久保存；停止不会撤销已成功外部操作，回执区分已完成、已取消和未知部分；重启不恢复主动取消。
- [ ] 通过真实控制队列验证 step 边界补充、排队、取消竞争、全部停止与跨 Worker 隔离，不为控制另建 Agent runtime。

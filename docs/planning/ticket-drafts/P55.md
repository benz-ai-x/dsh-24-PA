## What to build

飞书/企微 CLI 接入绑定从「逐阶段往返」收敛为「批量操作单＋一次验收」，并把企微服务授权过期从被动撞墙变为主动通知。研究依据：[F23 研究](../../research/F23-接入绑定体验实现研究.md)。安全红线不变：授权点击与密钥填写永远本人完成，agent 只发起、转交、验证。

交付三件：

1. **批量操作单＋一次验收（向导重构）**：`feishu-setup.md`/`wecom-setup.md` 改为「先全量、后集中」——配置开始即交付本人操作全量清单（依赖块 A 控制台 → B 终端 config init＋浏览器授权 → C 启动环境 Secret＋重启，企微为 A 扫码 → B 服务授权），agent 提前发起 Device Flow 并把授权 URL/二维码随清单一并交付；本人一口气做完回报一次，agent 集中验收。目标往返 N → ≈2。
2. **自动验收循环（执行纪律）**：本人报完成后以 `check`/`wecom_check` 循环按 nextSteps 收敛并一次性汇总剩余卡点；写入两份向导与 Lead 提示的接入节；是否为 `pa24_connection` 增加双通道批量检查形态按实施篇幅裁决。
3. **wecom 授权到期主动化**：定期 `wecom_check` 监控（提醒引擎或健康轮询，实施时定），命中 850002/850003 即经 notifyChannel 推送续期链接。

后置（本轮不做，另立项）：面板承载 QR 码与 Secret 输入框。

**功能 PR：F23 · 接入绑定体验**。单票单 PR。

**覆盖规格：** 用户故事 129；测试组随规格 2.0 落版时定（向导内容锚点测试、wecom 监控触发路径为必测项）。

**验证边界：** Device Flow 授权 URL 时效窗口、自动验收循环频率纪律、wecom 授权链接时效——实施期实测（见研究四）。向导变更不改 `check` 语义与安全红线。

## Acceptance criteria

- [ ] 新实例按新向导接入飞书：本人手工环节合并为一次清单交付＋一次集中验收，对话往返 ≤3 轮（真机记录轮次）。
- [ ] 企微接入同构；授权链接由 agent 发起/转交，本人仅在企微 App 内完成点击。
- [ ] 本人报「做完了」后，agent 自动循环 check 收敛并一次汇总全部剩余卡点（含 nextSteps），不再逐阶段追问。
- [ ] wecom 服务授权失效（850002/850003）时，主人在通知渠道收到含续期链接的主动提醒，无需撞错码才发现。
- [ ] 安全红线不变：Secret 不进对话/仓库；授权点击仅本人；诊断只读。
- [ ] 文档同步：SPEC 2.0（故事 129）、两份向导、索引与交付计划。

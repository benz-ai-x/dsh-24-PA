## What to build

维护者注册一种新的专业职责后，飞书仍由 Lead 接单，按配置委派该 Worker，并按同一方式查看、继续及接收结果。

**功能 PR：F02 · 并行事项与记忆维护**。本组 8 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F01 工作区助理与随手记。

**依赖理由：** 需要 P07 的真实生命周期/恢复和 P36 的统一记忆边界，避免新职责绕开已验证的团队契约。

**覆盖规格：** 用户故事 38, 40, 44, 96, 110；测试组 T04, T07, T19。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 注册声明职责、输入/输出契约、模型路由、工具白名单与许可资源；复用已校验的工作区配置，不扩展新的总控 runtime 或 OS 常驻进程。
- [ ] 用一项受控资料摘要职责演示注册→Lead 识别→原生 continuable child→持久结果→飞书回执；自动化只替换模型/外网边界，工具执行与持久状态真实。
- [ ] 新 Worker 沿用固定 profile、WorkItem、原生父子关系、有界并发、按需记忆、取消和恢复；不能自行再派 Worker、写记忆或代本人批准。
- [ ] 无效/重复职责或缺少模型/工具被拒绝并保留旧注册；移除职责前处理在途工作，不能让已接纳事项无声消失。
- [ ] 验证新增职责与原五类工作互不串线、越权工具被拒绝和重启可续办；只交付扩展契约与演示，不实现录音自动监听或转写。

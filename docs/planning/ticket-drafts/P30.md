## What to build

主人提交多页密集笔记，获得可按页和局部图核对的转写、图示说明及高影响疑点。

**功能 PR：F07 · 多页笔记与集中复核**。本组 2 张实施票共用一个功能分支及 PR，一个 PR 交付一个可用功能，不按单票建 PR。

同组前置在该功能分支已有提交且验收通过即可继续，前置票可保持打开；跨组代码依赖须等对应功能合并并通过验收。本票在所属功能合并且验收通过后关闭。

该功能合并前置：F05 个人提醒与免打扰、F06 手写笔记整理与人工审核。

**依赖理由：** 基于 F06 已合并的单页整理和指定版本审核，扩展到多页与裁片；无需等周期提醒完成，集中提醒由 P33 验收。

**覆盖规格：** 用户故事 66, 69, 70, 71, 72, 73, 74, 93；测试组 T11, T16。

**验证边界：** 使用真实 dsh Loader、原生 Session/Agent 与隔离 PostgreSQL；仅替换模型、外部网络和时钟。观察真实工具执行、持久状态及最终用户结果，不以模型自述或内部调用顺序代替验收。构建产物、权限、重复、部分失败、重启和必要迁移/恢复说明随本票交付；相关真实飞书/模型验证另记实测或未验证状态。

## Acceptance criteria

- [ ] 按明确页序识别多页，检查漏页、跨页重复和段落顺序，不因批次重试重复拼接。
- [ ] 从保真原图生成区域裁片，保存坐标变换并区分可靠/估计/页级引用。
- [ ] 图示保留原图与文字说明；数字、人名、英文缩写、日期、否定、勾选突出复核。
- [ ] 自报置信度不当概率；不清内容保留未知，预算/并发到限暂停并保留已完成页。
- [ ] 用代表性样本比较单页基线和增强结果；不新增第二套模型 runtime 或默认全量双模型 OCR。
- [ ] 增强后的多页候选继续经过已可用的版本发布/审核流程；页序、原稿或裁片变化进入内容指纹，不能继承不匹配的旧审核。

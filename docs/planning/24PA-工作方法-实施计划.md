# 24私助工作方法：日常安排与复盘

确认日期：2026-11-01（Asia/Shanghai）。用户批准方案并授权在 `codex/work-methodology` 实施；基线 `e06e4cff30fd67721537093e135e2fc2b48c330d`。功能归属 F47，故事 157。交付证据另记，设计获批不代表实际使用验收完成。

## 产品契约

- 方法论融入日常行为；明确小事直接办，重要取舍才讨论。以终为始、要事第一、主动推进、理解与协作、持续更新作为通用准则，GTD 支撑收集、澄清、组织、回顾与行动。
- 主人确认 1–3 个近期成果、完成标准和可选适用期限。助理不可凭推断更改已确认重点；阶段重点是业务规划对象，长期偏好仍遵循原记忆规则。
- 今日建议最多三项，包含成果、优先理由、下一步、关联来源、估时与可选时间块。查询覆盖登记来源并保留缺失说明，无截止的重要事情同样进入候选。没有已确认工作时段时不假设八小时可用；没有估时则标未知。
- 时间过载、承诺冲突或挤占已确认重点时，给出选项及影响，请主人决定。只暂停受影响部分。已作决定不反复追问。
- 保存建议不等于采纳；采纳每日计划不等于写入日历。选定日历块沿用原 `plan_adopt` 授权、核验与回执流程。
- 日终对照采纳快照，区分完成、推进中、受阻、主动调整与未知。完成依据为当前有效的业务状态或主人的明确说明；日程过去、同步时刻均不等于完成时刻。缺乏原因不臆测，仅提出一个影响后续安排的关键问题。调整作为候选供下一日使用，不自动延期或写记忆。
- 首页“今日工作”与对话共用规划记录，展示近期重点、今日建议及已采纳项、待决策和复盘；操作进入带日期及版本的对话草稿。普通读取不调用模型或原平台。
- 两个智能 Skill（`daily-planning`、`daily-review`）支持手工及定时运行，只能保存建议和复盘，不能确认重点、采纳计划或修改平台对象。在 Skill 管理明确放行后，通过通用定时任务启用；旧简报入口拒绝绑定这两个新方法。原模板不自动换绑，不自动开启定时服务。

## 实现与验证

- 工作账本增加带版本和不可变修订记录的规划聚合；日期按固定时区标识。乐观并发保护、重复提交复用、工作区隔离、重启恢复和备份随功能交付。
- `pa24_work` 增加 `planning_context`、`focus_update`、`daily_plan_save`、`daily_plan_confirm`、`daily_review_save`；后两类建议写入支持智能 Skill。近期重点修改与采纳只向交互式 calendar Worker 开放并保留本人指令依据；原生 Schedule 委派的普通 Worker 同样不可确认。保存建议同时校验读取时的 `focusRevision`，采纳前再次核算最新可用容量。
- `home` 新增 `workPlanning`；原有统计来源和业务对象不变。首轮无新一级导航。
- 覆盖无截止重点、过载/重叠/未知时段、过期和部分来源、采纳与建议分离、未经证实的完成、跨天延续、过时版本和重复调用、计划后台权限、首页只读和双语。
- 运行构建、预设检查、受影响单元测试及 SQLite/PostgreSQL 的 Runtime/Loader 验证；按电脑端 T20 验证首页，并进行 Standards/Spec 独立审查。
- 连续五个工作日的真实使用验收另记：重点是否符合意图、时间安排是否可执行、复盘是否影响次日、提问是否必要。隔离测试不能代替此项。

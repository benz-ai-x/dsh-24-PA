# Manticore 备份、校验与引导恢复

入口：24私助工作区 → 系统维护 → 账本与备份。列表按备份产物、完整性校验、隔离恢复演练分别留档，可筛选、分页、查范围和步骤。查询不会执行维护；填写绝对路径生成指令后，进入本地24私助会话发送。飞书和 Worker 不能调用这些维护操作。

## 创建与校验

1. 使用 `backup_create`，提供 `targetDir`（所有来源目录之外的备份父目录）和稳定 `requestId`。同一请求返回原记录，不重复生成产物；失败修复后以新请求重试，原失败保留。
2. 使用 `backup_verify`，提供实际 `backupDir` 和新的 `requestId`。它在临时隔离副本打开 SQLite／导入全新 PostgreSQL 实例，核验真实账本归属、schema、记录关联、原生 Session 与附件、原稿与裁片、审核快照、Skill 包和记忆。临时副本随检查清理；缺原生读取器时标为未检查。PostgreSQL 检查需可用的本地 `initdb`、`pg_ctl`、`psql`（支持 `--restrict`）；没有这些工具时保留备份并报告失败，不连接现场 DSN。
3. “产物形成”“校验通过”“隔离演练通过”是三项事实。账本是一致快照，文件在线采集；列表详情列出各自开始/结束时间和变动文件，不能推出全系统同一时点。格式 4 在备份工作区写入执行隔离标记；旧格式 3 可检查，旧格式 2 SQLite DB/WAL 组合不能证明一致性。

覆盖业务账本全表（含计划、运行输入/阻断、预算、资料审核、来源和健康档案）、工作区规则与非秘密配置、记忆及修订、个人 Skill、Host 状态、配置的 Session／storage／附件根。Session 根可能包含同 Host 其他工作区，清单如实保留来源范围。凭据文件与授权缓存排除；会话中的历史文字不会自动全文脱敏。远端文档和平台对象只有本地快照/引用，不能声称远端备份完成。

## 准备隔离副本

1. `backup_preview` 提供 `backupDir`；检查同一工作区身份，展示新增记忆、保留当前值的冲突、删除标记保护及证据边界。
2. 确认后调用 `backup_restore_check`，提供 `backupDir`、不存在的绝对 `targetDir`（父目录须存在）、预览返回的 `previewToken`、新 `requestId`、`confirm: true`。目标不能与现场或源备份重叠，不覆盖任何已有目录。预览过期、坏 JSON 或待核对审计会阻断。
3. 副本从复制前即带 `.24pa/restore-isolation.json`，普通绑定、重启均拒绝接纳。检查器只装载原生持久化读取器，不装载 Agent、调度、入站或出站消费者。复制失败的半成品也保持隔离。
4. `restore-report.json` 保存逐项结果。候选记忆保留当前较新内容、双方删除标记，并清理副本历史中的永久删除正文；现场和源备份不改。若当前文件丢失且备份早于删除，报告无法推知丢失的删除证据。

## 人工切换清单

隔离检查通过仍返回 `productionReady: false`。本轮不提供全自动覆盖恢复。以下须在单独获准的恢复窗口完成并留证，未完成时不要删除隔离标记或启动副本：

- 停止原 Host，保留原目录和账本，不允许两套实例同时运行。重新确认从备份时点到停机的增量，必要时重新制作备份和预览。
- 按报告核对原身份、所有登记日历/待办容器、已知远端对象及测试对象的清理状态。旧健康和权限证据只代表当时结果，重新验证授权；凭据经专门机制另行恢复，不从会话或报告提取。
- 核对每条未结束交办、Skill/Worker 运行、原输入、累计计时、未决工具/子任务/作业、预算等待和一次放行。已使用许可保持已使用；未知不能改成功，也不能靠重跑证明结果。
- 逐项核对计划启停、触发、结果、Outbox 和未知外部操作。已在备份后完成的动作/消息不得再建再发；保留原对象 ID、渠道、身份和容器，不能转投新的默认来源。需要补账的回执通过原功能恢复，未决项保持阻断。当前工具只列证据，不自动更改这些状态。
- 将核对后的账本和对应文件一同放入确定的配置根。SQLite 使用独立 `pa24.db`，不能混入旧 WAL/SHM；PG 使用独立目标库，先确认 owner/schema/编码/实际查询，再变更现场连接配置。隔离演练里的 PG 实例是临时导入验证，保留的 `pa24.sql` 仍需在最终目标导入。
- Session header/cwd、原稿/裁片、workspace_state 与运行快照包含原路径。本轮不改写私有 Session；优先停机后按原绝对路径恢复，不将隔离目录直接当新生产路径。路径搬移需另行核验。
- 只有上述核对、凭据、路径与回退方案均留证后，人工解除目标工作区隔离标记并启动唯一 Host。先只读检查，再逐项启用确认过的未来计划/执行/投递；任何未知都保留核对状态。保留演练报告和原目录用于回退。

schema 31 仅新增备份记录表。旧备份账本中可能保留“创建中”行，因为完成记录在快照之后写入；启动后标记为中断是事实，不能补造成功。普通代码回退可保留追加表，但旧代码没有恢复隔离保护，禁止用降级绕过隔离。

真实账号重新授权、远端增量对账、生产目录切换与完整现场演练继续由 [P40 / #46](https://github.com/benz-ai-x/dsh-24-PA/issues/46) 跟踪；自动化隔离测试不替代这些验收。

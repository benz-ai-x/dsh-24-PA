# 一个助理预设，按发起会话隔离工作和权限

状态：accepted。依据：2026-10-05 用户确认「机器人包含 Lead 与工作区维护能力」，随后确认中文名24私助、英文名24PA。

24私助以工作区为配置和记忆归属，只提供一个对用户可见的助理 preset。飞书接入保留固定顶层 Session，本地可有多个同预设顶层会话；各自协调的 Worker 挂到实际父会话，工作账本保存发起入口与固定投递目标。这样同一会话可以交办和维护，本地结果仍回本地，飞书事项仍回飞书，恢复也保留原归属。

独立维护 preset 会使用户为普通维护切换角色；把全部对话并入一个飞书 Lead 则会混合本地历史与回传目标。采用单一 preset、多会话的边界，并由宿主核验入口、父子关系和工作区来决定工具权限。子 Agent 即使继承同一 preset 也只获得其职责允许的工具；配置和 JSON 写入仅向有维护权限的本地顶层会话开放。

产品更名只改变展示名称。现有插件、preset、会话、工具和数据路径标识保持兼容；若原会话被用户改成其他 preset，保留历史并建立正确的新入口，不重写旧会话身份。智能业务 Schedule 继续绑定固定飞书接入顶层会话，原生 child 不挂计划。

2026-10-07 修订：用户确认24私助预设并入标准模式完整编程能力。该扩展不改变本决策的边界——标准编程工具（终端、文件、检索、计划、压缩、通用委派、ralph）只进入本地顶层24私助会话的角色白名单；飞书接入会话与 Worker 的业务白名单不变，tool-schedule 不并入（提醒统一走 PostgreSQL 账本），codex/claude-code 外部 CLI 委派需安装对应 provider 并经工作区 extraLocalTools 显式开启。同一预设仍不等于同一权限。

2026-10-23 修订：依据已批准的 Manticore 本地任务型 Skill 范围，收窄修正 2026-10-07 的「标准编程工具只进入本地顶层会话」条款。主人从本地管理入口明确预览并启动的 Skill 可创建独立本地运行；其原生编程子任务仅在宿主证明父子归属、运行账本证明同一工作区后，获得该次运行快照声明范围内的标准编程工具。这样允许本地任务复用宿主原生委派能力，同时把每个子任务的动作、停止与恢复归入原运行。子任务不得继承工作区配置、JSON 记忆维护、凭据或额外 MCP 权限；业务 Worker 与飞书入口继续受各自业务白名单限制，通用子任务不能伪装为业务 Worker。每次调用仍重新核验运行状态、来源与权限，权限变化只收紧；不是依靠 preset 名称或会话 ID 前缀授予权限。

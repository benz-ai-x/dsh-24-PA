# 24私助（24PA）初始化指南

本指南面向 AI 助理（也供本人查阅），是把 `@benz-ai-x/dsh-24pa` 安装到一个全新实例并跑到 demo 可用的**唯一权威操作序列**。动手前先通读全文；**一步一验：每个阶段结束时对照达标标准，未达标先处置再前进**。飞书接入不属于初始化：demo 验收通过后，以随包内置的 `feishu-setup.md`（本地24私助会话说「帮我接通飞书」，或 `pa24_connection action=guide`）为唯一权威。

核心心智模型：

1. **实例即目录**：`DSH_HOME`、工作区、npm 缓存全部收进一个实例目录，与全局 `~/.dsh` 及其他实例互不影响；删除该目录即删除整个实例。同一台机器可以并存多个实例（各占一个端口和一套状态）。
2. **版本对齐**：包版本号形如 `<dsh 基线>.<序号>`，与 dsh 宿主版本一对一；版本不匹配的组件（如 registry 上 peer 不符的 schedule 包）会保持禁用而非降级凑合。
3. **单写锁**：一个 `$DSH_HOME/24pa` 状态目录同一时刻只允许一个宿主进程；第二个宿主会在启动时因锁退出。
4. **一步一验**：每个达标标准都拿命令结果判定——退出码、HTTP 状态码、文件内容。

## 阶段 1：账本（默认零依赖；可选 PostgreSQL）

**默认（规格 2.1/F25）：SQLite，无需任何数据库**——账本是工作区内的 `data/pa24.db` 文件（WAL 模式），宿主首次绑定工作区时自动建表迁移；备份使用 SQLite 原生在线备份生成独立一致快照，不再拼接在线 DB/WAL 文件。跳过本阶段其余步骤。

备份格式 3 将账本快照与其他在线收集文件区分记录。旧格式 2 的 SQLite DB/WAL 集合不能证明一致性，不再通过完整备份验证；请保留旧文件供核对，并在升级前新建备份。旧格式 2 的 PostgreSQL 备份仍可验证。恢复 SQLite 时先停止 Host，把新快照 `pa24.db` 放入空的隔离目录，不带入旧 `-wal`/`-shm`，核对业务数据后再替换目标。旧插件不能验证格式 3，代码回退前需用新版完成验证；备份快照修复本身不改变业务 schema，账本归属修复增加 schema 17。联合文件仍不保证跨系统同一事务时点，完整步骤见[包内恢复说明](../packages/24pa/README.md#backup-and-recovery)。

### 工作区与账本归属（schema 17）

两种账本均核对工作区 `.24pa/ledger-identity.json` 的稳定身份和已登记主人。新工作区使用独立空账本；不能把另一工作区的 PG DSN 当作新账本复用，即使主人相同。demo 初次可尚未填主人，同一工作区可登记第一个非空 `ownerOpenId`；登记后配置保存、重载、重新绑定均不能清空或改成另一主人。

升级前停止使用该库的所有 Host，并保存账本、整个工作区、Host 会话和附件。SQLite 可在停机后用原生备份导出独立数据库（例如 `sqlite3 <旧库路径> ".backup '<隔离备份路径>'"`）；PG 用 `pg_dump --schema=pa24 --no-owner --no-privileges --dbname "$PA24_PG_DSN" --file <隔离备份路径>`。保留原件，先在隔离副本核对，不以旧格式 2 的 SQLite 摘要代替可恢复性验证。

- **空旧库**：除 schema 元数据和未用的 SQLite 序号外无行，可自动登记。
- **可证明的旧库**：历史 `workspace_state` 恰有一个路径且等于当前规范路径，`binding` 恰有一个非空主人且等于配置主人，才可升级并登记。归属核验、迁移和声明在同一事务中；任一步失败全体回滚，原活跃实例保留。
- **无法证明或混用**：拒绝接纳。只读检查 PG 的 `select path from pa24.workspace_state`、`select distinct owner_open_id from pa24.binding`；SQLite 对应表为 `pa24_workspace_state`、`pa24_binding`。在隔离库导出并逐项核对资料所属主人/工作区；先从正确的工作区备份和配置恢复证据。没有可信证据时，建立新工作区和独立空库，原库保留供人工核对；不要通过清空归属表、补造绑定行或改主人来绕过检查。

schema 17 的联合备份必须包含有效身份文件，并与备份清单记录的账本 UUID 一致；缺失、损坏或不匹配时报告不完整，不能据此恢复上线。

**路径搬移与恢复**：停止原 Host，把原工作区的身份文件与账本一同保留，再显式绑定新路径；随机身份与主人匹配即可，路径和 DSN 字符串不决定归属。复制身份文件表示恢复同一逻辑工作区，禁止把原件与恢复副本同时运行；新工作区应从空目录和空账本初始化。身份丢失或损坏时从同一工作区备份恢复该文件，不能生成新身份认领旧账本。原有会话、外部对象和资料的路径引用不会自动迁移，需按恢复说明核对。

**回退**：schema 17 是新增元数据，但旧代码没有归属保护。不要让新旧 Host 并行连接，也不要删除归属行作为回退；停机后恢复升级前的完整隔离备份和对应旧代码，再核对所有投递/外部对象。升级失败仅重试原正确工作区，不自动重分配历史数据。

仅当工作区 AGENTS.md 显式 `"storage": "postgres"` 时才需要 PostgreSQL（既有 PG 部署升级即此形态）：

宿主首次绑定工作区时自动创建 `pa24` schema 并迁移表，因此**只需准备一个空数据库和可写用户**，无需手工建表。

Docker 方式（单机 demo 等价配置：仅监听回环、trust 认证；对外开放时必须改为强认证）：

```yaml
# compose.postgres.yaml
name: pa24-<实例名>-postgres
services:
  postgres:
    image: postgres:16-bookworm
    container_name: <容器名>
    restart: unless-stopped
    environment:
      POSTGRES_USER: pa24
      POSTGRES_DB: <库名>
      POSTGRES_HOST_AUTH_METHOD: trust
      POSTGRES_INITDB_ARGS: --auth-host=trust
    ports: ["127.0.0.1:<宿主端口>:5432"]
    volumes: [pgdata:/var/lib/postgresql/data/pgdata]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U pa24 -d <库名>"]
      interval: 5s
      retries: 12
      start_period: 10s
volumes:
  pgdata:
```

```sh
docker compose -f compose.postgres.yaml up -d --wait
```

既有 PostgreSQL 方式：为目标用户执行等价的 `create role` / `create database` 即可。

达标标准：用将来 DSN 中的用户与库执行 `psql "<DSN>" -c 'select 1'` 成功。

### 原回合结算恢复（schema 18）

已完成 Worker 的结果事务暂时失败时，系统自动按退避间隔补结算（间隔上限 30 秒），不重新调用模型或重复执行外部动作。运行记录会显示结算待重试。重启后，从宿主已持久保存的 Session 历史核验原输入与完成回合，仍在原代次落账并生成一个结果投递意图。

升级前联合保存账本、工作区和原生 Session 历史。只有账本而缺少原回合历史，或历史被中断、父子关系/工作区/输入无法核验时，事项进入待核对；先检查原输出与外部对象，再明确停止或续办，不能把它当作自动执行失败后重发。临时历史读取故障保留自动重试。无新执行关联的历史事项仍按旧恢复流程递增代次并要求核对已完成步骤。

宿主不提供公开冷读能力时，新事项的冷恢复也会要求核对；不得以读取私有会话文件或重新执行原动作替代证据。回退到旧代码前停机并恢复升级前整套备份，避免旧代码重新执行已完成的事项。

### Skill 管理与手工运行（Manticore，schema 19）

在「24私助工作区 → Skill 管理」新建草稿，或上传 Markdown／ZIP；从一句话整理初稿后可直接编辑 `SKILL.md`。文件与内置原件先复制为个人 Skill，采纳时冻结完整包，后续编辑不会反写原文件。保存草稿、启用版本和真实运行分开；包校验错误仍可保存为待修正草稿，但不能启用或运行。

任务声明需包含参数、完成标准、执行范围与工具列表。`tools: []` 表示不使用工具；可在 `metadata.pa24.dependencies` 声明包内 `resources`、本地 `commands` 和 `environment` 名称，检查只报告缺少的名称，不安装依赖或回显凭据。模板保持零模型执行；自由改变模板业务行为时先生成智能副本草稿，再核对模型用量和工具范围。

点击「预览本次运行」核对参数、版本与工具，再确认试运行或正式运行。试运行也会真实执行获准工具；结果默认保存在本条运行，不自动向外投递。运行详情可查看原会话、工具回执、子任务/后台作业、结果下载和关联交办。编辑、回退或禁用只影响后续准入；禁用同时暂停关联计划，重新启用不会自动恢复计划。有效计划仍引用时不能删除；删除后保留版本和运行历史，也保留原运行停止与核对入口。

取消或重启不能证明已发生的动作被撤销。结果待核对时，先检查原文件/平台对象和子任务是否终止，逐项填写实际结果、已完成与剩余工作，再保存核对。原 unknown 回执保留；核对后可以显式选择原快照或当前配置预览接续，仍关联同一交办。迟到新证据会使旧核对失效。平台动作账本仍未决时先修复原对象回执，不能用运行核对或新建请求绕过。

升级前停机并联合备份账本、工作区身份文件和宿主 Session 历史；schema 19 在既有迁移事务内增加包、不可变版本、运行及核对表，不改 JSON 记忆权威。升级后先在隔离实例核验历史和权限。恢复缺少原生历史、后台作业终态或权限时保留待核对，不能重发动作；回退需停机恢复升级前整套备份和对应代码，不允许新旧 Host 并行连接或手删迁移记录。

### 来源登记与日程升级（Manticore / schema 20）

参数配置的“日历与待办来源”保存到原 AGENTS.md 配置块，包含名称、平台、本人身份、原生资源、用途、筛选、读写意图、启停、分域默认、公司／项目映射和可选会议时长。登记不授予权限；保存后点击该来源的只读检查，核对真实应用／机器人、本人和原生资源。飞书 `primary` 只有解析到本人的唯一真实日历后才可绑定，企微 `authorized_scope` 是授权查询范围，不能冒充某个公司／项目日历容器。

旧配置没有 `sources` 时只生成稳定候选，普通浏览不写配置或创建远端资源。保存来源会物化候选；在原参数表单改旧默认时会保留原来源并增加新默认，已有对象和计划不迁移。已经保存来源后，请在来源区改默认，不再以旧单值字段代表全部范围。手工编辑 AGENTS.md 时先物化原来源，避免把旧来源隐式移除。空来源列表保持为空，来源移除仍保留历史回执。

日程卡普通浏览使用带时间的缓存，点击“核验日历”或在对话查询才读取平台。失败、角色不全、企微窗口外和未展开的重复实例均标为范围不完整。写入按明确来源、公司／项目映射、默认的顺序选择唯一目标，权限不够不转投其他日历。默认变化不改变旧操作、提醒或会前准备的原目标；结果未知先核对原平台，已保存成功回执但本地补账失败时沿原操作恢复，不再创建一次。

新独立提醒按请求时刻触发原生日历提醒，旧提醒仍保留原提前量；会议“取消提醒”只清除本人提醒。飞书“本人退出”、企微指定日历容器／完整组织者证据／邀请／本人提醒编辑等当前适配差异会明确提示原平台办理。真实 App 离线提醒效果仍需授权后的设备验收。待办来源目前可登记和检查，待办业务继续使用原渠道与清单，M04 接入多来源。

升级前停止 Host 并联合备份账本、工作区身份和配置、宿主 Session 历史。schema 20 在 SQLite／PostgreSQL 的既有迁移事务内新增来源登记、身份能力证据、对象、成员关系及观察记录，配置仍以 AGENTS.md 为准。恢复后先确认原身份及资源，失效证据重新检查；不得将旧回执改绑新身份或新默认。回退须停机恢复整套升级前备份和对应代码，不手删迁移记录，不允许新旧进程并用同一账本。

## 阶段 2：实例目录与启动环境（你代办）

建立实例目录并写入 `start.sh`（下例为经过双实例验证的模板，逐项替换 `<...>` 占位）：

```sh
mkdir -p <实例目录>/{home,workspace}
cat > <实例目录>/start.sh <<'EOF'
#!/bin/sh
# 24私助 <实例名>（demo 模式；切换飞书模式见 feishu-setup.md 阶段 4）
export DSH_HOME=<实例目录>/home
export npm_config_cache=<实例目录>/npm-cache
export DSH_TELEMETRY_DISABLED=1
export PA24_WORKSPACE=<实例目录>/workspace
export PA24_PG_DSN=postgresql://<用户>@127.0.0.1:<端口>/<库名>
# 切换飞书模式时取消注释并由本人填写（值只存在于启动环境）：
# export PA24_FEISHU_APP_ID=<App ID>
# export PA24_FEISHU_APP_SECRET=<应用密钥>
# 注：F36 起上述飞书凭据与豆包 TTS Key 也可在面板「系统维护 → 参数配置 → 密钥」
# 组直接填写（存工作区密钥库 .24pa/secrets.json，0600，不进 AGENTS.md/备份）；
# 环境变量是可选的部署层覆盖（同名时优先）。两条路二选一即可。
exec <dsh 命令> --profile <实例名> --host 127.0.0.1 --port <面板端口> --no-open
EOF
chmod +x <实例目录>/start.sh
```

要点：`PA24_WORKSPACE` 必须是绝对路径，目录不存在会在首次启动时自动创建并写入 `AGENTS.md` 模板；**已有 `AGENTS.md` 永远保留、不覆盖**。DSN 等密钥值只放启动环境，`AGENTS.md` 里只出现变量名。重启永远经启动脚本进行——绕过脚本裸起会得到「宿主在线但什么都不装配」的实例；由 launchd 等托管器拉起时其 PATH 最小，需在脚本内显式补全。

达标标准：`start.sh` 存在、可执行，其中的 `DSH_HOME` 与实例目录一致。

## 阶段 3：安装插件（你代办）

`dsh plugin` 是独立子命令，无需宿主运行；**必须以与 start.sh 相同的 `DSH_HOME` 执行**，否则会装到全局 profile：

```sh
DSH_HOME=<实例目录>/home dsh plugin --profile <实例名> add '@benz-ai-x/dsh-24pa@<版本>'
```

profile 不存在会自动初始化。按宿主基线选版本（npm dist-tag `dsh-0.2.0-rc.2` / `dsh-0.2.1-alpha.1` 按基线分通道）：

| dsh 宿主基线 | 安装内容 |
|---|---|
| `0.2.1-alpha.2` – `0.2.1-alpha.5` | `@benz-ai-x/dsh-24pa@0.2.1-alpha.5.1`（alpha 线已停更于此，preset 内容与 `rc.1.1` 相同、仅 engines/peer 扩围与文档差异；alpha.1 已停留在 `.1.6`） |
| `0.2.1-rc.1` | `@benz-ai-x/dsh-24pa@0.2.1-rc.1.1`（活跃线；peer 覆盖 alpha.2–rc.1 宿主；alpha.4+ 批次部分子包在默认镜像源未同步，安装需官方 registry `--registry=https://registry.npmjs.org`） |
| `0.2.1-alpha.1` | `@benz-ai-x/dsh-24pa@0.2.1-alpha.1.6` |
| `0.2.0-rc.2` | `@benz-ai-x/dsh-24pa@0.2.0-rc.2.3`（该线 2026-10-08 冻结、不再迭代），另加两个简报/会前准备依赖的伴随件：`@deepseek-ai/dsh-experimental-schedule-bundle` 与 `<rc.2 源码 checkout>/packages/schedule/schedule`（本地路径） |

**预期坑 A（protobufjs 占位符）**：全新 profile 首次 `add` 以非零码结束是预期行为——pnpm 11 对飞书 SDK 的传递依赖 `protobufjs` 留了构建审批占位符，而**包此时已完整加入** profile。处置两步：

1. 编辑 `$DSH_HOME/profiles/<实例名>/pnpm-workspace.yaml`，把 `allowBuilds` 下的占位行改为通过：
   ```yaml
   allowBuilds:
     protobufjs: true   # 原值：set this to true or false
   ```
2. 原样重跑同一条 `add` 命令，此时应退出码 0。

**预期坑 B（minimumReleaseAge 观察期）**：dsh 内嵌 pnpm 的供应链策略不安装发布未满观察期的版本，会改装较旧版本并在回执中说明（文案提及 `minimumReleaseAge` 与「未满规定时长」）。确需精确版本时：

1. 在同一 `pnpm-workspace.yaml` 追加：
   ```yaml
   minimumReleaseAgeExclude:
     - '@benz-ai-x/dsh-24pa@<精确版本>'
   ```
2. `DSH_HOME=... dsh plugin --profile <实例名> remove @benz-ai-x/dsh-24pa` 后，再以精确版本重新 `add`。

达标标准：`add` 退出码 0；`$DSH_HOME/profiles/<实例名>/package.json` 的 dependencies 含 `@benz-ai-x/dsh-24pa`；rc.2 基线下两个伴随件同样就位。

   - **工作区**：`<实例目录>/workspace/AGENTS.md` 存在，且含唯一 json 配置块、`"mode": "demo"`；
   - **账本**（默认 SQLite）：`<实例目录>/workspace/data/pa24.db` 存在且 `run.log` 无存储错误；仅当显式 `"storage": "postgres"` 时改为：`run.log` 无 PostgreSQL 连接错误，用 DSN 登录库执行 `\dn` 能看到 `pa24` schema。
3. 任一项失败：先查故障对照表定位，再从对应阶段重来；重启宿主前先停旧进程并确认端口释放。

## 可选：听记接入（QwenNote 录音卡）

主人使用钉talk（QwenNote A2）录音卡时，本地24私助会话可读取其听记（最近列表、会议转写与纪要）。**仅本地会话可用；飞书入口会话与 Worker 永不放行**（听记含敏感内容，MCP 凭据为机器级）。

1. **通道（profile 配置，维护者代办）**：宿主 profile 的 `cordis.patch.yml` 增加条目（版本锁定，勿用 `-y` 拉最新）：
   ```yaml
   - id: mcp-qwennote
     name: '@deepseek-ai/dsh-mcp-client'
     config:
       serverName: qwennote
       transport: stdio
       command: npx
       args: ['-y', 'mcp-remote@0.14.3', 'https://minutes.qwennote.cn/mcp']
   ```
   新增行必须在既有条目的 `insert:` 列表内（裸顶层行会被加载器跳过——见 README「预设与补丁」）。
2. **放行（AGENTS.md）**：`extraLocalTools` 加入 `"mcp__qwennote__*"`（或精确工具名）。点名的工具未挂载时会在放行解析中被过滤并提示，不会阻断会话。
3. **首次授权（本人浏览器，一次性）**：dsh-mcp-client 会吞掉 mcp-remote 的授权链接输出（宿主日志拿不到 URL），且宿主重连可能堆出多个 mcp-remote 实例互相干扰——**可靠路径是独立授权进程**（维护者代办发起、本人浏览器确认）：
   - 维护者在宿主上清掉既有 mcp-remote 进程，随后手动起一个独立实例并把它的输出落文件（`HOME` 指向实例 home）：`setsid nohup <npx 缓存内的 mcp-remote> https://minutes.qwennote.cn/mcp > /tmp/mcp-auth.log 2>&1 &`，从日志取「Please authorize」链接（**约 5 分钟轮换且带一次性 state**，过期重起进程取新链接）；
   - 回调是宿主上的 `127.0.0.1:8905`：宿主在远程服务器时，本人从日常电脑起 SSH 本地转发（`ssh -L 8905:127.0.0.1:8905 <host>`）再打开链接确认授权；凭据不经助手转手；
   - 授权成功后独立进程自退、token 落共享缓存；重启宿主，新 mcp-remote 读缓存直连（健康面应转为「正常」）。
4. **诊断**：健康面「听记通道」三态——**正常**（工具已挂载）／**未授权**（配置在、从未完成授权）／**连接失败或 token 过期**（曾授权、当前未挂载；先重启宿主重连，仍失败按上一步重新授权）。诊断只看工具挂载与 token 缓存存在性，**不会主动调用听记工具**。
5. **使用与边界**：对本地24私助会话说「查一下最近的听记」即可；引用带来源标注；从中提炼的行动照走候选行动→审核→行动授权，不因来源是听记跳过确认。

## 可选：任务 skill（周期服务配置面）

「晨报与复盘」卡支持按计划直改**自动触发时间**、**语音开关**、**任务 skill**，并可**立即运行一次**当场验收；复杂变更（新建/暂停/停止）仍通过对话。

1. **宿主 skill 体系**随 dsh web 基线自带（registry＋文件发现＋模型侧工具），无需单独安装；宿主未提供时插件自动回落内置任务 skill（晨报/晚间复盘/每周回顾，模板轨照常可用），只是无自定义面。
2. **自定义任务 skill**：放 `workspace/.dsh/skills/<name>.md`（或 `<name>/SKILL.md`），frontmatter 必填 `name`（kebab-case）与 `description`；`metadata.track: template | agent` 声明执行轨（缺省 agent＝模型执行，周期执行支持随后续版本交付；当前版本计划绑定仅放行模板轨）。目录热更新，增删改无需重启。
3. **临时/业务 skill 的受控执行（F44）**：经通用「任务 skill 执行」Worker 委派（worker=skill），双门放行——`enabledWorkers` 加入 `"skill"` 启用角色，`extraBusinessSkills` 列出可委派的 skill 名（kebab-case）；Worker 以 `skill_run {skill}` 载入正文执行，越权名在建事项前即拒绝。
4. **工作流口径参数**：手写审核流的待审提醒文案等参数在 `handwriting-review-flow` 内置 skill 的 frontmatter `metadata.params` 声明，工作区同名 skill 覆盖即生效（改模板不改代码）。
5. **安全红线**：skill 不能放宽工具权限（平台白名单强制，只能收紧）；密钥与事务仍在平台层。

## 可选：语音晨报/复盘（TTS 双引擎）

晨报（morning）与晚间复盘（evening）可开启语音版：到点先送达本机/云端合成的**原生飞书语音消息**，紧跟全文文本兜底（数字、专名听不清时可查文字）。语音正文为口播变体（自动剥离同步时间戳、来源括注与数据缺失清单，超约 1200 字截断并在语音内播报提示）。引擎未配置、宿主缺依赖或合成失败时**自动降级为纯文本并告警，不中断服务**。

引擎是工作区配置（AGENTS.md 配置块 `tts` 字段），二选一：

### 豆包云（volcengine，推荐：零本地依赖）

1. **开通服务（本人，控制台操作）**：火山引擎**新版语音控制台** console.volengine.com/speech/new →「语音合成」→ 开通「**豆包语音合成大模型 2.0**」（Seed-TTS-2.0，有免费试用额度）。注意它与其他语音服务（如 Seed-Audio 音频生成）**相互独立**，须单独开通。
2. **创建 API Key（本人）**：同控制台「API Key 管理」页创建。**必须 是本控制台的 Key（UUID 形态）**——方舟（Ark）平台的 `ark-` 前缀 Key 调不了语音接口（报 401 `45000010`）。
3. **密钥就位（首选面板，F36 起）**：打开24私助面板「系统维护 → 参数配置 → 密钥」，把豆包 API Key 填进「豆包 TTS Key」行并「保存密钥」——存进工作区密钥库（`.24pa/secrets.json`，0600），不进 AGENTS.md/系统提示/备份，保存即生效。**可选**：或写启动脚本环境（`export PA24_VOLC_TTS_KEY=<豆包 API Key>`，同名环境变量优先于密钥库、变更以重启为准）。
4. **AGENTS.md 配置块**（面板参数配置表单或本地24私助会话维护）：引擎选 `volcengine`、音色任选其一，`volcKeyEnv` 保持默认即可（走密钥库时无需指定）：
   ```json
   "tts": { "engine": "volcengine", "voice": "zh_female_cancan_uranus_bigtts", "volcKeyEnv": "PA24_VOLC_TTS_KEY", "meloDir": "" }
   ```
   首发五音色（均经生产真机合成验证）：`zh_female_cancan_uranus_bigtts`（知性灿灿·晨报主推）、`zh_female_zhixingnv_uranus_bigtts`（知性女声·沉稳）、`zh_male_m191_uranus_bigtts`（云舟·男声）、`zh_female_vv_uranus_bigtts`（Vivi·元气）、`zh_female_xiaohe_uranus_bigtts`（小何·甜）；其他豆包语音合成 2.0 音色 ID 直接填入亦可（注意 `*_jupiter_*` 属 S2S 线，本接口报资源不匹配）。
5. **验证**：面板「晨报与复盘」卡 →「检测语音引擎」（只读预检密钥/音色）→「发一条测试语音」。通知渠道为企微（`notifyChannel=wecom`）时暂不支持语音，自动降级文本。

### Melo 本地（离线可用，依赖较重）

1. **宿主依赖（维护者代办）**：`python3`＋`sherpa-onnx`（建议独立 venv）、`ffmpeg`（wav→ogg 转码）；模型为 MeloTTS zh_en 全套（`model.int8.onnx`＋`lexicon.txt`＋`tokens.txt`＋`dict/`，国内网络经 hf-mirror.com 下载）。合成脚本**随插件分发**（包内 `melo/melo_synth.py`），无需自备。
2. **部署目录约定**：模型文件放一个目录（如 `/DSH/melo-tts`），并在目录内放一个名为 `python` 的符号链接指向装有 sherpa-onnx 的解释器（如 `ln -s /path/to/venv/bin/python /DSH/melo-tts/python`）；缺省回落 PATH 上的 `python3`。
3. **AGENTS.md 配置块**：
   ```json
   "tts": { "engine": "melo", "voice": "", "volcKeyEnv": "", "meloDir": "/DSH/melo-tts" }
   ```
4. **验证**：面板同上（预检会逐项报出目录/解释器/ffmpeg 缺失）。

### 开启语音版

对24私助会话说「开启晨报（语音版）」或「晚间复盘改语音」；配置口径为 `digest_enable` 带 `voice: true`、`digest_control` 带 `op: "voice"`（per-plan 粒度，支持「早语音晚文本」）。语音开关与引擎解耦：换引擎不动计划，关计划不动引擎。

## 故障对照表

| 现象 | 原因 | 处置 |
|---|---|---|
| 语音接口 401 `45000010 Invalid X-Api-Key` | 用了方舟（Ark）平台的 `ark-` Key | 去**语音技术新版控制台** API Key 管理页建 Key（UUID 形态） |
| 语音接口 403 `45000030 not granted` 或 `55000000 …mismatched with speaker related resource` | 「豆包语音合成大模型 2.0」服务未开通（与其他语音服务相互独立） | 控制台「语音合成」开通 Seed-TTS-2.0（有免费试用）后重试 |
| `add` 非零退出，输出含 `allowBuilds` / `protobufjs` | 坑 A | 阶段 3 两步处置后重跑 |
| 装上的版本比指定旧，回执含 `installDoneOtherVersion` | 坑 B（观察期） | exclude＋精确版本重装 |
| 改 `protobufjs: true` 后仍非零 | yaml 键名或缩进有误 | 对照阶段 3 实样；`allowBuilds` 必须是 mapping |
| 宿主启动即退出，日志含 lock | 同 `$DSH_HOME/24pa` 已有宿主（单写锁） | `lsof` 确认旧进程：停旧再启新；并行实例请用独立 `DSH_HOME` |
| readiness / 日志报 PostgreSQL 不可用 | DSN 错、库未建或 PG 未起 | 回阶段 1；docker 场景先 `up -d --wait` |
| rc.2 上简报/会前准备报「当前 Host 未提供原生 Schedule 服务」 | 两个 schedule 伴随件未装 | 按阶段 3 版本表补装；registry 的 `dsh-schedule@0.2.0-rc.1` peer 不匹配，装了也是禁用行 |
| 面板可开但预设/插件行缺失 | 补丁层未 reconcile | 确认 `add` 退出码 0 后重启宿主 |
| 「运行就绪」里宿主正常，但配置/账本/工作区全「需要处理」 | 宿主是绕过启动脚本裸起的（直接 `dsh web` 等），没带 `PA24_*` 环境变量；环境变量只在宿主启动那一刻读取 | 停掉裸起进程，经启动脚本重启 |
| 重启后面板打不开，或 `/api/changes.*` 报 404 | 每次重启会签发新 token，浏览器仍是旧地址 | 从 run 日志重新取带 token 的 URL 打开 |
| 外部 CLI 委派工具（`subagent_*`）缺席 | 对应 provider 包未装或未在 `extraLocalTools` 开启 | 缺席是设计行为（见包 README「暴露工具」），非初始化故障 |
| 听记通道「未授权」但确已点过授权 | 多 mcp-remote 实例抢 8905（宿主重连堆积）或回调不可达 | 清全部 mcp-remote 进程，按指南第 3 步用独立授权进程重试（链接约 5 分钟轮换，过期重取） |
| 听记工具时好时坏 | mcp-remote token 过期后自动刷新失败 | 健康面看「听记通道」态；重启宿主重连，仍失败重新授权（新 token 覆盖旧缓存） |

## 安全红线与回退

- 初始化全程（demo 模式）**用不到任何飞书密钥**；将来接飞书时 App Secret 与令牌只存服务器启动环境/钥匙串，`AGENTS.md` 与一切文件只出现变量名。
- **既有 PostgreSQL 实例升级（规格 2.1/F25 起，必读）**：账本缺省已反转为 SQLite——升级插件前，先在工作区 AGENTS.md 的 json 配置块加 `"storage": "postgres"`（并确认 `pgDsnEnv` 指向的环境变量仍在启动环境中），否则重启后将启用工作区 `data/pa24.db` 的新空 SQLite 账本（PG 数据不受影响，但业务视图会变空）。反向切换同理：声明哪个后端就运行哪个后端，无静默退回。
- 回退插件：`DSH_HOME=<实例目录>/home dsh plugin --profile <实例名> remove @benz-ai-x/dsh-24pa`，下次 Profile 启动收回预设与宿主插件；PostgreSQL 数据、dsh 会话与工作区目录不受影响。
- 回退整个实例：先停宿主进程，再删除实例目录（含 `DSH_HOME`）；账本数据在 PG 卷/库中，按需另行处理。

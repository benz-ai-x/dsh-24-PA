# 产品基线与文档同步

正式实现或需求、交互、权限、数据归属变更前，读取本文件与 [规格](../24PA-v1-SPEC.md) 的相关章节；界面变更另读规格「管理界面与 UI/UX 契约」。

## 权威与入口

- 用户已确认中文名「24私助」、英文名「24PA」。中文产品/预设用24私助，管理入口用24私助工作区；技术 ID 和既有数据标识保持兼容。
- [GitHub #1](https://github.com/benz-ai-x/dsh-24-PA/issues/1) 是父规格，仓库 SPEC 是对应版本；[设计](../24PA-整体设计方案.md) 解释流程与取舍，[术语表](../../GLOSSARY.md) 仅定义词义，[ADR](../adr/0001-workspace-session-boundaries.md) 记录会话与权限边界。
- 唯一助理预设支持事务协调和维护。一个预设不等于一个会话，Lead/Worker 不是产品入口；按实际发起会话创建 Worker、恢复工作并回传结果。
- 记忆和配置维护由本地24私助会话承接；飞书日常交办、拍照和版本审核保持不变。固定飞书 profile 共用，记忆整理仅由主人发起。
- 业务账本默认 SQLite（工作区文件，规格 2.1/F25）、可选 PostgreSQL（`storage: "postgres"` 显式声明）；JSON 是长期记忆的唯一可编辑权威，助理工作区 AGENTS.md 是规则和非秘密配置源。

## 先 research，再开发

服务器上的飞书 bridge 仅是样例，用于观察行为、发现风险和提出待验证问题。24私助按已确认的设计与规格独立实现；不能直接复制样例的实现方式，也不默认继承其代码骨架、部署、机器人、profile、工作区或会话。

每个功能进入正式实现前，按以下顺序推进：

1. 对齐设计、规格及相关 ADR，明确该功能的用户流程、边界和验收结果。
2. 调研对应版本的 dsh 源码、公开接口与飞书官方文档、SDK/CLI 契约；优先复用已验证的原生能力。对影响方案成立的生命周期、权限、持久化、失败恢复等行为，在获准的隔离环境做必要验证。
3. 将结论保存到 `docs/research/`，记录来源和版本、可复用接口、方案取舍、验证结果及未决问题。有效的既有研究可直接引用；版本或契约变化时重新核验。样例运行记录不能替代正式架构所用接口的验证。
4. 支撑该功能关键路径的研究完成后，再按既定功能 PR 开发和验收。关键问题未解决时继续研究；结论与已确认设计冲突时，先提出证据并按文档同步规则处理设计变更，再实现。

## 两种 AGENTS.md

仓库根 AGENTS.md 是开发协作指引，通过条件明确的链接指向本目录规则，不存放主人的运行配置。

主人在服务器选定的助理工作区 AGENTS.md 才进入运行上下文。它由稳定规则和一个可校验 JSON 配置块组成，模板随插件提供，创建时保留已有文件；密钥只保存环境或凭据引用。更名或文档修订不能覆盖主人的既有工作区文件。

## 修改后的同步与核对

1. 改规格时保留既有故事、场景、测试组和工单 ID；新要求补可验证结果，并映射到既有功能 PR。同步 #1、仓库 SPEC、设计与受影响工单正文/索引。
2. 改术语时同步当前用户文案和指南；历史研究、提交、截图、验收记录保留原版本称呼并注明背景，避免改写历史证据。
3. [#2](https://github.com/benz-ai-x/dsh-24-PA/issues/2) 与[原型验收](../prototypes/24PA-原型验收记录.md) 记录实际实现及限制。示例、视觉演示和原型内存状态不能作为 PostgreSQL 恢复、真实飞书或手写准确率的正式验收。
4. 完成前核对链接、术语、故事/场景/测试映射、分组与依赖；GitHub 更新保留原有评论、状态、标签和原生阻塞关系，核对回读结果。事项 tracker 的具体操作见 [issue-tracker.md](issue-tracker.md)。
5. 当前正式实施、生产配置与部署仍需用户后续授权；已有原型修改授权不扩大为正式实现。后续用户直接授权时按其授权范围推进。

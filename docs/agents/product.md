# 产品基线与文档同步

实现、修复或修改产品约定前，先确定下面的目标基线，再读取受影响章节。编写 AGENTS.md 时另按「两种 AGENTS.md」区分用途。

## 权威与入口

- **本轮目标**：[Manticore 产品定稿](../planning/24PA-Manticore-产品定稿.md) 已于 2026-10-20 审核通过。涉及其模块时，读取对应规则、验收场景与「工作对象与权限」；其明确修订的目标行为优先于 v1 旧描述，未覆盖部分沿用 [v1 规格](../24PA-v1-SPEC.md)。目标已确认与功能已交付分别核验。
- **规格同步**：[GitHub #1](https://github.com/benz-ai-x/dsh-24-PA/issues/1) 是父规格，仓库 SPEC 是对应文档。新定稿要求同步两处；同步是否完成须核对正文，不能由定稿状态推断。
- **设计与领域**：[整体设计](../24PA-整体设计方案.md) 解释流程与取舍；术语和 ADR 按 [领域文档约定](domain.md) 查阅。历史研究、原型和旧交付表用于追溯当时依据。
- **界面验收**：界面变更同时读取目标基线的模块验收和 v1 规格「管理界面与 UI/UX 契约」「T20」；按已确认修订处理新旧差异。

## 桌面五卡 UI/UX 基线（规格 2.14）

- **终端范围**：本产品的设计、开发与验收只考虑电脑端，不考虑手机端。T20 覆盖 1280×800、1440×900、1920×1080 电脑视口，不设置手机断点或 390px 验收；飞书／企微原生 App 的既有平台边界不因本条改写。
- **五卡原型**：用户于 2026-10-25 批准 [#240](https://github.com/benz-ai-x/dsh-24-PA/issues/240)–[#244](https://github.com/benz-ai-x/dsh-24-PA/issues/244) 的 Skill 管理、定时任务、日程、待办、运行记录原型，作为五卡的交互开发基线。逐卡契约、技术基线和原型路径见 [Manticore 补充修订](../planning/24PA-Manticore-产品定稿.md)，交付归属见 [PR 交付计划](../planning/24PA-v1-PR交付计划.md)。
- **本轮行为修订**：Skill 管理提供同一真实包快照的完整目录树与只读文件预览；待办来源的持久默认角色支持 `all / responsible / following / assigned / creator` 五档，明确角色只覆盖本次查询。规范性明细分别见 #240、#243，不能只改界面文案。
- **证据边界**：原型仅证明已批准的布局、信息优先级和交互方向；示例对象、计数、时间、哈希及即时状态切换不是正式能力或验收证据。正式交付仍按各票读取真实 RPC、配置、账本和外部对象。

- **当前授权**：用户已于 2026-10-20 审核通过 Manticore 定稿并授权五步实施（跟踪 [#212](https://github.com/benz-ai-x/dsh-24-PA/issues/212)）；M01a–M09 已全部合并，发版、生产部署与真实账号验收按具体授权另行办理。
- 按用户当前任务及已有明确授权推进。原型、文档同步或 `ready-for-agent` 标签本身不扩大为正式实施、生产配置或部署授权；已获授权的工作沿用授权范围。旧记录中的「待后续授权」描述当时状态，不覆盖后续授权。

## 先 research，再开发

服务器上的飞书 bridge 仅用于观察行为、发现风险和提出待验证问题。正式架构以已确认基线和验证过的接口为依据；样例代码骨架、部署、机器人、profile、工作区和会话均不自动继承。

每个功能进入正式实现前，按以下顺序推进：

1. **对齐**：定位目标基线、设计与相关 ADR，列出受影响的用户流程、边界及可观察的验收结果。
2. **核验**：调研对应版本的 dsh 源码、公开接口与相关平台官方文档、SDK/CLI 契约；优先复用已验证的原生能力。关键路径涉及的生命周期、权限、持久化和失败恢复均须有接口依据，必要时在获准的隔离环境验证。
3. **留证**：结论保存到 `docs/research/`，包含来源和版本、可复用接口、方案取舍、验证结果及未决问题。既有研究在版本与契约仍适用时可直接引用；样例运行记录仅证明样例行为。
4. **进入实施**：关键路径问题均有结论，每项验收均有验证方式后，按 [交付流程](delivery.md) 开发。与已确认设计冲突时，先列证据并处理设计变更；未解决的关键问题继续研究。

## 两种 AGENTS.md

| 文件 | 内容与修改边界 |
|---|---|
| 仓库根 AGENTS.md | 开发协作入口；保留常用约定和带触发条件的链接，具体规则放在对应文档。 |
| 主人选定的助理工作区 AGENTS.md | 运行规则与唯一可校验 JSON 配置块；模板随插件提供，创建时保留已有文件，配置变更保留工作规则。密钥只存引用，实际值沿用专门凭据机制。 |

仓库文档修订只更新开发指引；修改运行模板或既有实例文件时须有对应任务范围，并遵循规格「仓库指引与助理配置」「工作区、Lead/Worker、路由与并行」。

## 修改后的同步与核对

- **产品要求变化**：保留故事、场景、测试组和工单 ID；新增要求补可验证结果与功能 PR 归属，同步父规格、仓库 SPEC、设计及受影响工单正文／索引。GitHub 操作按 [GitHub 事项约定](issue-tracker.md) 执行。
- **术语变化**：按领域文档约定更新术语、当前用户文案和指南；历史研究、提交、截图与验收记录保留当时称呼和背景。
- **协作指引整理**：仅改措辞、结构或读取路径时，更新受影响入口与引用，核对迁移前后的约束；产品行为变化才触发规格同步。
- **实现证据**：[原型 #2](https://github.com/benz-ai-x/dsh-24-PA/issues/2) 与[原型验收](../prototypes/24PA-原型验收记录.md) 记录原型能力和限制；正式交付按交付流程保留实际验收证据。演示与内存状态不能证明持久恢复、真实平台操作或手写准确率。

完成时，受影响链接可达、术语一致、故事／场景／测试与功能归属可追溯；未完成的同步或未验证能力逐项说明。

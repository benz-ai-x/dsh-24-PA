# 领域文档

领域知识采用 **single-context** 布局，各类信息只有一个维护位置：

- [GLOSSARY.md](../../GLOSSARY.md)：领域名称、含义与易混概念。
- [docs/adr/](../adr/)：已确认架构决策及修订依据。

## 探索前读取

探索代码、讨论领域设计或修改领域文档前，读取术语表及相关 ADR；涉及工作区、会话、权限或提醒归属时，读取 [ADR-0001](../adr/0001-workspace-session-boundaries.md)。

术语或决策实际确定后，使用 `domain-modeling` 维护对应来源；只为已确定的内容创建文件。

## 使用统一术语

Issue 标题、设计提案、假设与测试名称使用术语表名称。遇到未收录概念，先判断是已有概念的别名还是新概念；已确认产品修订尚未同步时，按 [产品基线](product.md) 定位原文并明确同步缺口，保留技术标识与历史对象身份。

## 处理决策冲突

方案与现有 ADR 冲突时，列明 ADR 编号、冲突条款、证据与重新讨论的理由；决策确认后记录修订依据，再同步术语和受影响文档。完成时，新旧概念的对应关系及仍有效的决策边界须可追溯。

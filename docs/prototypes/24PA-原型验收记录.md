# 24PA dsh 原型验收记录

日期：2026-10-05。用户本轮明确授权制作能部署到 dsh 上体验的原型；正式版实施与上线仍未授权。

## 问题与结论

问题：常规私人助理操作、A–E 多 dsh 会话、单页手写整理的版本审核，能否放进同一个固定飞书身份入口，且切换、审核和行动权限清楚？

结论：真实 dsh 的 Loader、原生面板、SessionController、Tools 和受认证 Fetch 扩展已跑通；四个关键状态演练可操作。实际飞书/视觉模型效果和用户对交互的判断尚未验证，因此没有把原型实现提升为正式版设计结论，也未启动 12 个功能 PR。

原型代码和离线演练保存在独立 `prototype/24pa-dsh` 分支，main 只有此前的规格与规划文档。

## 实际发现并修正

- 使用 `ctx.sessions.flush(session)`，不能把 flush 当作 Session 实例方法。
- 使用 Connection 的受认证 Fetch 路由。当前 checkout 的独立 RPC channel 注册遇到注入边界错误，未修改 dsh 源码绕过它。
- 将工具限制放到每个实际 Agent 的创建阶段。preset 层的空 allow 会将其自身工具在下游会话中一起过滤；现已验证助理工具可用而 shell 不可用。
- 安装显式忽略脚本。首轮未指定该选项时，pnpm 因 protobufjs 安装脚本被忽略而返回失败；在独立验收 profile 通过官方 CLI 清理中断记录后，以最终命令安装成功。没有批准或运行此脚本。
- 给更新的 tgz 使用新版本号，避免包管理器复用同版本旧内容。最终代码版本为 `0.0.1-prototype.1`。

## 尚未验证与需要用户体验的部分

- 尚未提供服务器入口及实际飞书应用配置，因此未部署远程服务器、未发送真实飞书消息、未创建真实飞书任务或文档。
- 本地隔离 profile 没有模型凭据，未获得真实模型生成结果；更没有用示例稿代替中文手写识别评测。
- 飞书 CLI 的身份、命令和 XML 契约已按本机帮助与官方 SDK 类型对接；真实权限、卡片回调、图片下载、文档 revision/并发语义需租户联调。
- 会话日志由 dsh 保存，但原型的 active 指针、卡片凭证、审核状态和提醒只在内存；重启不提供 24PA 业务恢复，PG 恢复仍属于正式版。
- 需要用户判断：会话“查看/切换/返回”是否清楚；按版本审核是否足够直观；常规助理与手写审核的入口比例是否合适。

技术通路通过不等于这些体验问题已获得用户认可。正式版沿用既定真实 Loader/会话/PostgreSQL 主测试边界，并另做真实飞书和 30–50 页手写样本验收。

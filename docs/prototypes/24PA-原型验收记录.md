# 24PA 工作区原型验收记录

日期：2026-10-05。版本：`0.0.2-prototype.1`。用户已确认本轮重做设计和可部署原型；正式版实施与服务器上线仍未授权。

## 要验证的问题与结论

问题：**以一个 dsh 工作区为助理实例，飞书统一向 Lead 交办，专业 Worker 办理，配置和 JSON 记忆通过原生维护会话管理，能否成立？**

技术结论：真实 dsh Loader、WorkspaceRegistry、AGENTS.md instructions、Lead/维护 preset、continuable 子 Agent、受控工具及原生面板已接通。五类 Worker 在真实宿主中产生真实子会话；JSON 记忆经维护工具写入后，正常重启仍可检索。原型能安装到兼容 dsh 体验。

这证明了插件集成与关键状态通路，不证明真实飞书接口兼容性、模型的工作判断或中文手写识别质量。交互方式仍需用户在自己的飞书配置下体验。

## 已确认的产品调整

- 24PA 是服务器本地工作区；AGENTS.md 放稳定规则与实际非秘密配置。
- 日常委托/照片/审核在飞书，Lead 统一分派和汇报；不再要求 A–E 全局切换。
- Worker 按专业职责和事项隔离，使用原生子 Agent，不另建 OS 进程或 Agent 引擎。
- dsh 面板用于配置观察、事项状态和维护入口；记忆编辑通过原生维护会话。
- 记忆权威为结构化 JSON；本人发起整理，不做自动或定期记忆整理。业务提醒仍主动发送。
- 正式版使用现有 PostgreSQL；本次原型业务账本仍是内存，不使用 SQLite。

旧版 `a384603` 的 A–E 面板与离线按钮演练已被用户否定并在本轮移除，旧验证结果不再作为新版交互验收证据。`485ca95` 的启动端口预检保留。

## 验证方法

使用 dsh `0.2.1-alpha.1`，源码提交 `5badb15009ae1756c3afe0ae0cef1faafc290ccc`，Node `26.4.0`。先从源码 bundle 验证，再打包通过官方 CLI 安装到独立 DSH_HOME，运行实际包。

一次性探针仅替换模型边界，使用实际 Loader、会话/子 Agent、工具注册、fs、业务代码和消息处理器。模型边界返回明确标记的转写夹具，不调用真实视觉服务；固定提醒走 demo 内存投递通道。探针、临时数据、登录令牌均不入 Git 或安装包，按 prototype 技能未添加测试套件。

## 集成中实际修正的边界

- 自定义 preset 需要显式装配原生 agent-instructions 和维护用文件工具，不能假定继承 standard preset 的工具集合。
- 原生 fs 应从已声明 inject 的插件 context 取用；不能直接跨 context 读取未注入服务。
- SessionController.prompt 需要调用方取消信号；插件卸载要取消相应生命周期。
- Tools output.render 的签名是 `(args, value)`；模型必须收到真实返回值，不能只看到输入参数。
- 子会话打开地址包含 parentSessionId、childSessionId、mode，不能用普通会话地址替代。
- 原生工作区归属要通过 create 的 workspaceId 或 attach 建立；仅指定 cwd 会有相同目录，但空白维护会话的 UI 仍可能没有所选工作区。最终版采用 workspaceId，并由浏览器确认输入可用。
- 相同工作区的配置重载保留本次业务记录；切换目录和进程重启分别说明其状态边界。

## 未验证与未实现

尚未提供真实服务器入口、飞书应用授权和模型凭据，因此本轮没有部署远程服务器，没有发送真实飞书消息，也没有创建真实飞书任务/日程/文档。平台权限、长连接、图片下载、卡片回调、CLI/XML/revision 语义仍需租户联调。

真实模型的任务分流和工具选择、中文手写的转写质量与疑点提示尚未验收；边界模型输出不算 OCR 效果。真实测试仍按规格使用 30–50 页样本。

配置、JSON 记忆、收到的原稿和 dsh 会话持久；业务队列、提醒、卡片凭证和消息路由不耐久。未连接 PostgreSQL，未实现完整周期 Schedule、全面日程/任务同步、完整项目规划、多页处理或录音 Worker。JSON 原型保留当前版本和修改依据，尚无完整历史回滚。

正式版继续采用已确认的真实 Loader/Session/PostgreSQL 主测试边界，并分别验收真实飞书与视觉质量。原型分支及证据由 Issue #2 跟踪，不因技术通路通过而自动启动生产功能 PR。

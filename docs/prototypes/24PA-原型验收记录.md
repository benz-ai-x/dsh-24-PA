# 24PA 机器人原型验收记录

日期：2026-10-05。当前版本：`0.0.3-prototype.1`。本轮按用户“24PA 机器人包含 Lead 和工作区维护能力”的结论修改可部署原型；不启动正式版功能 PR。

## 本轮结论

只保留一个 **24PA 机器人** Agent 预设。在同一个 dsh 会话中，可以交办事务、查询/继续/停止 Worker、修改并重载 AGENTS.md、检查飞书接入、查询及维护 JSON 记忆。一般维护不再要求切换预设或标准模式。

新增只读「飞书接入」页面，显示 CLI 路径与版本、固定 profile、主人与 CLI 用户、令牌检查、资源配置与可读性、配置来源与生效时间、凭据是否由启动环境提供、最近一次检查，以及本次运行的机器人收发记录。通过自然语言修改配置，不增加配置表单。

Lead 保留为内部协调职责。飞书与 dsh 的事项共用运行账本；原生 Worker 归属于实际发起会话，结果回到对应入口。dsh 中的维护对话和本地 Worker 结果不会自动广播到飞书；主动提醒仍按本人委托发送。

飞书接入会话与 Worker 只能检索记忆；本地机器人会话具有维护能力。继承同一 preset 的原生 child 不因此取得文件编辑或记忆写入权限。手写 Worker 仍无行动工具，人工审核与执行行动保持分开。

## 验证环境与方法

- 真实 dsh `0.2.1-alpha.1`，源码提交 `5badb15009ae1756c3afe0ae0cef1faafc290ccc`；Node `26.4.0`。
- 官方 CLI 创建隔离 Web profile、安装真实 tgz，通过实际 Loader、SessionController、Tools、WorkspaceRegistry、原生 continuable 子 Agent 与文件服务运行。
- 模型使用一次性边界夹具；飞书诊断异常分支使用固定 argv 的 CLI 边界夹具。夹具、登录凭据、运行数据均不入 Git 或安装包，没有新增测试套件。
- 同时检查本机真实 `lark-cli 1.0.87`。检查发现本机显式 `default` profile 尚不存在；页面如实显示，没有切换到其他 profile 或替用户授权。

## 30 项真实宿主检查

以下按用户流程归并列出；完整逐项执行记录保存在本地忽略的 `.prototype-runtime/v3-final-evidence.json`。

| 检查范围 | 实际结果 |
|---|---|
| 单一预设 | 原生 roster 中只有一个 24PA preset，名称为「24PA 机器人」 |
| 统一会话 | 同一真实模型调用链读取/编辑 AGENTS.md，将并发数改为 3，重载、检索/写入 JSON，然后委派 memo Worker |
| 能力目录 | 机器人模型同时看见协调、工作区、记忆、接入检查和文件工具 |
| 入口恢复 | 点击入口复用同一原生 Session，cwd 与 Workspace 归属正确 |
| 旧入口兼容 | 原接入或机器人会话被改成标准 preset 时保留历史，创建正确的新入口并保存绑定 |
| 消息回传 | 本地 Worker 回到原 dsh 会话，未增加飞书 Lead 消息；跨入口控制通过原生 parent 继续原 Worker |
| 记忆版本 | 实际 JSON 写入；旧 revision 被拒绝；飞书 Lead 无记忆写权限 |
| 工具边界 | Lead 无 shell；Worker 无文件编辑工具；未知 child 无维护权限 |
| 日常助理 | tasks、memo、calendar、reminders 分别启动真实 child；任务/备忘/日历使用 demo 路径；固定提醒到期有 demo 投递回执 |
| 手写审核 | PNG 字节进入无工具的 handwriting child；生成 v1 待审；人工卡片审核不创建任务；继续原 child 产生 v2，旧卡片无法批准新版本 |
| 配置与来源 | AGENTS.md 实际进入模型；本地 CLI 版本与配置文件可检查；未重载修改有明确标记 |
| 错误恢复 | 无效配置不覆盖上一有效版本；同工作区重载保留运行业务记录与 JSON 记忆 |

额外 **4 项诊断边界检查**：身份匹配且令牌验证通过后才读取资源；单个资源拒绝保持独立可见；身份不匹配不读取资源；CLI 缺失与文件未重载分别报告；输出字段白名单不带 token。这些是外部边界夹具验证，不代表真实飞书资源权限验收。

## 浏览器验收

用户正在打开的本地 `3210` 已更新。更新前保存了旧内存快照，确认无运行中的事项；原生历史、工作区配置和记忆保留。本机体验实例不加载测试模型或测试业务。

实际浏览器确认：

- Agent 预设菜单仅有「24PA 机器人」这一项 24PA 选项，描述明确包含协调与配置/记忆维护。
- 「与24PA机器人对话」「通过对话配置」打开归属正确工作区的同一个原生机器人会话，输入框可用。
- 「飞书接入」无配置表单，按钮按需检查；显示实际 CLI 路径与版本、`profile "default" not found`、未配置资源及环境凭据。
- 页面刷新只读缓存状态，不自动反复访问飞书。
- 「运行记录」中可查看内部接入会话；事项链接采用实际 parentSessionId 打开原生 Worker。

## 已修复的宿主集成问题

升级时发现用户的旧接入 Session 当前 preset 为 `standard`，继续用原 ID 创建 `pa24-prototype` 会被 dsh 拒绝。现在按公开的 `agent-preset/conflict` 错误处理：保留旧历史，建立新入口，将映射保存到宿主状态文件。不会重写历史 Session 的 preset。角色判断读取当前组合的 preset，不把创建时的 header 当成后来选择的预设。

入口状态加载失败时给出具体错误，避免停在「正在加载工作区」。无效 AGENTS.md 重载不会替换有效配置。凭据只显示环境变量名与是否存在，不输出原值。

## 当前限制

当前本机缺少模型凭据、显式 default CLI profile 及机器人环境凭据；本轮没有部署远程服务器，没有发送真实飞书消息或写入真实日历/任务/文档。初次 CLI 安装、凭据注入与 OAuth 仍由用户在服务器完成；自然语言配置工具不代办登录。

真实模型分流、中文手写识别质量、飞书长连接/权限/回调、CLI/XML/revision 语义仍需真实环境联调。模型夹具不能证明识别准确率；正式验收仍使用 30–50 页样本。

配置、入口绑定、JSON 记忆、原稿与原生会话持久；事项、提醒、审核令牌及消息路由只在本次运行中。原型没有连接 PostgreSQL，不使用 SQLite 保存业务；没有完整周期 Schedule、多页处理、录音 Worker 或完整记忆历史回滚。没有自动/定期记忆整理。

正式版继续采用真实 Loader/Session/PostgreSQL 主测试边界。此前规格 1.1 的维护职责仍保留，入口合并以本轮用户确认和 Issue #2 记录为准；本轮没有领取或关闭生产实施票，没有创建或合并 PR。早期 0.0.2 验证记录可查 Git 历史。

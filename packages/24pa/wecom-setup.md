# 24私助（24PA）企业微信渠道接入指南

本指南面向 AI 助理（也供本人查阅），是企业微信日程/待办渠道与单向推送的**唯一权威流程**（规格 1.6 / F16；执行模式 F23 起改为**一次交付＋一次验收**）。通读全文 → 把你的准备做在前面（装 CLI、发起绑定拿二维码）→ 把「本人操作全量清单」**一次性**交给本人 → 本人一口气做完回报一次 → 你**自动循环** `pa24_connection action=wecom_check` 收敛，把剩余卡点**一次汇总**。检查结果的 `nextSteps` 字段会直接指出当前卡点的下一步（含平台返回的授权链接）。

核心心智模型：

1. **渠道边界**：企业微信只是日程/待办的**第二操作渠道**与提醒的**单向推送出口**——机器人把通知发到企微，但企微**不做收信**（收不到也不能处理你发过去的消息）；日常交互入口仍在飞书或 dsh 本地会话。收信需要企业微信回调服务器，超出本渠道范围。
2. **一种绑定**：wecom-cli 凭据是**机器级全局**的（`~/.config/wecom`，加密存储），没有 profile 概念；一台服务器绑一个机器人。授权真人身份由 `identity whoami` 解析，作为推送目标，**不需要也不接受在 AGENTS.md 里另填企微 userid**。
3. **授权会过期**：机器人绑定（auth init）一次长期有效，但**服务级权限**（日程/待办等）会过期（实测日程授权曾过期，报 errcode 850003）。过期不是故障：助理会定期检查并在失效时**主动推送续期链接**，本人按链接在企微内重新授权即可。
4. **三类事只有本人能做**：在企微 App 内扫码绑定机器人、在「工作台-智能机器人」里逐项授权/续期服务权限、决定切渠道（改 AGENTS.md）。其余（安装 CLI、诊断、改配置、发起检查）都可由你代办。
5. **安全红线**：App/机器人凭据只存在服务器本机（`~/.config/wecom`），不进仓库、不进 AGENTS.md、不回显；平台返回的授权链接只转交本人，不在本地尝试打开；诊断只读，不发消息、不建企微对象。

## 准备（你代办，配置开始立即做）

| 检查 | 达标标准 | 不达标处置 |
|---|---|---|
| dsh 宿主运行且工作区已绑定 | readiness 中 host/config/workspace 为 ok | 先解决宿主与工作区问题 |
| PostgreSQL 已连接 | readiness 中 postgres 为 ok | 修复 `pgDsnEnv` 指向的环境变量与数据库 |
| Node ≥ 官方要求 | `node -v` 可用 | 升级 Node（wecom-cli 是原生二进制分发，按平台自动选择） |
| 本人有企业微信管理员/机器人创建权限 | 能在企微「工作台 → 智能机器人」创建机器人 | 联系企业管理员；该企业未开通智能机器人能力时渠道不可用 |

**安装 CLI 并发起绑定**：`npm i -g @wecom/cli`（验证 `wecom-cli --version`；注意校验的是 **dsh 宿主进程的 PATH**，也可在 AGENTS.md 对应的宿主配置里指定 `wecomCliBin` 绝对路径）；随后在服务器执行 `wecom-cli auth init`——这是**扫码流程**，把终端里的二维码/链接原样随清单交给本人。

## 本人操作全量清单（一次交付给本人）

开场白（原样转交）：「以下两个块请在企业微信 App 里按顺序一口气做完，做完后回复我『全部做完了』。每一步都只有你能做。」

### 块 A：扫码绑定机器人（依赖：无）

打开随清单交付的二维码/链接，在**企业微信 App 内**扫码确认（选择正确的企业）。绑定一次长期有效。

### 块 B：服务级授权（依赖：块 A）

机器人默认没有任何服务权限。在**企业微信 App**内逐项授权（链接需在企微内打开；也可从「工作台 → 智能机器人 → 找到对应机器人 → 授权管理」进入）：

1. 按工作区将启用的渠道逐项授权：
   - `calendarChannel: wecom` → 授权「**日程**」；
   - `todoChannel: wecom` → 授权「**待办**」；
   - `notifyChannel: wecom` → 推送无需单独服务授权（身份解析通过即可）。
2. 授权页若提示已过期，直接重新授权即可（服务级授权会过期，属正常现象，不是故障）。

## 本人回报后你收尾（你代办）

1. 编辑工作区 AGENTS.md 的 json 配置块切渠道（仅按本人明确要求）：

   ```json
   {
     "calendarChannel": "wecom",
     "todoChannel": "wecom",
     "notifyChannel": "wecom"
   }
   ```

   三个字段按域独立选择（`feishu`/`wecom`，缺省 `feishu`，可混搭、不双写）；改后 `pa24_workspace action=reload`。切渠道不迁移已有飞书数据；两渠道的日程/待办投影与操作账以 `channel` 列区分。

## 自动验收（一次汇总，不逐项追问）

1. **循环收敛**：最多 3 轮。每轮运行 `pa24_connection action=wecom_check`；853006（该企业不可用此能力）无法由助理侧修复，如实报告并建议改用飞书渠道；其余需要本人的项（850002 未授权/850003 过期）把 `helpMessage` 里的授权链接原样转交。仍不达标时把**全部剩余卡点一次汇总**给本人，不要每轮追问。
2. **达标标准**：`cli.state = ok`、`identity.state = ok`（含授权真人姓名）、`services` 里所有已启用域 `state = ok`。
3. **端到端**（真实对象）：
   - 日程：让本人说「查一下本周企微日程」→ calendar_query 同步并返回列表；再建一条 15 分钟的测试日程、随即取消，向本人展示两步回执。
   - 待办：建一条测试待办 → task_list 可见（channel=wecom）→ task_complete 完成 → 向本人展示企微里的真实状态。
   - 推送：让本人设一条 1 分钟后的提醒，到点后确认**企微单聊收到机器人 markdown 消息**。
   - 测试数据即建即清；验证结果（含发送延迟、边界）如实记录。

## 授权到期后的续期（持续性）

服务级授权会过期；启用任一 wecom 渠道后，助理定期自动检查（只读），发现 850002/850003 时会经通知渠道**主动推送续期链接**给本人——按链接在企微内重新授权即可，无需撞上业务报错才发现。续期后可让助理再跑一次 `wecom_check` 确认。

## 已知边界（向本人汇报时如实说明）

- 企微日程首版支持**查询/创建/取消**；修改与会议邀请（meeting_schedule）不支持——需要变更时取消后重建，或本人手动调整。
- 企微待办支持**创建/完成/删除**（删除是企微独有能力，飞书任务无删除接口）；不支持修改。
- wecom-cli 无平台幂等键：所有写操作先落 24PA 操作账（`wecom_*` 键）防重；「结果未知」（超时）时先核对企微实际对象再决定重试。
- 邮件渠道仅支持 ±7 天窗口（平台限制），本渠道不接入；会话消息（chat）能力对多数企业不可用（853006），不在范围内。
